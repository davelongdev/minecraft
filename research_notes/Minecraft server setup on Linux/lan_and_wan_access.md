# How players reach self-hosted Minecraft Java servers (LAN and WAN), several servers on one Linux box, October 2026

Scope: 3–6 Java Edition servers (26.3, vanilla clients) on one Arch Linux box behind a consumer router; one adult operator, 10–20 kids, both "same Wi-Fi" and "kids at home". Research date 2026-10-18. Where a claim rests on a vendor blog or forum post rather than a primary source, that is flagged inline.

## 1. LAN: how clients find the server, fixed addresses, hairpin, studio/school network pitfalls

### Takeaway
On a LAN, kids type the box's private IPv4 and port (e.g. `192.168.1.20:25565`); a dedicated server does not announce itself in the Multiplayer screen's LAN list, because that list is fed only by the `224.0.2.60:4445` multicast that "Open to LAN" singleplayer sends. Give the box a DHCP reservation, keep everyone on the same non-guest, non-isolated SSID/VLAN, and have LAN players use the private IP rather than the public name unless the router is known to do NAT loopback.

### Cited Findings
- Connecting over LAN: "Players within your LAN can connect to your server by using the server host's internal IP address", entered with the port as in the page's example `192.168.1.2:1337`; players can be on "ethernet cable or wireless" — [minecraft.wiki, Tutorial: Setting up a Java Edition server](https://minecraft.wiki/w/Tutorial:Setting_up_a_Java_Edition_server)
- Default port is 25565, configurable in `server.properties`; `server-port` is "The TCP port number the server listens on." `server-ip` is "The IP address the server listens on. If empty, the server listens on all available IP addresses." (recommended left empty) — [minecraft.wiki, Server.properties](https://minecraft.wiki/w/Server.properties)
- Setting `server-ip` to an address that matches none of the host's interfaces causes "Failed to bind to port!"; leaving it blank lets it bind to all interfaces — [minecraft.wiki, Java server tutorial](https://minecraft.wiki/w/Tutorial:Setting_up_a_Java_Edition_server)
- LAN-list discovery mechanism: a published ("Open to LAN") singleplayer world "sends a UDP multicast to the multicast address `224.0.2.60:4445` every 1.5 seconds", which makes the world "pop up automatically in the server list"; if no port is set "the game randomizes the server port" and shows it in chat — [minecraft.wiki, LAN world](https://minecraft.wiki/w/LAN_world); same multicast facts and "Multiplayer now scans for local games" (1.3.1) — [minecraft.wiki, Multiplayer](https://minecraft.wiki/w/Multiplayer)
- Server-side plugins/mods exist purely to make a dedicated server appear in that LAN list by imitating the client broadcast: LanServers "makes a server show up in the Multiplayer menu as a LAN server" with "the same behavior as the Minecraft Client when you open your world to LAN" — [Hangar, LanServers](https://hangar.papermc.io/Redstonecrafter0/LanServers); LAN Announcer sends `[MOTD]<motd>[/MOTD][AD]<port>[/AD]` to 224.0.2.60:4445 every 1.5 s — [Modrinth, LAN Announcer](https://modrinth.com/mod/lan-announcer)
- Fixed private address: "You should set a static internal IP for your server host machine" because DHCP can change the internal IP and break forwarding rules; "Each modem or router has a different way of setting a static internal IP address." — [minecraft.wiki, Java server tutorial](https://minecraft.wiki/w/Tutorial:Setting_up_a_Java_Edition_server)
- Hostnames by mDNS (`name.local`): Windows 10 1703 and later include a built-in mDNS resolver/responder in the DNS Client service; Windows resolves `.local` by mDNS only if LLMNR (on by default) returns nothing first — [slightfuture.com technote](https://slightfuture.com/technote/windows-mdns-dnssd/) (unofficial); a 2018 write-up found Windows `.local` behaviour inconsistent: "you may or may not be able to reach other machines from programs, games, and web browsers by typing in their mDNS address" — [ctrl.blog](https://ctrl.blog/entry/windows-mdns-dnssd) (dated)
- NAT loopback/hairpin: without it, an inside host that connects to the router's public IP has its packets sent toward the ISP and dropped; the fix needs both a DNAT for the forwarded port and SNAT/masquerade on the return path; the simple workaround is "try the private IP directly" or split DNS (resolve the public name to the private IP internally) — [OneUptime, NAT hairpinning and loopback](https://oneuptime.com/blog/post/2026-03-20-nat-hairpinning-loopback/view); definition of hairpin NAT — [JumpCloud](https://jumpcloud.com/it-index/what-is-hairpinning-nat)
- The wiki's troubleshooting note is that from the host you can connect through "`localhost`, your internal IP (`192.168.x.x`) or your external IP" but it does not discuss hairpin support on consumer routers — [minecraft.wiki, Java server tutorial](https://minecraft.wiki/w/Tutorial:Setting_up_a_Java_Edition_server)
- Guest Wi-Fi/client isolation: on a Netgear business AP, with client isolation disabled clients can reach each other, enabled they cannot; a Netgear rep said guest-network clients are kept off the main LAN by design, so disabling isolation on the guest SSID may not be enough — [Netgear community thread](https://community.netgear.com/discussions/business-wireless-for-business/wax220-guest-networkisolation-not-working-properly/2318061/replies/2318086); a 2013 report of two devices on an Apple guest network unable to see each other's LAN world concluded that guest networks "explicitly isolate each client from all others" — [shell.lug.mtu.edu blog](https://shell.lug.mtu.edu/~adam/blog/no-minecraft-for-guest-network/)
- VLANs at schools: on a large school Cambium deployment "client isolation only applies to stations within the same VLAN" and inter-VLAN reachability is governed separately — [Cambium community](https://community.cambiumnetworks.com/t/network-wide-client-isolation-with-a-vlan-pool/61276); a Minecraft-at-home thread recommends a dedicated VLAN with "a WiFi AP that can handle VLAN tagging" for wireless players — [TrueNAS community](https://www.truenas.com/community/threads/security-and-minecraft.56769)
- Firewall symptoms: "connection timed out" usually means a firewall is dropping the attempt; "connection refused" means "there's no process listening on the port" — [minecraft.wiki, Java server tutorial](https://minecraft.wiki/w/Tutorial:Setting_up_a_Java_Edition_server)

### Inferences
- Because the vanilla dedicated server never sends the 4445 multicast (the existence of LanServers/LAN Announcer is the evidence; the wiki only says server worlds "can also be joined through LAN play"), the practical LAN workflow is Multiplayer → Add Server / Direct Connect with `IP:port`; with 3–6 servers that is 3–6 bookmarks per laptop, or one bookmark per kid pointing at their assigned port.
- A DHCP reservation on the router (vs. a static IP configured on Arch) is the lower-maintenance way to get the "static internal IP" the wiki asks for, and it keeps the router's own DNS/hostname table consistent; many consumer routers also resolve the DHCP hostname (e.g. `mcbox` or `mcbox.lan`) for LAN clients, but I found no source documenting that behaviour generically, so test it per router.
- mDNS `.local` names work natively on Linux (Avahi) and macOS and on Windows 10 1703+, but the Windows LLMNR-first quirk and reports of flakiness make the plain IPv4 address the safer thing to print on a card for kids.
- Studio Wi-Fi pitfalls, in likely order: (1) kids on a guest SSID (isolated from the wired/main LAN where the box sits), (2) client/AP isolation enabled on the main SSID, (3) the box on a different VLAN than the Wi-Fi, (4) a 2.4 GHz and 5 GHz SSID that are bridged to different networks. No source in this research tied 2.4 vs 5 GHz itself to connectivity; on a normal home router both bands bridge to the same LAN, so band choice only affects speed/congestion, not reachability (my inference; treat as unverified).
- Hairpin NAT support varies by router model; a 20-kid room all hitting the public DDNS name from inside the studio either works silently or fails for everyone. Safer: print the private IP for in-studio use and the public name for home use, or run split DNS (e.g. a Pi-hole/dnsmasq override) if kids must use one name everywhere.

### Gaps
- No primary (Mojang) statement that the dedicated server does not multicast to 224.0.2.60:4445; inferred from plugin descriptions.
- No vendor table of which consumer routers support NAT loopback; forum/blog material only.
- Nothing authoritative on 2.4 GHz vs 5 GHz as a LAN-reachability issue.
- Whether typical home routers resolve DHCP client hostnames for other LAN clients is router-specific and was not sourced.

## 2. WAN via port forwarding: per-server forwards, DDNS, CGNAT/double NAT, IPv6, SRV records, exposure

### Takeaway
Classic port forwarding means one TCP forward per server (25565, 25566, …) to the box's reserved private IP, a free DDNS name (DuckDNS has no renewal chore; No-IP free names must be confirmed every 30 days), and `_minecraft._tcp` SRV records so each server gets a bare name like `red.example.com` instead of `name:25566`. It only works if the router's WAN address is a real public IP: a WAN address in 100.64.0.0/10 or a private range, or one that differs from whatismyip, means CGNAT/double NAT and no inbound forwarding (T-Mobile Home Internet is the common US case).

### Cited Findings
- Port forwarding, per the wiki: open "a TCP/UDP port (default is 25565) on the server host's firewall", create the router rule with protocol "TCP/UDP" or "Both" (or two rules), internal IP = the host's internal address, leave external IP as is; test with a port checker while the server is running; "Players connecting from the Internet (i.e., outside of your LAN) must connect using your external IP address." — [minecraft.wiki, Java server tutorial](https://minecraft.wiki/w/Tutorial:Setting_up_a_Java_Edition_server)
- Multiple servers: the server jar accepts `--port <port>` (overrides `server-port`) and `--world <name>`; the wiki lists ports to avoid because "some ISPs may block these ports for security reasons" and advises avoiding ports below 1024 — [minecraft.wiki, Java server tutorial](https://minecraft.wiki/w/Tutorial:Setting_up_a_Java_Edition_server)
- Dynamic IP: most ISPs "only offer dynamic IP", so the external address changes "every few days to a few weeks"; options are checking it periodically, "a dynamic DNS (DDNS) service" (No-IP named), or a static external IP from the ISP, which "usually" costs a monthly fee — [minecraft.wiki, Java server tutorial](https://minecraft.wiki/w/Tutorial:Setting_up_a_Java_Edition_server)
- No-IP free hostnames: must be confirmed every 30 days; after day 23 the hostname enters a 7-day confirmation window, then a 14-day redemption period, then deletion; "updates on your hostname do not confirm them", so an update client alone does not keep the name alive (article dated 2026-07-29) — [No-IP KB: Why is my hostname missing or deleted?](https://www.noip.com/support/knowledgebase/why-is-my-hostname-missing-or-deleted-what-do-i-do); confirmation methods — [No-IP KB: confirm free hostname](https://www.noip.com/support/?p=2887)
- DuckDNS: a free account is "limited to five subdomains" (per the Home Assistant add-on README; no official DuckDNS statement found) — [home-assistant/hassio-addons duckdns README](https://github.com/home-assistant/hassio-addons/blob/684e197b0ec4f25b206346041ab66ffe1e3bfa92/duckdns/README.md); updates are a single `curl` to the update URL (returns `OK`/`KO`), typically from cron every 5 min or so — [TrueNAS community DuckDNS how-to](https://www.truenas.com/community/threads/how-to-install-duckdns-org-a-how-to-guide.24170)
- Cloudflare as DDNS: community scripts update an A record with an API token scoped to "Edit DNS" from cron (e.g. [zhanghan177/cloudflare-ddns](https://github.com/zhanghan177/cloudflare-ddns), [cleberg.net walkthrough](https://cleberg.net/blog/cloudflare-dns-api/)); the API can only update an existing record, so create the A record once by hand — [OpenWrt ddns-scripts Cloudflare note (mirror)](https://38.54.75.67.sslip.io/docs/guide-user/services/ddns/cloudflare)
- Double NAT (nested routers): "Port forwarding from nested routers causes all connections to port forward to the parent router"; check whether the WAN IP is internal, and if so configure forwarding on the ISP modem/router too — [minecraft.wiki, Java server tutorial](https://minecraft.wiki/w/Tutorial:Setting_up_a_Java_Edition_server)
- CGNAT detection: compare the router's WAN IP with what whatismyip reports; a difference means an extra NAT; a WAN IP in 100.64.0.0/10 (100.64.0.0–100.127.255.255) is the strongest signal; a WAN IP in 10.x / 172.16–31 / 192.168 is also not public (CGNAT or a second router); traceroute alone is not conclusive because some ISPs hide hops — [OneUptime, detect CGNAT (2026-03-20)](https://oneuptime.com/blog/post/2026-03-20-detect-cgnat/view); same checks — [ipcheck.ing, am I behind CGNAT](https://docs.ipcheck.ing/knowledge-base/diagnose/am-i-behind-cgnat)
- Under CGNAT "you don't own a unique public IP, so inbound port forwarding fails"; fixes: ask the ISP for a public IP or use a tunnel — [OneUptime, detect CGNAT](https://oneuptime.com/blog/post/2026-03-20-detect-cgnat/view)
- US example: "T-Mobile home internet does not allow port forwarding" because CGNAT blocks unsolicited inbound traffic — [LocalXpose blog](https://localxpose.io/blog/t-mobile-home-internet-port-forwarding) (tunnel-vendor blog); an August 2026 guide lists the CGNAT workarounds as IPv6, a tunnel like Tailscale, a VPN with port forwarding, or an ISP public-IP add-on — [ModemGuides, Double NAT vs CGNAT](https://www.modemguides.com/blogs/modemguides-blog/double-nat-vs-cgnat-fix)
- IPv6: the wiki says "If for some reason you have trouble with connecting publicly over your IPv4, try connecting over IPv6" but "This should only be done for testing … external players should still use IPv4." — [minecraft.wiki, Java server tutorial](https://minecraft.wiki/w/Tutorial:Setting_up_a_Java_Edition_server); IPv6 addresses are typed in brackets, `[2001:db8::10]:25565`; bind `server-ip` to `::` or leave blank and open TCP 25565 in ip6tables — [OneUptime, Minecraft server with IPv6](https://oneuptime.com/blog/post/2026-03-20-configure-minecraft-server-ipv6/markdown); a client mod claims the vanilla client "will only try to connect to the first address it can find, which is usually the IPv4 address" rather than racing both — [Modrinth project acgisbT9](https://modrinth.com/project/acgisbT9); a tcpdump on a dual-stack host showed the client trying IPv4 first and giving up, fixed by removing the A record — [idefix.net note](https://idefix.net/~koos/newsitem.cgi/1662306697) (anecdotal)
- SRV records: "the game allows server operators using custom ports without requiring the player to explicitly type it"; the record name must be `_minecraft._tcp.<your-domain-name>`, it points at a hostname that needs an A record first, answer format `<weight> <port> <target>` e.g. `600 25565 mc.example.com`; verify with `nslookup -q=srv` / `dig … srv`; "Changes to your domain record are not instantaneous." — [minecraft.wiki, Java server tutorial](https://minecraft.wiki/w/Tutorial:Setting_up_a_Java_Edition_server)
- `_minecraft` "tells the name of the service, you may not change this or Minecraft will not resolve the SRV properly"; an SRV requires an existing A record — [MC Middle-earth wiki](https://www.mcmiddleearth.com/wiki/setting-up-a-srv-record/); registrar forms differ (some want the full `_minecraft._tcp.play` in the name field, others split service/protocol) — [Porkbun KB](https://kb.porkbun.com/article/148-how-to-connect-your-domain-to-minecraft-using-srv-records)
- SRV is Java-only: "Bedrock doesn't support SRV records" — [mcstatus FAQ](https://mcstatus.readthedocs.io/en/stable/pages/faq/); a Java client resolves `_minecraft._tcp` under the typed hostname to find host and port — [Infinity-Filter docs](https://docs.infinity-filter.com/miscellaneous/srv-records)
- Security hygiene from the wiki: "Close unused ports, and open ports when needed to prevent outside attacks and security exploits"; set `enable-status=false` to "appear offline to port scanners" (optional); "Incorrect configuration can lead to networking and security issues." — [minecraft.wiki, Java server tutorial](https://minecraft.wiki/w/Tutorial:Setting_up_a_Java_Edition_server)

### Inferences
- For 3–6 servers on one public IP, the SRV layout is one A record (`mc.example.com` → DDNS target, or a CNAME to the DuckDNS name) plus one SRV per server: `_minecraft._tcp.red.example.com → 0 5 25565 mc.example.com`, `_minecraft._tcp.blue.example.com → 0 5 25566 mc.example.com`, etc. Kids type `red.example.com`; the client reads the port from SRV. This needs a real domain (SRV on DuckDNS/No-IP free subdomains is not generally offered; not sourced, so verify), which is why Cloudflare-hosted DNS plus a DDNS script is the common pairing.
- Exposure: any port-forward route publishes the home IP to every kid's launcher and anyone who gets the hostname; the wiki's `online-mode=true` default keeps unknown accounts out, and a whitelist is the obvious add-on, but a determined griefer still learns the home IP (DDoS risk). Tunnels (section 3) hide it.
- Each extra forwarded port is another rule to maintain; a Velocity proxy (section 4) collapses this to one forward on 25565 and moves the "which server" decision to hostnames, which pairs well with SRV-less bare names.
- IPv6-only hosting is viable only if every kid's home has IPv6 (most US cable/fiber do, but not all Wi-Fi hotspots or school networks); the vanilla client's IPv4-first behaviour reported above means a dual-stack name does not fall back to v6 if v4 is blocked, so an IPv6-only plan would need AAAA-only names.

### Gaps
- Could not fetch the dedicated wiki port-forwarding or SRV sub-pages (404 at the old `Tutorials/` paths); the main Java tutorial covered both.
- No official DuckDNS statement on the five-subdomain limit or on whether SRV/other record types are offered for free subdomains.
- No official Mojang documentation on client SRV resolution or dual-stack behaviour; third-party and anecdotal only.
- No list of which US ISPs are CGNAT by default beyond T-Mobile Home Internet (vendor blog); Starlink residential status not confirmed in this research.

## 3. WAN via tunnels (no port forwarding): playit.gg, ngrok, Cloudflare Tunnel/Spectrum, Tailscale, ZeroTier, Headscale, VPS relay

### Takeaway
For kids who must install nothing, the only free, working option is playit.gg (host runs an agent, players connect to a `*.ply.gg`-style address; free tier is global-anycast only, and in late 2025/2026 generic TCP/UDP tunnels moved to the $3/month Premium while the Minecraft Java tunnel type stays free). ngrok TCP needs a card on file and caps at 1 GB/month free. Cloudflare Tunnel for Minecraft needs `cloudflared` on every kid's machine (Spectrum "Minecraft" exists but only on paid Pro+/one app). Tailscale, ZeroTier, and Headscale all require a client and an account on each kid's laptop. A $5-class VPS with WireGuard/frp/rathole gives full control for a few dollars a month and no client software.

### Cited Findings
- playit.gg: "Only you run the agent, your players just connect"; Minecraft Java and Bedrock are listed under the "Free" section; "Premium just $3/month"; 19 datacenters incl. Seattle, Los Angeles, Denver, Dallas, Chicago, New York, Miami — [playit.gg home](https://playit.gg/)
- playit free vs premium (search-indexed pricing table, not visible in the fetched page): free 6 TCP ports and 6 UDP ports vs 16 each on Premium ("If you're hosting Minecraft Java, you can host 6 servers for free!"), 1 vs 5 firewalls, 2 vs 10 agents, 0 vs 3 dedicated IPv6; Premium $3/month or $30/year; custom domain add-on $1/month, global dedicated IP $10/month — [playit.gg/pricing](https://playit.gg/pricing) (contradicted by the Premium support page, which says ports go "from 4 to 16")
- playit Premium page: free tunnels are "Global Anycast", which "work quite well but don't always route optimally"; Premium adds regional tunnels ("Regional tunnels fix this by ensuring the client connects to a datacenter in the specific region"), "3 custom domains", external domains, more firewall rules and agents — [playit.gg/support/playit-premium](https://playit.gg/support/playit-premium/)
- playit 2026 restriction evidence: a September 16, 2026 notice says for Bedrock "A TCP/UDP tunnel can be used, however this requires premium. We're actively working on … making it available to free users once again." — [playit.gg Bedrock NetherNet notice](https://playit.gg/support/minecraft-bedrock-nethernet/); a January 2026 Trustpilot reviewer: abusers led playit to "lock these tunnels behind a premium paywall" (TCP/UDP) — [Trustpilot playit.gg](https://nz.trustpilot.com/review/playit.gg?page=2) (user review); forum staff say free-region ports can be exhausted and that regional tunnels need premium — [discuss.playit.gg "Port limit reached"](https://discuss.playit.gg/t/port-limit-reached/3571)
- playit routing caveat: free anycast "can route a North American user through Singapore"; "The only way to influence which datacenter your players route through is with regional tunnels." — [playit.gg/pricing](https://playit.gg/pricing)
- ngrok: Free $0, "Up to 3 online endpoints", "TCP with credit card verification" ("TCP endpoints also need a verified credit card, and ngrok doesn't charge it"), 1 fixed TCP address, 1 GB data out, 5k TCP connections/month; Hobbyist $10/month: 3 endpoints, 5 GB then $0.10/GB; Pay-as-you-go $20/month base — [ngrok pricing](https://ngrok.com/pricing); limits detail — [ngrok pricing-limits](https://ngrok.com/docs/pricing-limits)
- Cloudflare Tunnel for arbitrary TCP: "`cloudflared` will need to be installed on each user device that will connect", run as `cloudflared access tcp --hostname tcp.site.com --url localhost:9210`, then the user points the app at that local port and signs in through a browser — [Cloudflare docs, arbitrary TCP](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/non-http/cloudflared-authentication/arbitrary-tcp/)
- Cloudflare Spectrum protocols per plan: Free "No" for everything; Minecraft "(one app allowed)" = "Yes" on Pro, Business, Enterprise; generic TCP/UDP = "Paid add-on" on Enterprise only — [Cloudflare docs, Spectrum protocols per plan](https://developers.cloudflare.com/spectrum/protocols-per-plan/); Pro plan ≈ $20/month annual or $25/month monthly (third-party 2026 guide) — [CDNsun Cloudflare pricing 2026](https://blog.cdnsun.com/cloudflare-pricing/); per-GB Spectrum fees quoted only by third-party blogs, unverified
- Tailscale Funnel: "Funnel can only listen on ports `443`, `8443`, and `10000`", "Funnel only works over TLS-encrypted connections", traffic "is subject to non-configurable bandwidth limits", "currently in beta", available on all plans — [Tailscale KB 1223 Funnel](https://tailscale.com/kb/1223/funnel); a third-party guide notes Funnel "does not give you the normal Java TCP 25565 … endpoint that players expect" — [natchecker.com](https://natchecker.com/blog/tailscale-minecraft-server)
- Tailscale game-server sharing: install on the server, lock the firewall to `tailscale0` + UDP 41641, Share the machine from the Machines page (reusable invite link "up to 1,000 times"); "Friends need their own Tailscale accounts to receive an invitation"; friends install Tailscale, accept, and enter the server's Tailscale IP + port 25565; shared machines are quarantined (inbound from friends only) — [Tailscale docs, share a private game server](https://tailscale.com/docs/use-cases/personal-or-at-home-use/share-private-game-server)
- Tailscale subnet routers are for devices that cannot run Tailscale (consoles, IoT) on the *server's* side; they do not let a non-tailnet player reach the tailnet — [Tailscale docs, devices without Tailscale](https://tailscale.com/docs/reference/devices-without-tailscale)
- Tailscale Personal plan: "Up to 6 users", "Unlimited user devices", $0 "Free forever", "for non-commercial use" — [Tailscale pricing](https://tailscale.com/pricing); Terms of Service updated August 25, 2026, no age clause surfaced in excerpts — [Tailscale terms](https://tailscale.com/legal/terms)
- ZeroTier: official docs say the free option "allows for a limited number of devices, and is intended for testing, non-commercial, and personal use" — [ZeroTier docs pricing](https://docs.zerotier.com/pricing); extracted plan data: free Personal = 10 devices, 1 network, 1 admin — [freetier.co ZeroTier listing](https://freetier.co/directory/products/zerotier) (aggregator); staff: "there's never been a per-network limit. Just an overall limit of total number of devices" — [ZeroTier forum](https://discuss.zerotier.com/t/zerotier-private-network-limit-free-tier/17486)
- Headscale: self-hosted Tailscale control server; "a single Tailscale network (tailnet), suitable for a personal use, or a small open-source organisation"; v0.29.0 published 2026-06-17 — [pkg.go.dev headscale v0.29.0](https://pkg.go.dev/github.com/juanfont/headscale@v0.29.0)
- VPS relay: the home box opens one outbound WireGuard tunnel to a VPS (CGNAT allows outbound), the VPS DNATs its public port through the tunnel; worked example is a Minecraft server on TCP 25565 — [1337hosting, port forwarding behind CGNAT/Starlink with WireGuard](https://1337hosting.com/tutorials/port-forwarding-behind-cgnat-starlink-wireguard); same pattern on Hetzner — [Hetzner community tutorial](https://community.hetzner.com/tutorials/bypass-cgnat-with-a-wireguard-vps-relay/); frp = `frps` on the VPS + `frpc` at home with a token and a TCP proxy mapping remote→local port; rathole is the Rust alternative — [OneUptime, CGNAT workarounds](https://oneuptime.com/blog/post/2026-03-20-cgnat-workaround-port-forwarding/view), [noted.lol, CGNAT and rathole](https://noted.lol/cgnat-and-rathole/)

### Inferences
- Kid-side software is the deciding factor for 10–20 children at home: playit.gg, ngrok TCP, Spectrum, and a VPS relay need nothing on the kid's laptop; Cloudflare Tunnel (cloudflared per kid + SSO login), Tailscale (account + client + accepting a share), ZeroTier (account/client + a network admin approving each node), and Headscale (client pointed at your server) all put an install and an account on every family's machine. Tailscale's free plan caps at 6 *users*; node-sharing invitees are not members of your tailnet, so a classroom of 20 shared-in families is plausible, but each family must create a Tailscale account (Google/Microsoft/GitHub/Apple login), which is a parental-consent conversation; I found no age clause in Tailscale's terms excerpt, so treat the under-13 question as open.
- playit free tier fits the 3–6 server case on paper (6 TCP "Minecraft Java" tunnels), but the 2026 posts about free-region port exhaustion, anycast misrouting, and TCP/UDP tunnels going Premium make the $30/year Premium the realistic budget if it's used weekly with kids; at that price regional (US) tunnels and 3 custom domains come with it.
- Cloudflare Spectrum "Minecraft (one app allowed)" on a $25/month Pro plan handles only one server address per zone, so for several servers it would need a proxy in front (section 4) or more zones; it is the only Cloudflare path where vanilla clients connect directly.
- A VPS relay is the most flexible no-client option: one public IP you control, all 3–6 ports (or a Velocity proxy on the VPS itself), the home IP hidden, latency equal to home→VPS→kid (pick a VPS in the same US region). Cost is the VPS (typically $4–6/month, not sourced here) plus an hour of WireGuard/frp setup.
- Latency: every tunnel adds a hop through a datacenter; for US kids within a few hundred miles of a US playit/VPS node this is tens of ms, which Minecraft tolerates (the wiki's ping scale calls 0–150 ms "good"), but anycast misrouting to another continent would not be.

### Gaps
- playit.gg has no dated changelog/announcement for the free-tier restriction; evidence is a Sept 2026 support note (Bedrock-specific) plus user reviews. Whether the "Minecraft Java" tunnel type is unaffected for new free accounts should be verified by creating one.
- Official Spectrum per-GB pricing and whether the "one app" Minecraft add-on carries usage fees were not found on cloudflare.com.
- ZeroTier's current pricing page could not be fetched; the 10-device figure is from an aggregator (one source claims 25 nodes, older).
- Tailscale Personal "6 users / unlimited devices" was read from the pricing page; older limits (3 users/100 devices) may still appear in third-party guides.

## 4. Several servers on one address: ports vs Velocity forced hosts vs `/server` vs `/transfer`

### Takeaway
Three workable patterns: (a) distinct ports, zero extra software, kids type `name:25566` or you add SRV records; (b) Velocity 4.3.0 (Java 25, supports clients 1.7.2–26.3) on 25565 with `[forced-hosts]` mapping `red.example.com`/`blue.example.com` to backends on localhost ports, plus `/server` hopping, which for vanilla 26.3 backends means running each backend on Fabric + FabricProxy-Lite (26.3 listed) with `online-mode=false` and firewalled ports; (c) pure vanilla: `accepts-transfers=true` on each server and `/transfer host [port]` to move players server-to-server with no proxy.

### Cited Findings
- Velocity current release: "Get Velocity 4.3.0" (build #44) — [papermc.io/downloads/velocity](https://papermc.io/downloads/velocity); "Velocity 4.0.x and above requires at least Java 25" — [Velocity FAQ](https://docs.papermc.io/velocity/faq/); "Velocity requires at least Java 25", default listen `0.0.0.0:25565` — [Velocity getting started](https://docs.papermc.io/velocity/getting-started/)
- Supported game versions: Velocity "is compatible with Minecraft 1.7.2 through 26.3"; Vanilla backends work "if it acts like Vanilla" but the Vanilla server "lacks player info forwarding support"; the team "strongly recommends that you use Fabric with the FabricProxy-Lite mod" (does not change the Vanilla experience, vanilla clients still work); VanillaCord is the fallback for legacy forwarding; Paper recommended for public servers; proxy-behind-proxy unsupported — [Velocity server compatibility](https://docs.papermc.io/velocity/server-compatibility/)
- Forced hosts config: "This configures the proxy to create a forced host for the specified hostname"; the value is "An array of servers to try for the specified hostname"; `try` = "what servers Velocity should try to connect to upon player login and when a player is kicked from a server"; `bind` listens on all addresses on 25565 by default — [Velocity configuration](https://docs.papermc.io/velocity/configuration/)
- Default `velocity.toml` example (verbatim):
  `[servers]` `lobby = "127.0.0.1:30066"` `factions = "127.0.0.1:30067"` `minigames = "127.0.0.1:30068"` `try = ["lobby"]`; `[forced-hosts]` `"lobby.example.com" = ["lobby"]` `"factions.example.com" = ["factions"]` `"minigames.example.com" = ["minigames"]`; `player-info-forwarding-mode` options `none` (offline-mode UUIDs), `legacy` (≤1.12), `bungeeguard`, `modern` ("Only applicable for Minecraft 1.13 or higher"); `ping-passthrough` can take the MOTD/description from "The first server in the try (or forced host) list that responds" — [default-velocity.toml](https://raw.githubusercontent.com/PaperMC/Velocity/dev/3.0.0/proxy/src/main/resources/default-velocity.toml)
- Hostname matching is case-insensitive and "port numbers are ignored when matching hostnames" (stated for Gate, a Velocity-compatible proxy with the same forced-hosts model) — [Gate docs, forced hosts](https://www.mintlify.com/minekube/gate/configuration/forced-hosts)
- Forwarding: backends must "disable the `online-mode` setting in the `server.properties` file" ("the proxy will do [authentication] instead"); modern forwarding on Fabric = FabricProxy-Lite; "Legacy forwarding is fundamentally insecure"; Paper sets `proxies.velocity.secret` to match `forwarding.secret` — [Velocity player information forwarding](https://docs.papermc.io/velocity/player-information-forwarding/); offline-mode backends are "dangerously insecure" until the forwarding + securing steps are done — [Velocity getting started](https://docs.papermc.io/velocity/getting-started/)
- FabricProxy-Lite: "Fabric mod for support forward player data from velocity", requires `player-info-forwarding-mode = modern`, `secret` "should be the same random string as in Velocity's `forwarding.secret` file" (or `FABRIC_PROXY_SECRET_FILE`), supported versions list includes 26.3, 26.2, 26.1.x; server-side only; "Updated 7 months ago" — [Modrinth, FabricProxy-Lite](https://modrinth.com/mod/fabricproxy-lite)
- `/transfer`: Java syntax `transfer <hostname> [<port>] [<players>]`, port "defaults to `25565`", added in Java Edition 1.20.5 (24w04a), permission level 3 — [minecraft.wiki, Commands/transfer](https://minecraft.wiki/w/Commands/transfer)
- `accepts-transfers` (default false): "When false, incoming transfers are rejected and the player is disconnected. When true, incoming transfers are allowed" — [minecraft.wiki, Server.properties](https://minecraft.wiki/w/Server.properties); 24w03a: "Custom servers can now request that clients connect to another server with a new packet"; "By default, servers don't accept incoming transfers and disconnect the client"; the transferred client connects with transfer intent id 3; resource packs carry over; cookies (≤5 KiB) "persist across server transfers but are not kept after the player disconnects" — [minecraft.wiki, Java Edition 24w03a](https://minecraft.wiki/w/Java_Edition_24w03a)
- Paper names the property `accept-transfers` on newer builds (plugins note the name differs) — [Paper server.properties reference](https://docs.papermc.io/paper/reference/server-properties), [Modrinth TransferX](https://modrinth.com/mod/transferx); rejected transfer shows "Connection failed while transferring to the server. The server does not accept transfers." — [Modrinth ServerTransfer](https://modrinth.com/plugin/servertransfer); a third-party tool describes the experience as the client disconnecting and "immediately reconnect[ing] to the destination, exactly as if the player had clicked the server in their Multiplayer list" — [minecraftmaps transfer generator](https://www.minecraftmaps.com/tools/transfer-command-generator) (non-official)

### Inferences
- Pattern (a), ports: for Dave's datapack games the simplest is six vanilla jars on 25565–25570, six router forwards (or six playit tunnels), and either `name:port` on a card or SRV names. Nothing to patch when 26.4 lands.
- Pattern (b), Velocity: one forward/tunnel, hostnames instead of ports, `/server <name>` for kids to hop, one MOTD per forced host. Costs: Java 25 (already needed for 26.3), each backend must run Fabric + FabricProxy-Lite (vanilla jar cannot receive modern forwarding, so skins/UUIDs/whitelist break under `none`), backends in `online-mode=false` bound to `127.0.0.1` so nobody bypasses the proxy, and a redeploy when Velocity/FabricProxy-Lite lag a new game version (FabricProxy-Lite shows 26.3 already). Forced hosts need DNS names for each server; with a single DDNS name only, `/server` hopping from the default `try` server still works.
- Pattern (c), vanilla `/transfer`: with `accepts-transfers=true` on all six, a command block/datapack (`transfer <host> 25566`) moves a kid between servers with no proxy or mod; the kid's client reconnects to the new address, so the new address must be reachable from where the kid is (public name from home, private IP in the studio — the same hairpin caveat as section 1). Transfers from a datapack need the hostname baked into the function, so keep one DDNS name and vary ports.
- Mixing (c) with per-port exposure is the lowest-maintenance "hub" design for vanilla-only clients; (b) is better if kids should never see ports or if the box is behind a single playit tunnel.

### Gaps
- Velocity's own docs do not state in prose whether 26.3 clients are "fully" supported beyond the compatibility line; no PaperMC release notes for 4.3.0 were retrievable.
- Official wiki text on what the player sees during `/transfer` (any prompt?) was not found; only third-party descriptions.
- No measurement of Velocity overhead on a single home box.

## 5. Firewall notes specific to Minecraft Java

### Takeaway
A Java server needs exactly one inbound rule: TCP `server-port` (25565 default). Query (UDP 25565 by default) and RCON (TCP 25575) are off by default and should stay unexposed (RCON is unencrypted); UDP forwards are only for Bedrock/Geyser (19132) or the Simple Voice Chat mod (24454). Leave `server-ip` blank; with a proxy, bind backends to localhost instead.

### Cited Findings
- `server-port`: "The TCP port number the server listens on"; `query.port` (default 25565): "The UDP port number query … listens on", `enable-query` default false; `enable-rcon` default false, "It's not recommended to connect to rcon via untrusted networks, like the internet, as it is not encrypted"; `rcon.port` (default 25575): "The TCP port number rcon listens on"; `server-ip` blank = all interfaces; `online-mode` "should only be set to false when the server is not connected to the Internet"; `enforce-secure-profile` default true; `prevent-proxy-connections` kicks players whose ISP/AS differs from what Mojang's auth server saw — [minecraft.wiki, Server.properties](https://minecraft.wiki/w/Server.properties)
- The wiki tutorial's forwarding instructions say open "TCP/UDP" for 25565, but the only UDP listener on 25565 is Query, which is off by default (see above) — [minecraft.wiki, Java server tutorial](https://minecraft.wiki/w/Tutorial:Setting_up_a_Java_Edition_server) and [Server.properties](https://minecraft.wiki/w/Server.properties)
- Server list ping: the Multiplayer screen shows ping per server; Java ping icons scale "Between 0 and 150ms" (good) to "Above 1000ms"; `enable-status=false` makes the server "appear offline to port scanners" (and in the server list) — [minecraft.wiki, Multiplayer](https://minecraft.wiki/w/Multiplayer), [Java server tutorial](https://minecraft.wiki/w/Tutorial:Setting_up_a_Java_Edition_server)
- Simple Voice Chat "does not use your normal Minecraft port (25565 TCP). It uses a separate UDP port, and the default is 24454"; Geyser wants UDP 19132; they cannot share a UDP port — [supercraft.host voice chat guide](https://supercraft.host/wiki/minecraft/simple-voice-chat-server-setup/), [Aternos, installing voice chat mods](https://support.aternos.org/hc/en-us/articles/360019336497-Installing-Voice-Chat-Mods)
- Velocity: backends go `online-mode=false` and must be secured so "nothing aside from the proxy can connect to your server" — [Velocity player information forwarding](https://docs.papermc.io/velocity/player-information-forwarding/); Tailscale's game-server guide shows the pattern of denying inbound by default and allowing only the VPN interface — [Tailscale docs, share a private game server](https://tailscale.com/docs/use-cases/personal-or-at-home-use/share-private-game-server)

### Inferences
- On Arch with no firewall by default, the minimal hardening for the port-forward route is: forward only TCP 25565–2557x on the router, keep `enable-query`/`enable-rcon` false (or bind RCON use to localhost via `ssh`), and leave `online-mode=true` with a whitelist of the kids' usernames. For the Velocity route add a host firewall (nftables/ufw) that allows TCP 25565 from anywhere and the backend ports only from 127.0.0.1.
- `prevent-proxy-connections=true` would kick kids who connect through a VPN/tunnel whose exit AS differs from their auth request; leave it false when using Tailscale/playit-style paths.

### Gaps
- No Mojang document enumerating "only TCP is needed"; it follows from the per-property protocol notes in Server.properties.

## 6. Child-account multiplayer (Xbox/Microsoft Family) and LAN vs internet

### Takeaway
A child Microsoft account with the Xbox "Multiplayer" privilege off sees the Java client's Multiplayer button greyed out with "Multiplayer is disabled. Please check your Microsoft account settings"; the organizer flips it in the Xbox Family Settings app (Multiplayer tile → Allow) or at the Xbox privacy page ("You can join multiplayer games", plus "You can play with people outside Xbox Live" and "You can join cross-network play" per the fullest third-party checklist), then the child signs out/in and may wait up to a day. Because LAN worlds are listed inside that same Multiplayer screen, a blocked account cannot join a LAN server either (inference; no official text found). The official article exists (title "Managing Multiplayer Game Access for a Child Account in Minecraft") but its page timed out on every fetch.

### Cited Findings
- In-game text quoted by a parent: "Multiplayer is disabled. Please check your Microsoft account settings"; accepted answer (2020): account.microsoft.com/family → More Options → Xbox settings → Privacy & online settings → pick the child → "Xbox1 / Win10 online security" tab → allow multiplayer games; Microsoft help text quoted in the thread: "Decide if a member can play multiplayer games with their friends. **Note** If a member wants to play Minecraft, you'll need to have this option turned on. Select the **Multiplayer** tile and turn **Allow** off or on." — [Microsoft Q&A 4220013](https://learn.microsoft.com/en-us/answers/questions/4220013/minecraft-java-edition-multiplayer-option-disabled)
- Same greyed-out button reported in 2026 on macOS; a Microsoft moderator said a mis-classified (child-flagged) adult account needs Microsoft Support "manual review" with government ID — [Microsoft Q&A 5831285](https://learn.microsoft.com/en-us/answers/questions/5831285/minecraft-java-edition-multiplayer-disabled-micros)
- Official article link (not retrievable in this research): help.minecraft.net "Managing Multiplayer Game Access for a Child Account in Minecraft" — [help.minecraft.net article 24302916594701](https://help.minecraft.net/hc/en-us/articles/24302916594701-Managing-Multiplayer-Game-Access-for-a-Child-Account-in-Minecraft) (cited via [Microsoft Q&A 5630668](https://learn.microsoft.com/en-us/answers/questions/5630668/how-to-fix-parental-controls-for-minecraft-multipl))
- Fullest setting checklist (third-party, a kids' Minecraft club): in Microsoft Family Safety → Settings → Xbox & gaming allow "Join multiplayer games", "Play with people outside Xbox Live", "Join cross-network play"; on xbox.com (parent signed in) → Privacy & online safety → Xbox privacy, child profile: required "You can join multiplayer games", "You can play with people outside Xbox Live", "You can join cross-network play"; recommended "Communicate with voice & text outside Xbox Live", "Text chat in multiplayer games"; also allow Minecraft under Screen time → Apps & games; click Save, fully restart Minecraft; changes must be made from the parent account — [Mud Club, Minecraft Access Checklist](https://mudclub.helpjuice.com/en_US/online-safety-and-privacy/minecraft-access-checklist)

- A June 2026 thread reports the Xbox privacy page showing "You do not have permission to change these settings" and Family Safety server errors when adding the account to a family (unresolved) — [Microsoft Q&A 5912527](https://learn.microsoft.com/ru-ru/answers/questions/5912527/multiplayer-blocked-in-minecraft-java-edition-bugg)
- A Mojang bug report described the message appearing only via the current launcher, not the legacy launcher; closed "Cannot Reproduce" — [MCL-23731](https://bugs.mojang.com/browse/MCL-23731)
- The Java Multiplayer screen is where LAN games appear ("Multiplayer now scans for local games"; LAN worlds "pop up automatically in the server list") — [minecraft.wiki, Multiplayer](https://minecraft.wiki/w/Multiplayer); Bedrock console note: an online subscription is required for multiplayer and "This includes joining or hosting a LAN multiplayer game" — [minecraft.wiki, Multiplayer](https://minecraft.wiki/w/Multiplayer)

### Inferences
- The Java client gates the whole Multiplayer menu (server list, Direct Connect, LAN scan) on the Xbox multiplayer privilege, so a LAN-only studio server does not sidestep the family setting: every child account the studio uses must have "Join multiplayer games" allowed, regardless of LAN vs internet. The one documented exception is Bedrock-on-console, not Java.
- For a class of 10–20 kids, the practical plan is a take-home sheet for parents with the three Xbox privacy toggles above, asking them to do it at least a day before the session, plus a studio set of adult-owned Microsoft accounts (one per laptop) as a fallback, since propagation delays and mis-flagged accounts are the recurring failures in 2026 threads.
- Whether a parent is comfortable enabling "Play with people outside Xbox Live" is the real policy question: a private whitelisted server (online-mode on) limits who can actually join, but the toggle itself is account-wide and also opens public servers.
