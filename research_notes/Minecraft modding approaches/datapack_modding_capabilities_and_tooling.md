# Data-pack-only "modding" of Minecraft Java Edition in 26.x: capabilities, hard limits, tooling, distribution

Research date: 2026-10-12. Current release: Java Edition 26.3 "Wilderness Bound" (released 2026-09-15; data pack format 121.0, resource pack format 97.1). Anything marked **[pre-26.x]** landed before the switch to date-based versioning (26.1, released 2026-03-24, was the first date-versioned release). Primary sources are the Minecraft Wiki (minecraft.wiki) and Mojang's changelogs; where only secondary sources were reachable this is flagged. Some official pages (minecraft.net articles, feedback.minecraft.net changelogs, vanillatweaks.net, planetminecraft.com) refused or timed out on automated fetches, so a few counts and quotes come from the wiki or from secondary write-ups and are labelled as such.

## Key question 1: Capability inventory in 26.x (what a data pack can define, with the version each landed in)

### Takeaway
By 26.3 a data pack is a large JSON/NBT/mcfunction surface: ~55 registries under `data/<namespace>/` (functions, predicates, loot tables, item modifiers, recipes, advancements, enchantments, dialogs, damage types, dimensions, full world gen, GameTest instances, villager trades, world clocks, block transformers, and more), plus commands including function macros (1.20.2), `/dialog` (1.21.6), `/time` with clocks (26.1) and `/compute` + `/posteffect` (26.3). 26.3 is also a large *breaking* format revision (loot/predicate field renames, `number_provider` split into context providers, `worldgen/configured_feature` → `worldgen/feature`).

### Cited Findings

**Pack format history and the min_format/max_format mechanism**
- Data pack format mapping: 48 = 1.21–1.21.1 (data-driven enchantments and paintings); 57 = 1.21.2–1.21.3; 61 = 1.21.4; 71 = 1.21.5 (text components stored as NBT objects); 80 = 1.21.6 (`/version` added); 81 = 1.21.7–1.21.8; 88.0 = 1.21.9–1.21.10; 94.1 = 1.21.11 (`/stopwatch`, environment attributes, timelines, `attack_range`); 101.1 = 26.1–26.1.2 (data-driven villager trades; world clocks and time markers); 107.1 = 26.2 (entity predicate format changed); 121.0 = 26.3. — [Minecraft Wiki: Pack format](https://minecraft.wiki/w/Pack_format)
- Snapshot/pre-release formats: 26.1 snapshots 95.0–100.0 and pre-releases 101.0–101.1; 26.2 snapshots 101.2–106.0 and pre-releases 106.1–107.1; 26.3 snapshots 108.0–118.0 and pre-releases 119.0–121.0 (format 114 skipped). — [Minecraft Wiki: Pack format](https://minecraft.wiki/w/Pack_format)
- Starting with snapshot 25w31a (1.21.9), `pack.mcmeta` uses `min_format` and `max_format` instead of `pack_format`, for both data packs and resource packs. From format 88.0 onward, formats carry a minor version; non-breaking changes raise only the minor number. — [Minecraft Wiki: Pack format](https://minecraft.wiki/w/Pack_format); [Minecraft Wiki: Data pack](https://minecraft.wiki/w/Data_pack)
- Resource pack formats for 26.x: 84.0 (26.1), 88.0 (26.2), 97.1 (26.3); 26.4 snapshot 3 is already at 100.0. — [Minecraft Wiki: Pack format](https://minecraft.wiki/w/Pack_format); [Minecraft Wiki: Resource pack](https://minecraft.wiki/w/Resource_pack)
- Multiple-format declarations and **overlays** (alternate directories applied on top of the base pack) since 23w31a (1.20.2); **filter** section (block files from lower packs) since format 9/10 (1.19). — [Minecraft Wiki: Data pack](https://minecraft.wiki/w/Data_pack)

**Registries available to data packs (26.3 wiki listing, `data/<namespace>/…`)**
- Functions: `function` + `tags/function`; structures: `structure` (.nbt); `advancement`; loot/items: `loot_table`, `item_modifier`, `predicate`, `recipe`, `slot_source`, `context_float_provider`, `context_int_provider`; enchantments: `enchantment`, `enchantment_provider`; dimensions: `dimension`, `dimension_type`; `worldgen/` (biome, configured_carver, configured_feature, density_function, noise, noise_settings, placed_feature, processor_list, structure, structure_set, template_pool, world_preset, flat_level_generator_preset, multi_noise_biome_source_parameter_list); mob variants (cat, chicken, cow, frog, pig, wolf, wolf_sound, zombie_nautilus); cosmetics (`banner_pattern`, `painting_variant`, `trim_material`, `trim_pattern`, `decorated_pot_pattern`, `instrument`, `jukebox_song`); `chat_type`, `damage_type`, `dialog`; trading (`villager_trade`, `trade_set`); `trial_spawner`, `world_clock`, `timeline`, `block_transformer`, `sulfur_cube_archetype`; GameTest (`test_environment`, `test_instance`); `tags/<registry>`. Many of these are flagged "experimental" on the wiki in the sense that they are dynamic registries requiring a world reopen/server restart (not `/reload`). — [Minecraft Wiki: Data pack](https://minecraft.wiki/w/Data_pack)
- Note the Nodecraft 26.3 write-up says `worldgen/configured_feature` became `worldgen/feature` and `worldgen/configured_carver` became `worldgen/carver` in 26.3; the wiki Data pack page fetched still listed the old names (likely lag). — [Nodecraft, 2026-09-15](https://nodecraft.com/blog/game-news-tips/minecraft-java-26-3-wilderness-bound-is-out-what-it-means-for-your-server) (secondary)
- `/reload` applies changes to tags, loot tables, recipes, advancements, item modifiers, predicates, functions and structure templates; dynamic-registry content (dimensions, worldgen, enchantments, dialogs, etc.) needs a world reopen (singleplayer) or server restart. — [Minecraft Wiki: Data pack](https://minecraft.wiki/w/Data_pack)
- Data pack history **[pre-26.x]**: data packs added 1.13 (17w43a), `/datapack` 17w46a, recipes 17w48a, tags 17w49a/b, `#minecraft:load` 18w01a; entity type tags 1.14; predicates 1.15 (19w38a); Safe Mode and custom dimensions 1.16; item modifiers 1.17 (20w46a); data-driven structures 1.18.2; pack filters and chat types 1.19; damage types 1.19.4 (23w06a); trim materials/patterns 1.19.4→1.20; overlays 1.20.2 (23w31a); wolf variants and banner patterns 1.20.5 (24w10a); data-driven enchantments and painting variants 1.21 (24w18a); jukebox songs 1.21 (24w21a); folder names singularised 1.21 (24w19a/24w21a); goat horn instruments, trial spawner configs, GameTests, mob variants, dialogs, timelines through 1.21.2–1.21.11. — [Minecraft Wiki: Data pack](https://minecraft.wiki/w/Data_pack)

**Functions and macros [pre-26.x unless noted]**
- `.mcfunction` files under `data/<ns>/function/` (renamed from `functions` in 1.21, 24w21a); one command per line, no leading slash, `#` comments; trailing backslash continues a line (1.20.2, 23w31a); commands in functions may exceed the 32,500-character command-block limit. — [Minecraft Wiki: Function](https://minecraft.wiki/w/Function_(Java_Edition))
- **Macros** added 1.20.2 (23w31a): lines beginning `$` with `$(key)` placeholders (keys `[A-Za-z0-9_]`), filled from a compound passed inline or via `with block|entity|storage <path>`; strings insert without quotes, numbers without suffixes, booleans as 1/0, lists/compounds as SNBT; a missing key or unparseable substituted line makes the whole function fail to run. — [Minecraft Wiki: Function](https://minecraft.wiki/w/Function_(Java_Edition))
- Limit: `max_command_sequence_length` gamerule, default 65,536 commands per function run; all nested calls execute within one tick. `#minecraft:load` runs before `#minecraft:tick` since 1.19.3 (22w46a); `/return` and "functions return no result unless they use /return" since 1.20.3 (23w41a). The wiki lists no function-format changes in 1.21.x–26.x. — [Minecraft Wiki: Function](https://minecraft.wiki/w/Function_(Java_Edition))

**Predicates**
- Condition `type` values in 26.3: `all_of`, `any_of`, `damage_source_properties`, `enchantment_active_check`, `entity_properties`, `entity_scores`, `float_value_check`, `int_value_check`, `inverted`, `killed_by_player`, `location_check`, `match_block`, `match_tool`, `random_chance`, `random_chance_with_enchanted_bonus`, `survives_explosion`, `table_bonus`, `time_check`, `weather_check`. Removed in 26.3: `reference` and `block_state_property` (snapshot 4; the latter replaced by `match_block`), `value_check` (pre-release 1; split into int/float). The top-level field was renamed `condition` → `type` in 26.3 snapshot 4. — [Minecraft Wiki: Predicate](https://minecraft.wiki/w/Predicate)
- 26.2 snapshot 3: entity predicates changed to a component-map-like format with identifier keys (`type` → `minecraft:entity_type`); unknown sub-predicate keys are now rejected rather than ignored; type-specific sub-predicates moved to `minecraft:type_specific/<x>`; new `minecraft:entity_tags` sub-predicate (`any_of`/`all_of`/`none_of`). — [Minecraft Wiki: Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2); [Minecraft Wiki: Predicate](https://minecraft.wiki/w/Predicate)
- Entity sub-predicate history **[pre-26.x]**: `type_specific` 1.19 (22w14a); `slots` 1.21 (24w10a); `movement` and `periodic_ticks` 1.21 (24w18a); flags `is_on_ground`/`is_flying` 1.21 (24w18a); gamemode accepts a list 1.21 (24w21a); player `input` 1.21.2 (24w36a); flags "now supports new values" 1.21.11 (25w41a). 26.1 snapshot 1 added an optional `food` field to the player sub-predicate. — [Minecraft Wiki: Predicate](https://minecraft.wiki/w/Predicate)
- 26.1 added predicate `minecraft:environment_attribute_check` and number providers `minecraft:environment_attribute` and `minecraft:sum`; 26.3 added block predicate `minecraft:height_range`. — [Minecraft Wiki: Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1); [Minecraft Wiki: Java Edition 26.3](https://minecraft.wiki/w/Java_Edition_26.3)

**Loot tables / item modifiers (26.x changes)**
- 26.1: new loot context `minecraft:villager_trade`; new loot functions `set_random_dyes`, `set_random_potion`; `enchant_with_levels`/`enchant_randomly` gain `include_additional_cost_component`. — [Minecraft Wiki: Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1)
- 26.3 (per Nodecraft's summary of the official notes): `minecraft:number_provider` removed, replaced by `minecraft:context_int_provider` and `minecraft:context_float_provider`; `minecraft:reference` removed from loot functions and predicates (fields accept IDs or inline objects directly); loot pool entries rename `conditions` → `condition` and `functions` → `modifier`; loot functions rename `function` → `type`; recipes: `cookingtime` now required, smoker/blast furnace use the furnace value (double custom times), brewing is a `minecraft:brewing` recipe type. The article warns "Nearly all complicated datapacks will not work with this new format." — [Nodecraft, 2026-09-15](https://nodecraft.com/blog/game-news-tips/minecraft-java-26-3-wilderness-bound-is-out-what-it-means-for-your-server) (secondary; wiki 26.3 page confirms the new `context_*_provider` registries and `#brewing_fuel` tag removal) — [Minecraft Wiki: Java Edition 26.3](https://minecraft.wiki/w/Java_Edition_26.3)

**Item components and custom items**
- Components replaced NBT item data in 1.20.5 **[pre-26.x]**. Components relevant to custom items (as documented for 26.3): `custom_data` (arbitrary NBT, e.g. `iron_sword[custom_data={foo:1}]`), `item_model` (points to an item model definition; nonexistent → missing model), `custom_model_data` (lists `floats`, `flags`, `strings`, `colors` consumed by item model definitions), `item_name` (non-italic, not anvil-removable) vs `custom_name`, `equippable` (slot, sounds, `asset_id`), `consumable` (`consume_seconds`, `animation`, `sound`, `on_consume_effects`), `food`, `damage_resistant`, `enchantable`, `blocks_attacks` (shield-like), `glider` (elytra-like), `death_protection` (totem-like), `attribute_modifiers`, `can_break`/`can_place_on` (adventure mode), `attack_animation` (`whack`/`stab`/`none` + duration), `kinetic_weapon`, block-entity components `container`, `container_loot`, `lock`. — [Minecraft Wiki: Data component format](https://minecraft.wiki/w/Data_component_format)
- Version landmarks: `item_model`, `equippable`, `glider`, `tooltip_style` added 1.21.2 (24w36a); `item_name` always present from 24w36a. — [Minecraft Wiki: 24w36a](https://minecraft.wiki/w/Java_Edition_24w36a)
- 26.1 components: `additional_trade_cost` (transient), `dye` ("The presence of this component itself does not enable functionality"); `provides_banner_patterns`, `blocks_attacks.bypassed_by`, `damage_resistant` accept IDs or lists, not only tags. — [Minecraft Wiki: Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1)
- 26.2 components: `sulfur_cube_content`; new attributes `air_drag_modifier`, `below_name_distance`, `bounciness` (0–1), `friction_modifier`, `name_tag_distance`; `knockback_resistance` min −2.0. — [Minecraft Wiki: Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2)
- 26.3 components: `attack_animation` and `interact_animation`; `block_transformer` (item converts blocks on use: block state provider, sound, particle, loot, `consume_on_use`, `item_damage_per_use`; axes/hoes/shovels use it by default — i.e. stripping/tilling/pathing is now data-driven); `brewing_fuel` (`uses`, `speed_multiplier`), `cooking_fuel`, `compostable`, `cushion/color`, `mob_visibility`, `provides_pottery_pattern`, `sign_text_front`/`sign_text_back`, `villager_food`, `waxed`. — [Minecraft Wiki: Java Edition 26.3](https://minecraft.wiki/w/Java_Edition_26.3)

**Dialogs (1.21.6+) [pre-26.x origin]**
- Introduced 1.21.6 (25w20a). Types: `notice`, `confirmation`, `multi_action`, `server_links`, `dialog_list`. Common fields: title, `external_title`, `can_close_with_escape`, `pause`, `after_action` (`close`/`none`/`wait_for_response`). Body: `plain_message`, `item` (size 1–256). Inputs: `text` (optional multiline), `boolean`, `single_option`, `number_range`. Actions: static `open_url`, `run_command`, `suggest_command`, `change_page`, `copy_to_clipboard`, `show_dialog`, `custom`; dynamic `dynamic/run_command` (macro template with `$(key)` from inputs) and `dynamic/custom`. Opened via `/dialog`, a `show_dialog` click action, or the pause-menu / Quick Actions keybind via dialog tags. — [Minecraft Wiki: Dialog](https://minecraft.wiki/w/Dialog)
- Limits: `run_command` runs as the player (needs their permission level; privileged commands only for operators); controls disabled while a dialog is open; `pause:true` pauses singleplayer and autosaves; `after_action: none` only allowed when `pause` is false; NBT/score/selector text components are not resolved in dialogs (MC-297871); `custom` events do nothing on vanilla servers. — [Minecraft Wiki: Dialog](https://minecraft.wiki/w/Dialog)
- `/dialog show <targets> <dialog>` (registry ID or inline SNBT) and `/dialog clear <targets>`; permission level 2; added 25w20a; built-in blank dialogs `minecraft:custom_options`, `minecraft:server_links`, and (1.21.6 pre-1) `minecraft:quick_actions`. The wiki lists no changes to `/dialog` in 1.21.7–26.3. — [Minecraft Wiki: Commands/dialog](https://minecraft.wiki/w/Commands/dialog)
- Every dialog header contains a warning button that "is always there"; clicking it opens a screen explaining that the content is custom and offering to leave the world. Players have asked Mojang for a "never show again" option. — [Kore docs: Dialogs](https://kore.ayfri.com/docs/dialogs) (secondary); [FancyInnovations blog on 25w20a](https://docs.fancyinnovations.com/blog/what-are-minecraft-dialogs/) (secondary); [feedback.minecraft.net thread](https://feedback.minecraft.net/hc/en-us/community/posts/36772820246029/comments/37097836540813)

- 26.1: `/swing <entity> <mainhand|offhand>`; `/fetchprofile entity <selector>`; `/time` reworked around **world clocks** (`of <clock>`, `pause`, `resume`, `query <timeline>`, `rate <0..1000>`, time markers `day`/`noon`/`night`/`midnight`); `set`/`add` now return elapsed ticks. **Text components**
- 1.21.5 **[pre-26.x]**: text components stored as NBT objects; snake_case `click_event`/`hover_event`, `run_command` takes `command`. 26.1 pre-release 1 changed the `minecraft:nbt`, `minecraft:selector`, and `minecraft:object` text-component formats; `object` gained an optional `fallback` for contexts that can't render it (logs, narration); player-head objects no longer allowed in server status messages. — [Minecraft Wiki: Pack format](https://minecraft.wiki/w/Pack_format); [minecraft.net: 26.1 Pre-Release 1](https://www.minecraft.net/article/minecraft-26-1-pre-release-1) (via search snippet)

### Inferences
- 26.3 is the biggest format break since 1.20.5/1.21: the loot/predicate key renames and the removal of `reference`/`number_provider` mean virtually every non-trivial pack needs edits to move from 107 to 121, which is why the `min_format`/`max_format` range mechanism matters (a pack can declare 107–121 only if it uses no renamed fields, as this repo's four game packs do).
- Mojang's cadence is now roughly one data-pack-format major bump per snapshot (108→121 across ten snapshots and three pre-releases of 26.3), so "which pack format" is a moving target within each drop; tools that pin formats (Spyglass, Misode) lag by weeks.
- The direction of each drop is consistent: hard-coded behaviours (villager trades, tool block-conversion, fuels, compost, sign text, time of day) are being lifted into data (26.1 trades, 26.3 `block_transformer`/`cooking_fuel`/`compostable`), which steadily widens what a "no Java" pack can change.

- The wiki 26.3 page was truncated at ~100k characters before its dialog/text-component/function sections; I could not confirm whether dialogs or functions changed in 26.3 beyond what the `Commands/dialog` and `Function` pages show (both list no 26.x changes).
- Mojang's own 26.3 release article on minecraft.net and the feedback.minecraft.net changelogs timed out / returned 403, so the `/item fill|override`, `/execute … slots`, and loot-key-rename items rest on the Nodecraft summary plus the wiki Predicate page (which independently confirms `condition` → `type` and the removed predicate types).

## Key question 2: Hard limits of data-pack-only modding (and the standard workarounds)

### Takeaway
A data pack sees only what the server sees: movement/jump/sneak/sprint key states (via the player `input` predicate since 1.21.2), statistics (jumps, drops, item use, sneak time), inventory/hotbar NBT, advancement triggers, and interaction/attack events on entities; it cannot add blocks, entity types, GUIs, sounds, textures, or client rendering, and the workarounds are display/interaction/marker entities, item model definitions keyed on `custom_model_data`/`item_model`, and dialogs/books/signs/containers for UI.

### Cited Findings

**Which inputs the server can see**
- Player `input` sub-predicate (1.21.2, 24w36a): seven optional booleans `forward`, `backward`, `left`, `right`, `jump`, `sneak`, `sprint`, matched against "the corresponding keybind the player is pressing". — [Minecraft Wiki: 24w36a](https://minecraft.wiki/w/Java_Edition_24w36a); [Minecraft Wiki: Predicate](https://minecraft.wiki/w/Predicate)
- Custom statistics usable as scoreboard criteria: `minecraft:jump` (count), `sneak_time` (ticks), `crouch_one_cm`, `sprint_one_cm`, `swim_one_cm`, `aviate_one_cm`, `drop` (items dropped, count), `open_chest`, `interact_with_<station>`, `play_time`, `time_since_rest`; statistic-type criteria families `minecraft.used`, `mined`, `crafted`, `broken`, `picked_up`, `dropped`, `killed`, `killed_by`, each keyed by a resource location (e.g. `minecraft.used:minecraft.carrot_on_a_stick`). There is no `use_item` custom stat; item use is `minecraft.used:<item>`. — [Minecraft Wiki: Statistics](https://minecraft.wiki/w/Statistics)
- Entity flags testable in predicates include `is_on_ground` and `is_flying` (1.21, 24w18a) with further unnamed values added in 1.21.11 (25w41a); this repo's `predicate/sneaking.json` uses `minecraft:flags.is_sneaking` successfully in 26.3 (local verification, see project CLAUDE.md). — [Minecraft Wiki: Predicate](https://minecraft.wiki/w/Predicate)
- Interaction entity (1.19.4, 23w07a) **[pre-26.x]**: invisible, invincible, custom `width`/`height` (default 1); `response` 1 makes left-click play a punch sound and right-click swing the arm; stores last `attack` and `interaction` compounds (`player` UUID + `timestamp`); detect via `/data get`, advancement triggers `player_hurt_entity` (left) / `player_interacted_with_entity` (right), or `/execute on attacker` / `on target`. Detection stops at roughly 22.6 blocks in each dimension and is asymmetric (about 3.3 blocks in −X/−Z vs 19.3 in +X/+Z from centre). — [Minecraft Wiki: Interaction](https://minecraft.wiki/w/Interaction)
- Inputs that remain invisible to vanilla commands: a 2025 feedback post asks for a `/detectinput`-style command because command blocks "can't read movement directly"; community solutions for drop (Q), swap-hands (F), and hotbar-slot changes are Bukkit plugins or client mods (e.g. ControlCommands, a Fabric client mod exposing /jump, /drop-item, /swap-hands, /select-slot-1), not vanilla features. — [feedback.minecraft.net: Add player input detection to commands](https://feedback.minecraft.net/hc/en-us/community/posts/35962989701517-Add-player-input-detection-to-commands); [Modrinth: ControlCommands](https://modrinth.com/mod/controlcommands)

**No new blocks / entities: the display-entity toolkit [pre-26.x]**
- Display entities (`block_display`, `item_display`, `text_display`) added 1.19.4 (23w06a): summon-only; `transformation` (rotation/scale/translation), interpolation via `start_interpolation`/`interpolation_duration`, `teleport_duration` (1.20.2); block display shows any block state (not fluids); item display shows an item incl. resource-pack `item_model` models and its slot is targetable by `/item` and `/loot`; text display has alignment, `line_width` (default 200), background colour, shadow, see-through, opacity. Limits: no hitbox, collision, or damage; don't block placement or push entities; invisible for one tick after load; count toward the entity total. — [Minecraft Wiki: Display](https://minecraft.wiki/w/Display)
- Marker entity: doesn't move, take damage, or collide; is not sent to the client and not counted in the entity total (hence its use as an invisible data anchor). — [Minecraft Wiki: Display](https://minecraft.wiki/w/Display)
- Smithed's ecosystem formalises the "poor man's block": its conventions include a Tag Specification ("a set of custom tags for interacting with blocks, entities, and items") and a Custom Block library (v0.2.0), plus CMD ID Prefixing for `custom_model_data`. — [Smithed Docs: Conventions](https://docs.smithed.dev/conventions/); [Smithed Docs home](https://docs.smithed.dev/)

**No custom GUI beyond dialogs/books/signs/containers**
- Dialogs are the only map-made modal UI; they disable player controls while open, cannot resolve NBT/score/selector components (MC-297871), and always carry the warning button. — [Minecraft Wiki: Dialog](https://minecraft.wiki/w/Dialog); [Kore docs: Dialogs](https://kore.ayfri.com/docs/dialogs)
- Sign click events: in 26.3 signs ignore `click_event`s unless the sign has `allow_op_features` (new signs must set it explicitly). — [Nodecraft](https://nodecraft.com/blog/game-news-tips/minecraft-java-26-3-wilderness-bound-is-out-what-it-means-for-your-server) (secondary; matches this repo's 26.3 gotcha)

**No custom rendering / sounds / textures from the server alone**
- Post effects are client-side resource-pack files; `/posteffect` only names one, the server "cannot confirm that one will apply". — [Minecraft Wiki: Java Edition 26.3](https://minecraft.wiki/w/Java_Edition_26.3)
- `item_model` pointing at a nonexistent model renders the missing model; models, textures, sounds, fonts, shaders all live in `assets/` of a resource pack. — [Minecraft Wiki: Data component format](https://minecraft.wiki/w/Data_component_format); [Minecraft Wiki: Resource pack](https://minecraft.wiki/w/Resource_pack)

### Inferences
- For the kids' tutorial, the complete list of "keys a data pack can react to" is: WASD/jump/sneak/sprint (input predicate or `is_sneaking` flag), jump count (`minecraft.custom:minecraft.jump`), drop (`minecraft.custom:minecraft.drop` or `minecraft.dropped:<item>`), item use (`minecraft.used:<item>`, e.g. carrot on a stick / warped fungus on a stick), hotbar slot (`SelectedItemSlot` NBT) and offhand swap (compare `Inventory`/`equipment` NBT between ticks). Mouse clicks are visible only when they hit an entity (interaction entity, `player_interacted_with_entity`) or a block (`item_used_on_block`, `placed_block`, `using_item` advancement triggers). Chat typing, Esc, Tab completion, and GUI navigation remain undetectable, consistent with the tutorial design of passing quests 1–2 "on trust".
- Interaction-entity asymmetric reach limits mean a large "poor man's button" hitbox should be centred so clicks stay within ~3 blocks on the negative axes.

### Gaps
- No single authoritative wiki page enumerates the full set of entity `flags` values after 1.21.11; the Predicate page only says "new values" were added. Confirm against the jar (`minecraft:flags` in `EntitySubPredicates`) for `is_sneaking`/`is_sprinting`/`is_swimming`/`is_baby`/`is_on_fire`.
- I found no official statement of how often player input is synced to the server (it is sent in the player-input packet each tick, but the wiki does not say so).
- r/MinecraftCommands wiki pages were not reachable (Reddit blocks fetches); its FAQ on input detection could not be cited.

## Key question 3: Resource packs in 26.x (what they add, distribution, known issues)

### Takeaway
Resource packs supply everything client-side: textures, block/item models, the 1.21.4 item model definition system (`assets/<ns>/items/`, driven by `item_model` and `custom_model_data`), sounds, fonts, languages, equipment models, particles, waypoint styles, post effects, and GLSL core/post shaders (still modifiable in 26.x). Distribution is per-client, server-pushed (`server.properties`), or world-embedded (now the world's `resourcepacks/` folder since 26.1); Realms cannot force a pack.

### Cited Findings
- Contents of `assets/<namespace>/`: `atlases`, `blockstates`, `equipment`, `font`, `items`, `lang`, `models`, `particles`, `post_effect`, `shaders` (`core` .fsh/.vsh, `include` .glsl, `post`), `sounds`, `texts`, `textures`, `waypoint_style`; root `sounds.json`, `gpu_warnlist.json`, `regional_compliancies.json`; `pack.mcmeta` can declare languages, `overlays`, and `filter` (format 9, 22w11a). — [Minecraft Wiki: Resource pack](https://minecraft.wiki/w/Resource_pack)
- Item model definitions (1.21.4, 24w45a) at `assets/<ns>/items/`: types `model`, `composite`, `condition`, `select`, `range_dispatch`, `empty`, `bundle/selected_item`, `special`; boolean properties include `broken`, `carried`, `damaged`, `has_component`, `component`, `keybind_down`, `selected`, `using_item`, `view_entity`, `custom_model_data` flags; select properties include `block_state`, `component`, `context_dimension`, `context_entity_type`, `display_context`, `local_time`, `main_hand`, `trim_material`, `custom_model_data` strings; range properties include `bundle/fullness`, `compass`, `cooldown`, `count`, `damage`, `time`, `use_cycle`, `use_duration`, `custom_model_data` floats; tint sources `constant`, `dye`, `firework`, `grass`, `potion`, `team`, `custom_model_data` colors (`map_color` removed 26.3 snapshot 7). History: 1.21.5 `component` properties; 1.21.6 `player_head`, `oversized_in_gui`; 1.21.9 `copper_golem_statue`, `on_shelf` context; 1.21.11 `swap_animation_scale`; 26.1 `transformation` field, `bell`/`book`/`end_cube` special types; 26.2 removed `bed`, `standing_sign`, `hanging_sign` special types (beds and signs became block models). — [Minecraft Wiki: Items model definition](https://minecraft.wiki/w/Items_model_definition); [Minecraft Wiki: Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2)
- Shaders in 26.x: 26.1 rewrote the lightmap algorithm and changed `LightmapInfo` uniforms (`BlockLightTint`, `NightVisionColor` added; `AmbientLightFactor` removed); 26.2 consolidated text shaders into `core/text` and `core/text_background` with defines `IS_GUI`, `IS_SEE_THROUGH`, `IS_GRAYSCALE`. Earlier: global uniforms 25w10a (1.21.5), core shader uniforms became uniform blocks 25w16a (1.21.6). — [Minecraft Wiki: Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1); [Minecraft Wiki: Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2); [Minecraft Wiki: Resource pack](https://minecraft.wiki/w/Resource_pack)
- Core shaders are still overridable by resource packs in 26.x: Modrinth packs list 26.1.x/26.2 compatibility while overriding `particle.fsh`/`particle.vsh`, noting core shaders could not be modified by packs before 1.17 and that Sodium needs a separate core-shader-support mod. — [Modrinth: VNP (community pack page)](https://modrinth.com/resourcepack/vnp) (secondary)
- 26.1 block-model changes: texture entries may be objects with `sprite` and `force_translucent`; any block model can use cutout/translucent textures based on pixel transparency; equipment models load from `assets/<ns>/models/equipment/` since 24w36a. — [Minecraft Wiki: Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1); [Minecraft Wiki: 24w36a](https://minecraft.wiki/w/Java_Edition_24w36a)
- Distribution: local `resourcepacks` folder (lower in the list loads first, higher overrides); server `resource-pack` URL in `server.properties` pointing to an HTTP(S) zip, players may decline unless `require-resource-pack=true` (then they're disconnected); Realms: "no way to force a pack"; world-embedded `resources.zip` loads as the default pack but is not sent to LAN players. — [Minecraft Wiki: Resource pack](https://minecraft.wiki/w/Resource_pack)
- 26.1 moved world resource packs into a `resourcepacks/` subfolder of the save. — [Minecraft Wiki: Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1)
- 26.x known issues noted on the wiki: 26.3 `textures/misc/forcefield.png` gets mipmaps but is excluded from mipmap settings; glow particles made opaque (26.1 snapshot 5); Mojang's "Slicer" tool is pointed to for upgrading bed/sign textures after the 26.2 model change. — [Minecraft Wiki: Resource pack](https://minecraft.wiki/w/Resource_pack); [Minecraft Wiki: Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2)
- Modrinth lists 36,572 resource pack projects vs 15,209 data packs and 77,111 mods (API, 2026-10-12). — [Modrinth API search](https://api.modrinth.com/v2/search?facets=%5B%5B%22project_type%3Aresourcepack%22%5D%5D&limit=1)

### Inferences
- With `/posteffect` (26.3) plus `item_model`, `equippable.asset_id`, custom fonts, and core shaders, a datapack + resource pack pair can now change how the world *looks* for a player from a server command, but only if the client has the pack; a data pack alone can't guarantee any of it.
- The wiki's `resources.zip` entry predates 26.1's `resourcepacks/` folder move; this repo's observation that a world `resources.zip` "did not get applied in 26.3" is consistent with the file location having changed (untested here).

### Gaps
- The Resource pack page gave no definition of the `resources.zip` behaviour post-26.1, and no mention of `resource-pack-sha1`/`resource-pack-prompt`; those `server.properties` keys were not verified in a 26.x source.
- No Mojang statement on core shaders' long-term status in 26.x was found (only community packs demonstrating they still load).

## Key question 5: Distribution and reach (how packs ship; Modrinth, Planet Minecraft, Vanilla Tweaks, GM4, Smithed)

### Takeaway
Packs ship as zips dropped into a world's `datapacks/` folder (singleplayer or the server's `world/datapacks`), activated with `/reload` or `/datapack`; Realms only via uploading a whole world (and worlds using experimental/dynamic-registry content can't be uploaded). Modrinth hosts ~15,200 data pack projects (2,306 already tagged 26.3; the leaders — VeinMiner 93.7M, Terralith 24.1M — ship dual as datapack + Fabric/Forge mod), while Smithed, Gamemode 4, Bookshelf and Vanilla Tweaks define the shared conventions (Lantern Load versioning, namespacing, Weld merging).

### Cited Findings
- Install paths: world creation screen (More → Data Packs, drag the zip/folder in and enable); existing world → Edit → Open world folder → `datapacks`, then `/reload` (cheats) or F3+T; dedicated server → `datapacks` folder inside the world folder (default `world`), `/reload` from console or a level-3 operator; verify with `/datapack list enabled`. — [Minecraft Wiki: Tutorial: Installing a data pack](https://minecraft.wiki/w/Tutorial:Installing_a_data_pack)
- Load order is stored in `level.dat`, changeable in the Data Packs screen or with `/datapack`; last pack wins for duplicate files; tags merge unless `"replace": true`. Malformed content the game can't ignore triggers an error on world open with a Safe Mode option. — [Minecraft Wiki: Data pack](https://minecraft.wiki/w/Data_pack)
- Realms: worlds with experimental settings "cannot be uploaded to Realms, and the upload fails with a server error"; resource packs cannot be forced on Realms. — [Minecraft Wiki: Data pack](https://minecraft.wiki/w/Data_pack); [Minecraft Wiki: Resource pack](https://minecraft.wiki/w/Resource_pack)
- Modrinth (API, 2026-10-12): 15,209 data pack projects total; by supported version: 26.3 = 2,306, 26.2 = 3,928, 26.1 = 4,076, 1.21.11 = 5,670, 1.21.1 = 6,263, 1.20.1 = 4,998. ## Key question 6: Mojang's trajectory (data-driven direction, official Java add-ons?)

### Takeaway
Mojang's observable policy is incremental: each 26.x drop moves more hard-coded behaviour into data (villager trades 26.1; tool block-transformation, fuels, compost, sign text 26.3; biome spawns into environment attributes 26.3) and adds map-maker commands (`/compute`, `/posteffect`), while its one structural announcement for Java modding is the October 2025 removal of code obfuscation to make mods "easier to create, update, and debug". No source shows an official Java "add-on" system or marketplace being planned; add-ons remain a Bedrock concept.

### Cited Findings
- Mojang announcement (reported 2025-10-29): "For a long time, Java Edition has used obfuscation (hiding parts of the code)… Now we're changing how we ship Minecraft: Java Edition to remove obfuscation completely", starting with the first snapshot after the Mounts of Mayhem launch, to "pave a future for Java Edition where it's easier to create, update, and debug mods." ### Inferences
- The "data-driven" direction is demonstrated by the changelogs rather than declared in a roadmap: every 26.x drop converted at least one previously hard-coded system (trades, time, tool actions, fuels) into registry/component data, and 26.3's wholesale renaming of loot/predicate keys suggests Mojang is willing to break pack compatibility to regularise the formats.
- Deobfuscation benefits Java *mods*, not data packs; combined with the absence of any Java add-on announcement, the realistic 2026 picture is "data packs for behaviour within vanilla's rules, Fabric/NeoForge mods for everything else", with Mojang lowering the cost of the latter rather than merging the two.
