# Self-hosting Minecraft Java 26.3 Fabric servers on a general-purpose VPS (October 2026)

Scope: 2–4 concurrent Fabric 26.3 server instances, 10–20 total players, custom server-side Fabric mods + datapacks, vanilla clients, US-based kids' program. Prices are USD list prices checked 2026-10-18 unless stated; where only aggregator or EUR figures were available this is flagged.

## Q1. Current prices and specs for 4 / 8 / 16 GB plans at each provider; bandwidth; hourly billing; stopped-VPS billing

At list price (2026-10-18) the US-region 8 GB tier clusters at $40–48/month for shared-CPU plans (Vultr Regular $40, Lightsail $44, DigitalOcean $48, Linode $48, Vultr High Frequency/Performance $48), with OVHcloud US VPS-2 (4 vCore / 8 GB) the outlier at $8.50/month (12-month upfront pricing implied). ## Q2. Sizing: RAM/CPU per Fabric 26.3 instance for ~10 players; Java 25; GC flags; instances per 8 GB vs 16 GB; single-thread CPU

### Takeaway
Minecraft 26.3 (released 2026-09-15) requires Java 25 (Mojang's own version manifest says `majorVersion: 25`), and Fabric Loader 0.19.5 is the stable loader for it. The vanilla wiki's guidance is 2 GB RAM for 5–10 players and 4 GB for 10+, with single-core speed the deciding CPU factor (the server uses about three cores at most); on that basis an 8 GB VPS fits two instances comfortably or three tight ones, and 16 GB fits three to four with headroom.

### Cited Findings
- Mojang's `version_manifest_v2` lists 26.3 as the latest release (released 2026-09-15T11:23:02Z) with `javaVersion: {component: java-runtime-epsilon, majorVersion: 25}`; the current snapshot line is 26.4-snapshot-4 — [piston-meta version manifest](https://piston-meta.mojang.com/mc/game/version_manifest_v2.json) (queried 2026-10-18)
- Java Edition 26.3: release date 15 September 2026, minimum Java SE 25, data pack format 121.0, next version in development 26.4 — [Minecraft Wiki: Java Edition 26.3](https://minecraft.wiki/w/Java_Edition_26.3)
- Fabric meta lists 26.3 as stable (and 26.4-snapshot-1..4 unstable); loader 0.19.5 is the stable loader, 0.20.0 exists as unstable; Fabric API 0.163.0+26.3 was published 2026-10-14 — [meta.fabricmc.net game versions](https://meta.fabricmc.net/v2/versions/game); [meta.fabricmc.net loader versions](https://meta.fabricmc.net/v2/versions/loader); [Modrinth Fabric API](https://api.modrinth.com/v2/project/fabric-api/version) (queried 2026-10-18)
- Fabric 26.3 server guide (checked 2026-09-18): Java 25 required, Loader 0.19.5 recommended, installer 1.1.2, example start script `-Xms1G -Xmx4G` ("example settings, not a requirement"), 26.3 "enables the whitelist by default", keep `online-mode=true`, `white-list=true` — [TroubleChute Fabric 26.3 server](https://hub.tcno.co/games/minecraft/26.3/server/fabric/)
- Vanilla server hardware table (server only, OS extra): 1–4 players 1 GB; 5–10 players 2 GB; 10+ players 4 GB with an i5-4690 / Ryzen 5 1600 class CPU and SSD. "Single-core performance matters most. The server uses up to about three cores." Hyperthreading barely helps; large worlds with redstone/mob farms "can easily more than double the requirements" — [Minecraft Wiki: Server/Requirements](https://minecraft.wiki/w/Server/Requirements)
- Aikar's flags (G1GC): `-Xms10G -Xmx10G -XX:+UseG1GC -XX:+ParallelRefProcEnabled -XX:MaxGCPauseMillis=200 -XX:+UnlockExperimentalVMOptions -XX:+DisableExplicitGC -XX:+AlwaysPreTouch -XX:G1NewSizePercent=30 -XX:G1MaxNewSizePercent=40 -XX:G1HeapRegionSize=8M -XX:G1ReservePercent=20 -XX:G1HeapWastePercent=5 -XX:G1MixedGCCountTarget=4 -XX:InitiatingHeapOccupancyPercent=15 -XX:G1MixedGCLiveThresholdPercent=90 -XX:G1RSetUpdatingPauseTimePercent=5 -XX:SurvivorRatio=32 -XX:+PerfDisableSharedMem -XX:MaxTenuringThreshold=1 -Dusing.aikars.flags=https://mcflags.emc.gs -Daikars.new.flags=true`; PaperMC recommends "at least 6-10GB" heap regardless of player count, leaving 1,000–1,500 MB for OS/overhead (e.g. `-Xms6500M -Xmx6500M` on an 8 GB host), and warns 32 GB "will only waste your money" — [PaperMC Aikar's flags](https://docs.papermc.io/paper/aikars-flags/); [aikar.co original](https://aikar.co/?p=375)
- 12 GB+ variant: G1NewSizePercent=40, G1MaxNewSizePercent=50, G1HeapRegionSize=16M, G1ReservePercent=15, InitiatingHeapOccupancyPercent=20 — [BerryByte Aikar's flags](https://old-docs.berrybyte.net/games/minecraft/aikars-flags); set `-Xms` = `-Xmx` to avoid heap resizing lag — [supercraft Aikar's flags](https://supercraft.host/wiki/minecraft/aikars_flags/)
- Hosting-vendor rules of thumb (commercial sources, inconsistent): ~50–80 MB per player on Paper, 100–300 MB per player on modded Forge/Fabric; a Fabric host recommends 4 GB minimum (6 GB recommended) per ~8 players; at view distance 10 a player loads up to 441 chunks, at 16 up to 1,089, so lowering view distance cuts RAM; "a CPU with 8 slow cores is worse than one with 4 fast cores" — [gbnodes RAM calculator](https://gbnodes.host/blogs/how-much-ram-minecraft-server-2026-calculator/); [mado-hosting Fabric](https://www.mado-hosting.com/minecraft-modpacks/fabricfps); [ligahosting guide](https://ligahosting.com/news/minecraft-server-hosting-guide); [dathost benchmarks](https://dathost.com/blog/minecraft-server-performance-benchmarks-2026)
- A 26.3 Paper Docker test with `itzg/minecraft-server:java25` and `VERSION: "26.3"` reported "server ready about 28 seconds after startup" (2026-10-04) — [supercraft docker setup](https://supercraft.host/wiki/minecraft/docker_server_setup/)
- An older Java fails immediately: a 26.x jar on Java 21 dies with an unsupported class file version error — [gameserverkings updating guide](https://www.gameserverkings.com/knowledge-base/minecraft/updating-your-server-version/)

### Inferences
- A heap of 2–3 GB per instance (e.g. `-Xms2G -Xmx2G` to `-Xmx3G`) is a defensible starting point for ~5–10 players on a small custom-datapack world with light server-side mods, per the wiki table; the PaperMC "6–10 GB minimum" guidance targets large public survival servers and is not needed for mini-game worlds the size of the ones in this repo (void worlds, 12×12 islands).
- Budget per instance ≈ heap + ~0.5–1 GB JVM/OS overhead. 8 GB box: 2 instances at 3 GB heap or 3 instances at 2 GB heap, plus Velocity (~512 MB), leaves ~0.5–1 GB for the OS — tight but workable for 10–20 total players; 16 GB box: 3–4 instances at 3 GB heap with comfortable headroom. This is my sizing from the cited figures, not a benchmarked result.
- CPU: with ~3 usable threads per instance and the main tick thread single-threaded, 4 vCPU shared plans are the floor for 3 instances; prefer the "high frequency / premium CPU" tiers (Vultr HF, DO Premium, Linode G6/G7 dedicated) if lag appears, because clock speed per core is what shortens the 50 ms tick.
- Aikar's flags are tuned for G1 and heaps ≥ 6 GB; on a 2–3 GB heap the defaults are reasonable and the main win is `-Xms`=`-Xmx` plus `-XX:+UseG1GC`; I found no 2026 source recommending ZGC for small Minecraft heaps.

### Gaps
- No benchmark specific to Fabric 26.3 with light server-side mods on a 2–4 vCPU shared VPS; all RAM-per-player numbers are hosting-vendor rules of thumb.
- No primary source on ZGC vs G1 for Minecraft on Java 25 (searched Aikar's flags; the PaperMC page does not cover ZGC).
- The minecraft.wiki requirements page has not been updated for the Java 25 line (it stops at 1.20.5 → Java 21); the Java 25 requirement comes from Mojang's manifest and the 26.3 wiki page.

## Q3. Running several servers on one box: panels, ports, Velocity proxy, Docker

### Takeaway
Velocity 4.3.0 (Java 25 minimum) supports clients 1.7.2 through 26.3 and the Velocity team "strongly recommends" Fabric + FabricProxy-Lite (v2.12.0 supports 26.1–26.3) as the backend, so one public address with `/server` hops between game instances is fully supported for vanilla clients. For management, itzg/minecraft-server 2026.10.0 (`latest` = Java 25, `TYPE=FABRIC`, `VERSION=26.3`) with docker compose is the lightest option; Pelican (v1.0.0-rc.1, 2026-10-10, Java 25 yolk available) or Pterodactyl (v1.15.1, 2026-08-14, Java 25 yolk) give a web console; Crafty Controller 4.11.0 (2026-09-16) is the simpler non-Docker panel.

### Cited Findings
- Velocity requires at least Java 25; backends must run `online-mode=false` and you must then configure forwarding and follow the security guide — [Velocity getting started](https://docs.papermc.io/velocity/getting-started/)
- PaperMC's fill API lists Velocity 4.3.0 (build 44) as the current SUPPORTED version with Java minimum 25 — [fill.papermc.io velocity versions](https://fill.papermc.io/v3/projects/velocity/versions) (queried 2026-10-18)
- "As of the page's writing, Velocity supports Minecraft 1.7.2 through 26.3." Fabric "works out of the box"; add FabricProxy-Lite for modern forwarding and CrossStitch "if you run mods that add content" (custom argument types); plain vanilla backends work but lack player-info forwarding, so "the Velocity team strongly recommends that you use Fabric with the FabricProxy-Lite mod" — [Velocity server compatibility](https://docs.papermc.io/velocity/server-compatibility/)
- Modern forwarding: `player-info-forwarding-mode = "modern"` in velocity.toml, matching `forwarding.secret` on each backend; for Fabric use FabricProxy-Lite (CrossStitch optional); no actively supported Fabric mod does legacy forwarding; modern forwarding needs 1.13+ — [Velocity player information forwarding](https://docs.papermc.io/velocity/player-information-forwarding/)
- FabricProxy-Lite v2.12.0 (published 2026-03-28) lists game versions 26.1, 26.1.1, 26.1.2, 26.2, 26.3; CrossStitch's latest release is 0.1.7 for 1.21.8 (2025-08-09) with no 26.x build — [Modrinth FabricProxy-Lite versions](https://api.modrinth.com/v2/project/fabricproxy-lite/version); [Modrinth CrossStitch versions](https://api.modrinth.com/v2/project/crossstitch/version) (queried 2026-10-18)
- FabricProxy-Lite setup: drop in mods, start once to generate `config/FabricProxy-Lite.toml`, paste Velocity's secret; `hackEarlySend` is needed with some mods (LuckPerms) — [FabricProxy-Lite GitHub](https://github.com/OKTW-Network/FabricProxy-Lite); [CurseForge page](https://www.curseforge.com/minecraft/mc-mods/fabricproxy-lite)
- itzg/minecraft-server: `TYPE=FABRIC`, `EULA=TRUE`, `VERSION` (defaults to latest vanilla), `FABRIC_LOADER_VERSION`/`FABRIC_LAUNCHER_VERSION` to pin, `MODRINTH_PROJECTS=fabric-api,...` to auto-download mods — [itzg docs: Fabric](https://docker-minecraft-server.readthedocs.io/en/latest/types-and-platforms/server-types/fabric/); image tags `latest`, `stable`, `java25`, `java25-alpine`, `java25-jdk`, `java25-graalvm` are all Java 25, and `latest` tracks the newest Java Mojang requires — [itzg docs: Java versions](https://docker-minecraft-server.readthedocs.io/en/latest/versions/java/); latest image release 2026.10.0 (2026-10-10) — [GitHub releases](https://github.com/itzg/docker-minecraft-server/releases)

### Inferences
- Layout for one box: Velocity on 0.0.0.0:25565 (the only public game port); backends on 127.0.0.1:25566/25567/25568 with `online-mode=false` + FabricProxy-Lite modern forwarding and the shared secret; backends never exposed. With itzg compose, publish only the Velocity port and keep backends on the compose network (no `ports:` on them).
- CrossStitch has no 26.x build, so if a custom Fabric mod registers custom command argument types, test command tab-completion through the proxy; datapack-only content (the packs in this repo) does not need it.
- Pelican is at release-candidate stage (rc.1 on 2026-10-10) and ships a Java 25 yolk; Pterodactyl 1.15.1 is stable and also has Java 25. Both add PHP + MariaDB + Redis + Docker to maintain; for 3 servers run by one adult, a compose file with three itzg containers plus a Velocity container (image `itzg/mc-proxy`, not verified here) or three systemd units is less to operate.
- `online-mode=false` on backends is safe only because the firewall/compose network prevents direct connections; this is the single most important configuration check for a kids' server (see Q5).

### Gaps
- No primary-source confirmation that `itzg/minecraft-server` has been tested with `TYPE=FABRIC` + `VERSION=26.3` specifically (the docs are version-agnostic; the one tested 26.3 example was Paper). Fabric meta serves 26.3, so the auto-installer path should work.
- Pterodactyl's docs page (pterodactyl.io/project/introduction.html) returned 404; no statement on Pterodactyl's maintenance pace was obtained.
- Crafty's own docs on per-server Java selection were not found (only third-party images).
- Velocity's own Java/memory sizing guidance (how much RAM the proxy needs) was not found in the fetched pages.

## Q4. Operations: setup checklist, firewall, restarts, backups, updates, monitoring, time cost

### Takeaway
Setup is: Ubuntu/Debian VPS → Temurin/OpenJDK 25 → Fabric server launcher (loader 0.19.5) per instance → accept `eula.txt` → `server.properties` (`online-mode=true` on a standalone server or `false` only behind Velocity, `white-list=true`, `enforce-whitelist=true`, `enable-rcon=false`) → systemd units or Docker restart policies → nightly tar of each world folder pulled to the local machine (rsync/scp) plus optional provider backups at 20–30% of the plan (DigitalOcean/Hetzner) or $0.05–0.06/GB snapshots. Each 26.x release (26.3 was 2026-09-15; 26.4 is in snapshots) means re-checking Fabric Loader/API, FabricProxy-Lite, Velocity, and the custom mods before updating.

### Cited Findings
- First run stops and asks you to accept the EULA by editing `eula.txt` from false to true; stop the server before editing `server.properties`; keep `server-ip` empty and `server-port=25565`; console commands `whitelist on`, `whitelist add <name>`, `whitelist list` — [TroubleChute Fabric 26.3 server](https://hub.tcno.co/games/minecraft/26.3/server/fabric/)
- Recommended baseline: `online-mode=true`, `white-list=true`, `enforce-whitelist=true`, `enable-rcon=false`; if RCON is needed, long random password, bind to localhost/VPN, firewall-allowlist — [Terabit hardening checklist](https://terabit.io/kb/secure-minecraft-server-access-baseline)
- Provider backup/snapshot costs: DigitalOcean backups 20% (weekly) / 30% (daily) of Droplet price or usage-based from $0.01/GiB-month, snapshots $0.06/GB-month — [DigitalOcean pricing](https://www.digitalocean.com/pricing/droplets); Hetzner backups 20% of server price, 7 slots — [Hetzner billing FAQ](https://docs.hetzner.com/cloud/billing/faq/); Lightsail snapshots $0.05/GB-month — [Lightsail pricing](https://aws.amazon.com/lightsail/pricing/); OVHcloud US includes a free daily system-disk backup (7 kept) — [OVHcloud US VPS](https://us.ovhcloud.com/vps/)
- Hetzner bills stopped servers; advises snapshot + delete for long pauses — [Hetzner billing FAQ](https://docs.hetzner.com/cloud/billing/faq/); DigitalOcean same (destroy to stop billing, snapshot loses the IP) — [DO community](https://www.digitalocean.com/community/questions/billing-of-droplets-when-they-are-off); Lightsail same, static IPs billed when unattached > 1 h — [AWS re:Post](https://repost.aws/questions/QUXTceGm-iTe6ewBHIN6NrBQ/why-am-i-being-charged-for-a-stopped-amazon-lightsail-instance)
- itzg image: `FABRIC_FORCE_REINSTALL=true` repairs a corrupted launcher jar; pin `FABRIC_LOADER_VERSION` to control upgrades; `--pull=always` fetches new image releases — [itzg docs: Fabric](https://docker-minecraft-server.readthedocs.io/en/latest/types-and-platforms/server-types/fabric/)
- Game version cadence: Mojang's manifest shows 26.3 released 2026-09-15 and 26.4 at snapshot 4 (queried 2026-10-18); Fabric already lists 26.4-snapshot-1..4 — [piston-meta](https://piston-meta.mojang.com/mc/game/version_manifest_v2.json); [Fabric meta](https://meta.fabricmc.net/v2/versions/game)
- Paper 26.3 and NeoForge 26.3 were "still in beta" and Geyser supported 26.2 not 26.3 as of a late-September 2026 guide — [space-node 26.3 update guide](https://space-node.net/blog/minecraft-26-3-server-update-guide-2026) (secondary, hosting vendor)
- Aikar's flags include GC logging for Java 11+ (`-Xlog:gc*:logs/gc.log:time,uptime:filecount=5,filesize=1M`) which "doesn't hurt performance and can stay on" — [PaperMC Aikar's flags](https://docs.papermc.io/paper/aikars-flags/)

### Inferences
- Firewall: allow 22/tcp (ideally from the operator's IP only) and 25565/tcp (Velocity) inbound; nothing else. Backends bound to 127.0.0.1 or a Docker network need no rule. If Pelican/Pterodactyl is used, its panel (80/443) and Wings (8080, 2022) become additional exposed services to patch.
- Automatic restarts: systemd `Restart=on-failure` + a nightly `systemctl restart` timer, or Docker `restart: unless-stopped`; itzg supports in-container auto-pause/stop when empty (not verified in this research, but documented in the project).
- Backups: a cron/systemd timer that runs `save-off; save-all` via console (or stops the container), tars `world/` per instance (each of this repo's void worlds is tens of MB), and the operator's machine pulls them with `rsync` over SSH — fits the existing scp-based playtest workflow. Provider snapshots add ~20–30% to the bill on DO/Hetzner and are best used as a weekly whole-box safety net, not the primary world backup.
- Updates: with ~monthly 26.x releases, expect a compatibility check of (loader, Fabric API, FabricProxy-Lite, Velocity, custom mods) each time; clients auto-update to the newest release, so a backend pinned to the old version locks out kids until updated unless Velocity's protocol support plus a backend ViaVersion-style layer is added (not researched).
- Time cost (estimate, not sourced): initial build 3–6 hours for one adult comfortable with Linux; steady state ~1–2 hours/month (monthly game update, OS patches, backup check), more in months when a 26.x release breaks a mod.

### Gaps
- No sourced figure for operator time per month; the estimate above is mine.
- Did not find primary docs for itzg's auto-pause (`ENABLE_AUTOPAUSE`) or `itzg/mc-proxy` Velocity image behaviour for 4.3.0; both exist in the project but were not fetched.
- No source on how Velocity handles clients newer than the backend (e.g. 26.4 clients on a 26.3 backend); needs a ViaVersion/ViaFabric check.

## Q5. Security and safety for child players

### Takeaway
The non-negotiables are Mojang authentication (`online-mode=true` on anything reachable from the internet, or Velocity in online mode with modern forwarding and backends firewalled off), the whitelist (on by default in 26.3; add `enforce-whitelist=true`), RCON disabled or localhost-only, op rights limited to adults, and keeping the server logs (chat is in `logs/latest.log`) for moderation.

### Cited Findings
- Online mode verifies each joining account with Mojang so nobody can join as someone else; turning it off lets any client connect under any username; offline-mode whitelist mods only check nicknames; whitelist and online mode do different jobs and both should be on for an internet-facing server — [mineguard whitelist vs online mode](https://mineguard.pro/en/blog/whitelist-vs-online-mode-minecraft); [Modrinth Offline Whitelist listing](https://modrinth.com/project/ERjdp2FE)
- Baseline: `online-mode=true`, `white-list=true`, `enforce-whitelist=true`, `enable-rcon=false` — [Terabit checklist](https://terabit.io/kb/secure-minecraft-server-access-baseline)
- RCON is unencrypted, equals op level 4 (op, ban, stop, whitelist), has no login rate limit; connect only from localhost or VPN — [gameserverkings RCON](https://www.gameserverkings.com/knowledge-base/minecraft/setting-up-rcon/); [ipfyi port 25575](https://ipfyi.com/port/25575/)
- 26.3 enables the whitelist by default on a new server — [TroubleChute Fabric 26.3](https://hub.tcno.co/games/minecraft/26.3/server/fabric/); also reported by [space-node](https://space-node.net/blog/minecraft-26-3-server-update-guide-2026)
- Behind Velocity, backends must run `online-mode=false`; Velocity calls this "insecure" until forwarding and the security guide are applied, and legacy forwarding is "fundamentally insecure" without ensuring only the proxy can reach the backends — [Velocity getting started](https://docs.papermc.io/velocity/getting-started/); [Velocity forwarding](https://docs.papermc.io/velocity/player-information-forwarding/)
- Paper/Spigot security settings guidance (enable/disable lists) exists for plugin servers; not Fabric-specific — [mineguard Paper security](https://mineguard.pro/en/blog/paper-spigot-security-settings)

### Inferences
- With Velocity in `online-mode = true` and modern forwarding, Mojang auth happens at the proxy and the backend receives the verified UUID, so the whitelist on each backend keeps working with real usernames; the risk is purely that a backend port becomes reachable directly, which the firewall/compose-network rule prevents. Whitelisting at the Velocity level too (Velocity has no built-in whitelist; a plugin is needed) was not researched.
- Chat moderation: vanilla server logs record chat with timestamps in `logs/`; keep them off the box (part of the nightly backup) and disable nothing that reduces logging. Minecraft's built-in player reporting and chat signing remain on with online mode; no Fabric-specific moderation mod was evaluated.
- No public-facing panel (Pelican/Pterodactyl web UI) or RCON should be exposed; if a panel is wanted, put it behind the operator's IP allowlist or a VPN.

### Gaps
- No source specifically on child-safety practices for self-hosted Minecraft servers (COPPA-style record keeping, parental consent for whitelisting); the searches returned only generic hardening pages.
- Velocity-level whitelist plugins and chat-logging/moderation mods for Fabric 26.3 were not researched.

## Q6. Total monthly cost for the realistic setup (one 8 GB VPS, 3 Fabric instances behind Velocity) per provider; DigitalOcean vs Hetzner tradeoffs

### Takeaway
At list prices on 2026-10-18 the realistic single-box setup costs about $40–48/month on US shared-CPU plans (Vultr Regular $40, Lightsail $44, DigitalOcean/Linode/Vultr HF $48), roughly $8.50/month on OVHcloud US VPS-2 with a 12-month commitment, $63–86/month on dedicated-vCPU tiers, and an unconfirmed but post-increase-higher figure at Hetzner's US sites; add ~20–30% for provider backups. DigitalOcean's advantages over Hetzner are US pricing in USD, docs/support, and instant signup; Hetzner's historical price edge in the US has largely evaporated after the April and June 2026 increases, though it still bundles 20 TB of traffic.
