# slicedlime's "Command Training Grounds" map — how it works internally (read from the datapack)

Scope note: everything below comes from read-only inspection of the pristine world zip `/home/dave/Downloads/CommandTrainingGrounds.zip`, extracted to `/tmp/ctg-inspect/` (world → `world/`, nested `datapacks/ctg.zip` → `ctg/`, `resources.zip` → `res/`). Paths in citations are relative to the inside of `ctg.zip` unless prefixed `res/` (resource pack) or `world/` (world save). No web research was done; the YouTube URLs quoted are the ones embedded in the pack. The map's `level.dat` declares version `1.19.3` and the enabled datapack list `vanilla`, `file/ctg` (disabled: `bundle`, `update_1_20`) — [world/level.dat](world/level.dat).

## 1. Directory layout of ctg.zip (namespaces, counts, tags, predicates, structures)

### Takeaway
A single `ctg` namespace with 452 `.mcfunction` files (8,777 lines, of which 4,400 are camera-path teleports), 3 predicates, 31 structure NBTs, a custom `the_void` biome, and `load`/`tick` function tags. There are no advancements, loot tables, or item modifiers — all detection is done in tick functions.

### Cited Findings

### Inferences
- No advancements/loot tables/predicate-heavy detection: the author chose a "poll every tick from a function" architecture, which is simpler to teach from but means every check in the map costs server time every tick.
- The `_ip` structure variants are the "in-progress" copies loaded at 1% integrity during the island fade-in (see §5).

### Gaps
- Structure NBT contents were not parsed (binary); island sizes are inferred from the 32×32×32 `fill` boxes in `restart_map`.

## 2. What the load and tick functions do; scoreboard objectives and criteria; how progress is stored

### Takeaway
Progress is a tiny global state machine — fake players `Lesson`, `Exercise`, `Tick` on a dummy objective `_ctg_main` — mirrored into a backup objective, into an area-effect-cloud's NBT, and into an end-gateway block's NBT in a force-loaded chunk at (1024, 1024). Every tick: run self-repair, then advance `Tick`, then dispatch to `ctg:lessonN/exerciseM` via a 123-line lookup table.

### Cited Findings
- `loop` (tick): `function ctg:safety/check`; then `execute unless score ErrorMode _ctg_main matches 0.. run function ctg:tick` and `... run function ctg:dispatch`; then `function ctg:safety/clear` — [data/ctg/functions/loop.mcfunction](data/ctg/functions/loop.mcfunction)
- `tick`: increments `Tick _ctg_main` and copies it to `Tick _ctg_backup` **unless** a player named `slicedlime` is holding a lava bucket (`unless entity @p[name=slicedlime,nbt={SelectedItem:{id:"minecraft:lava_bucket"}}]`) — the author's pause switch; runs completion particles for `@e[type=marker,tag=_ctg_complete_effect]`; checks for a specific player head at `1032 0 1024` (`SkullOwner:{Id:[I;...]}`) and calls `ctg:check_version_done`, **which does not exist in the pack** — [data/ctg/functions/tick.mcfunction](data/ctg/functions/tick.mcfunction); `find ctg -name 'check_version*'` returned nothing
- `dispatch`: 123 lines of `execute if score Lesson _ctg_main matches N if score Exercise _ctg_main matches M run function ctg:lessonN/exerciseM`; `Exercise 0` → `ctg:lessonN/intro`; `Lesson 0` → `ctg:intro/intro`; `Lesson 12` → `ctg:next_episode/intro` — [data/ctg/functions/dispatch.mcfunction](data/ctg/functions/dispatch.mcfunction)
- Objectives present in the shipped `scoreboard.dat`: `_ctg_main` ("CTG Main Storage", dummy), `_ctg_backup` ("CTG Backup Storage", dummy), `_ctg_scratch` ("CTG Scratch Space", dummy); fake players `Lesson`, `Exercise`, `Tick` scored in both main and backup; one team `all`; player entry `slicedlime` — [world/data/scoreboard.dat](world/data/scoreboard.dat) (via `zcat | strings`)
- Objectives created by functions: `_ctg_main dummy`, `_ctg_backup dummy`, `_ctg_scratch dummy`, `_ctg_intro dummy` (per-player camera frame counter), `_ctg_stick_used minecraft.used:minecraft.debug_stick` (lesson 5 only, removed again in `lesson5/exercise10`), and lesson-facing dummies `fun`, `poopy`, `Test`, `Bird`, `Winner`, `OnGround`, `Entities` — grep of `scoreboard objectives add` over [data/ctg/functions/](data/ctg/functions/); [data/ctg/functions/lesson5/exercise8.mcfunction](data/ctg/functions/lesson5/exercise8.mcfunction)
- `_ctg_main` fake players besides Lesson/Exercise/Tick: `ErrorMode`, `WaitingForLoad`, `ExpectedCookies`, `GoldBlock`, `L3E6Test`, `L7E10Check`, `L7E10Score`, `DisplayCooldown` — grep over [data/ctg/functions/](data/ctg/functions/)
- `_ctg_scratch` is **deleted and re-created every tick** (`scoreboard objectives remove _ctg_scratch` / `add`) at the top of `safety/check` and wiped with `scoreboard players reset * _ctg_scratch` in `safety/clear`; per-tick temporaries live there (`Completed`, `CommandExecuted`, `Stone`, `Blocks`, `Swords`, `Activated`, `Random`, `Count`, constants `2`, `10`, `40`, etc.) — [data/ctg/functions/safety/check.mcfunction](data/ctg/functions/safety/check.mcfunction), [data/ctg/functions/safety/clear.mcfunction](data/ctg/functions/safety/clear.mcfunction)
- `store` writes Lesson/Exercise from scratch into `_ctg_main`, `_ctg_backup`, into `@e[type=area_effect_cloud,tag=_ctg_backup]` as `DurationOnUse` (Lesson) and `WaitTime` (Exercise), and into block `1024 0 1024` (an `end_gateway`) as `ExitPortal.X` / `ExitPortal.Z`; `Tick` is copied only if `Tick _ctg_scratch matches -1..` — [data/ctg/functions/store.mcfunction](data/ctg/functions/store.mcfunction)
- `safety/check`: `forceload add 1024 1024` if not loaded; detects chunk-loaded via `unless block 1024 -1 1024 lime_stained_glass_pane`; increments `ErrorMode` if not loaded (which disables tick+dispatch); `store success` on `scoreboard objectives add _ctg_main/_ctg_backup` to detect that the player deleted them; prints `text/objective_error` — [data/ctg/functions/safety/check.mcfunction](data/ctg/functions/safety/check.mcfunction)
- `safety/check_loaded`: restores the backup AEC (`restore_entity`: tries `data merge` tags back onto an AEC at 1024 -1 1024, else re-summons with `Duration: 2047483647`), teleports it back to 1024 -1 1024, kills duplicates recursively (`kill_duplicate_entities`), restores the `end_gateway` block (`restore_block`), then runs `set_lesson` — [data/ctg/functions/safety/check_loaded.mcfunction](data/ctg/functions/safety/check_loaded.mcfunction), [data/ctg/functions/safety/restore_entity.mcfunction](data/ctg/functions/safety/restore_entity.mcfunction), [data/ctg/functions/safety/restore_block.mcfunction](data/ctg/functions/safety/restore_block.mcfunction)
- `safety/set_lesson`: reads Lesson/Exercise from four sources (main, backup, entity NBT, block NBT) and keeps "whichever is lowest but positive" using `scoreboard players operation ... <` after seeding with 2147483647 — [data/ctg/functions/safety/set_lesson.mcfunction](data/ctg/functions/safety/set_lesson.mcfunction)
- `safety/wait_load` (comment: "after a load-in it's impossible to know if it's loaded properly so we resort to this horror of hackery"): places a command block `{Command:"function ctg:safety/end_wait_load"}` at 1024 -63 1024, an oak pressure plate above it, and summons an armor stand onto the plate; when the entity actually ticks it triggers the plate and `end_wait_load` clears `WaitingForLoad` — [data/ctg/functions/safety/wait_load.mcfunction](data/ctg/functions/safety/wait_load.mcfunction), [data/ctg/functions/safety/end_wait_load.mcfunction](data/ctg/functions/safety/end_wait_load.mcfunction)
- `load.json` also runs `ctg:restart_exercise`, whose entire body is `scoreboard players set Tick _ctg_main 0` — so every `/reload` or world load replays the current exercise's intro text and `Tick 1` setup — [data/ctg/functions/restart_exercise.mcfunction](data/ctg/functions/restart_exercise.mcfunction)
- Per-player text-component data storage: `data modify storage ctg:lXeY LastExecution set from block ...` (37 `storage ctg:` uses), `storage ctg:l8e10 entity/test`, `storage ctg:l10e4 score`, `storage ctg:l9e3 Command` — grep over [data/ctg/functions/](data/ctg/functions/)

### Inferences
- Because the state is three global fake-player scores (not per-player scores or advancements), **all players share one position in the course**; the map is designed for one player (or a group working together), not for a classroom where each student progresses independently. `gamemode ... @a`, `clear @a`, `tag @a add _ctg_lXeY_check` and `@p`-based checks throughout confirm this.
- The quadruple-redundant storage (two objectives, an entity, a block) exists purely to survive learners who are *being taught* `scoreboard objectives remove`, `kill @e`, and `fill ... air` — exactly the commands the lessons teach. This is the map's most teacher-relevant engineering idea: assume students will break your infrastructure with the thing you just taught them.
- The force-loaded chunk at x=1024,z=1024 (y −63…319) is a hidden "sandbox": invisible to the player on the islands near 0,0, always loaded, used both as backup storage and as the test bench for re-running the student's commands (§4).

### Gaps
- `ctg:check_version_done` is referenced but missing; whether this was a stripped feature or an oversight can't be determined from the files.

## 4. How the map verifies that the player did the exercise correctly (techniques)

### Takeaway
The dominant technique is **sandboxed re-execution**: the student's command-block text is copied (`data modify block … Command set from block …`, 34 occurrences) into fresh command blocks inside a force-loaded, out-of-sight chunk at x=1024,z=1024 with controlled surroundings, fired with `auto 1`, and the *outcome* is inspected — often in both a positive and a negative scenario so hard-coded coordinates or unconditional commands fail. Around this sit simpler probes: inventory counts via `clear … 0`, block-state checks, `execute if blocks … all` against a reference the map builds for itself, gamerule/time queries, predicates, scoreboard reads, and tick-to-tick edge detection.

### Inferences
- Checking *outcomes in a controlled replica* rather than parsing the command string is the key design decision: it accepts any correct phrasing (`~ ~3 ~`, `^ ^3 ^`, `execute positioned …`) while rejecting commands that merely work by coincidence at the original spot. Only the three `kill @p/@a/@r` exercises use literal string matching.
- Because checks run from the pack's own functions (not the student's command block), the map can test commands that would be dangerous to run on the real island (e.g. `kill @a` is never actually executed by the map).

### Gaps

## 5. How exercises are presented to the player (text, titles, signs, cinematics)

## 7. Progress storage and multiplayer

### Takeaway
Progress is world-level, not per-player: three fake-player scores (`Lesson`, `Exercise`, `Tick`) plus their mirrors. Multiple players can be in the world (all checks use `@a`/`@p`), but they advance as one group, and several checks assume a single player.

### Cited Findings
- State variables are fake players on `_ctg_main` (`Lesson`, `Exercise`, `Tick`), mirrored to `_ctg_backup`, to AEC NBT (`DurationOnUse`, `WaitTime`), and to block NBT (`ExitPortal.X/Z`) — [data/ctg/functions/store.mcfunction](data/ctg/functions/store.mcfunction)
- The only per-player scores are `_ctg_intro` (camera frame), `_ctg_stick_used`, exercise-specific per-entity scratch flags, and the lesson-facing objectives students create — grep over [data/ctg/functions/](data/ctg/functions/)
- Group semantics: `gamemode adventure @a[...]`, `clear @a …` sums across all players (so two players each holding 32 red wool would satisfy "a stack"), `title @a`, `tellraw @a`, `tag @a add _ctg_l4e1_check` — [data/ctg/functions/lesson1/exercise2.mcfunction](data/ctg/functions/lesson1/exercise2.mcfunction), [lesson4/exercise1](data/ctg/functions/lesson4/exercise1.mcfunction)
- Single-player assumptions: `if score @p fun matches 4711`, `clear @p emerald 0`, `tp @s -4 98 -115` of whichever player stepped on the copper, `if entity @a[gamemode=adventure]` (any one player) — [data/ctg/functions/lesson10/exercise2.mcfunction](data/ctg/functions/lesson10/exercise2.mcfunction), [lesson11/exercise12](data/ctg/functions/lesson11/exercise12.mcfunction), [lesson3/exercise3](data/ctg/functions/lesson3/exercise3.mcfunction)
- A team `all` with `seeFriendlyInvisibles false` is created so the invisible camera armor stand stays invisible to everyone — [data/ctg/functions/transition.mcfunction](data/ctg/functions/transition.mcfunction)
- Spawnpoint is set per player at the end of each flight (`execute as @a[tag=_ctg_transition_done] at @s run spawnpoint @s ~ ~ ~`) — [data/ctg/functions/transition.mcfunction](data/ctg/functions/transition.mcfunction)

### Inferences
- For a classroom, each student would need their own copy of the world (the design intent: "This map along with its companion video series is meant to teach you"); a shared server would make the group advance together and let one student complete exercises for everyone.

### Gaps
- No evidence in the files of a multiplayer mode or per-player progress toggle.
