# Core concepts of the modern Minecraft Java Edition command system (1.13 → 26.2, data pack format 107.1)

Scope: Java Edition only. Baseline for "what changed" is 1.19.3 (data pack format 10, the Command Training Grounds era); target is 26.2 (data pack format 107.1, released 2026-06-16). Version numbers in parentheses after a change are the release and, where the wiki gives it, the snapshot that introduced it. Where a claim was verified against the local 26.2 client jar or the working `one-block_2` pack on this machine, that is stated explicitly.

---

## Key question 0 — Brigadier syntax, autocomplete, coordinates, and the overall parsing model

### Takeaway
Since 1.13, commands are parsed by the Brigadier tree parser: the server parses first (completeness, argument validity), then executes; the client parses too, to give tab completion and red error highlighting. Positions come in three notations (absolute, `~` relative to execution position, `^` local to execution rotation), and `~` and `^` cannot be mixed within one position.

### Cited Findings
- Command parsing has two stages: the server parses a command to check it is complete and its arguments are valid, then executes it; the client also parses commands to provide autocompletion and catch typing mistakes. — [Commands (Minecraft Wiki)](https://minecraft.wiki/w/Commands)
- Autocomplete: when the cursor is at an argument such as an entity ID, a list of matching values appears above the text box and narrows as you type; Tab cycles through commands or arguments and can auto-enter them. If the client can't parse an argument it is marked in red and a syntax error appears above the chat bar; execution errors for unparseable commands end with `<--[HERE]`. — [Commands](https://minecraft.wiki/w/Commands)
- Syntax notation used by the wiki: literals are plain text, arguments are `<name>`, `(a|b)` is a required choice, `[entry]` is optional, `-> command` means further arguments follow (redirect). — [Commands](https://minecraft.wiki/w/Commands)
- Permission levels run 0–4: `/help`, `/list` need 0; `/time`, `/gamemode` need 2; `/op`, `/ban` need 3; `/stop`, `/save-all` need 4. In Java, "cheats" only affect a player's permission level. — [Commands](https://minecraft.wiki/w/Commands)
- Every command yields a success count (0 or 1 in Java, except `/execute`) and a result value; `/execute ... store` saves `success` and `result`. Outcome classes are Unparseable, Failed, Successful, Void, Terminated, Error. — [Commands](https://minecraft.wiki/w/Commands)
- Execution sources in Java: chat, command block / command-block minecart, server console (no `/`), data pack functions, clicking a `run_command` text component, clicking a dialog action button. — [Commands](https://minecraft.wiki/w/Commands)
- Argument types (the names shown in the F3+… "Command Syntax" report and used by Brigadier): `brigadier:bool`, `brigadier:double`, `brigadier:float`, `brigadier:integer`, `brigadier:string` (single word, quotable phrase, or greedy phrase); `minecraft:block_pos` (3 ints with `~`/`^`), `minecraft:vec3` (doubles, `~` and `^`), `minecraft:vec2`, `minecraft:column_pos`, `minecraft:rotation` (yaw pitch), `minecraft:angle` (yaw only), `minecraft:entity` (name, selector, or UUID), `minecraft:game_profile`, `minecraft:score_holder` (selector, name, UUID, or `*`), `minecraft:objective`, `minecraft:objective_criteria`, `minecraft:operation`, `minecraft:scoreboard_slot`, `minecraft:int_range`/`float_range` (`n`, `n..`, `..n`, `a..b`), `minecraft:item_stack` (item + components), `minecraft:item_predicate`, `minecraft:block_state`, `minecraft:block_predicate`, `minecraft:component` (text component), `minecraft:style`, `minecraft:nbt_compound_tag`, `minecraft:nbt_tag`, `minecraft:nbt_path`, `minecraft:resource_location`, `minecraft:resource`, `minecraft:resource_key`, `minecraft:resource_or_tag`, `minecraft:resource_or_tag_key`, `minecraft:resource_selector` (wildcards `*`, `?`), `minecraft:function` (id or `#tag`), `minecraft:loot_table`, `minecraft:loot_predicate`, `minecraft:loot_modifier`, `minecraft:item_slot`, `minecraft:item_slots` (`*` wildcard), `minecraft:slot_source`, `minecraft:dimension`, `minecraft:entity_anchor` (`eyes`|`feet`), `minecraft:heightmap`, `minecraft:gamemode`, `minecraft:swizzle` (non-repeating `x`/`y`/`z`), `minecraft:team`, `minecraft:team_color`, `minecraft:time` (`d`, `s`, `t` default), `minecraft:uuid`, `minecraft:message` (greedy, selectors expanded), `minecraft:dialog`, `minecraft:hex_color`, `minecraft:swing_animation`, `minecraft:template_mirror`, `minecraft:template_rotation`. `brigadier:long` exists in Brigadier but is unused by Minecraft. — [Argument types](https://minecraft.wiki/w/Argument_types)
- Absolute coordinates are `X Y Z` from the world origin; X increases east, Z increases south. — [Coordinates](https://minecraft.wiki/w/Coordinates)
- `~` is an offset from the command's execution position; lone `~` means offset 0; `~` and absolute values can be mixed (`/tp ~ 64 ~`); `/execute` can change what `~ ~ ~` refers to. — [Coordinates](https://minecraft.wiki/w/Coordinates)
- `^` local coordinates are `^left ^up ^forward` relative to the executor's facing (+X local = left, +Y local = up, +Z local = the direction faced); `^ ^ ^5` moves 5 blocks forward. Caret and world notation cannot be mixed (`^ 0 ^` is rejected with "Cannot mix world & local coordinates (everything must either use ^ or not)"). Workaround: `execute rotated ~ 0 run tp ^ ^ ^3` keeps Y in world space. — [Coordinates](https://minecraft.wiki/w/Coordinates)
- Execution position, rotation, dimension, and anchor all affect what `^ ^ ^` resolves to, and `/execute` can change each of them. — [Coordinates](https://minecraft.wiki/w/Coordinates)
- A block's position is the integer coordinate of its lower-north-west corner (round down); an entity's coordinates are at the bottom centre of its collision box. — [Coordinates](https://minecraft.wiki/w/Coordinates)
- Facing/yaw values: South 0°, West +90°, North ±180°, East −90°. Pitch (`x_rotation`): −90 straight up, 0 horizon, +90 straight down. — [Coordinates](https://minecraft.wiki/w/Coordinates); [Target selectors](https://minecraft.wiki/w/Target_selectors)

### Inferences
- For teaching: `~` answers "where am I being run from?", `^` answers "which way am I facing?". Because both depend on execution context, the `/execute` lesson should precede or accompany the coordinates lesson.
- The "Cannot mix world & local coordinates" error is the single most common beginner error with `^`; the `rotated ~ 0` trick is the standard idiom.

### Gaps
- The wiki Coordinates page does not document the 0.5 block-centring rule for integer positions in `/tp`/`/summon` (integers in a `vec3` are centred to .5 unless a decimal point is given). This is well known but was not confirmed from a fetched source.
- The wiki Commands page did not state the Brigadier introduction version in the portion read; it is the 1.13 "Update Aquatic" command rewrite (17w45a per the execute/selector histories below), but the library name/date was not confirmed from a primary page.

## Key question 1 — How do target selectors work in full?

### Takeaway
Six selector variables (`@p`, `@r`, `@a`, `@e`, `@s`, and since 1.21 `@n`) are filtered by case-sensitive `[argument=value,...]` pairs that are AND-ed; ranges use `..`, negation uses `!`, and only some arguments may repeat. `@n` is sugar for `@e[sort=nearest,limit=1]`.

### Cited Findings
- Variables: `@p` nearest player (ties → most recently joined; default sort nearest, limit 1); `@r` random player (sort random, limit 1); `@a` all players, alive or dead (sort arbitrary, no limit); `@e` all entities in loaded chunks plus online players (sort arbitrary, no limit); `@s` the executing entity (selects nothing from a command block or console); `@n` nearest entity. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- `@n` was added in 24w21a (1.21) and is equivalent to `@e[sort=nearest,limit=1]`, accepting extra filters such as `@n[type=pig]`. 1.21-pre1 stopped it selecting dying entities. — [Java Edition 24w21a](https://minecraft.wiki/w/Java_Edition_24w21a); [Target selectors](https://minecraft.wiki/w/Target_selectors)
- Syntax: `@<variable>[<argument>=<value>,...]`; argument names and values are case-sensitive; multiple arguments are AND-ed; spaces are allowed inside the brackets but not between the variable and `[`. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- `x`, `y`, `z`: doubles, not centre-corrected (`x=0` is not `x=0.5`); alone they only change the origin used for sorting/distance; they also limit the search to the current dimension. Not repeatable. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- `distance`: Euclidean distance from origin measured at the entity's feet; float range, unsigned; current dimension only. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- `dx`, `dy`, `dz`: signed offsets forming a box from (x,y,z) to (x+dx, y+dy, z+dz); the far corner gains +1 on each axis so each dimension is at least one block; entities match if their hitbox intersects the box; omitted deltas default to 0 when another is given. `@e[x=1,y=2,z=3,dx=0,dy=0,dz=0]` selects entities intersecting block 1 2 3. Distance checks the feet point against a sphere, volume checks the full hitbox; combining both selects the overlap. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- `scores={obj=range,...}`: integer ranges, several objectives comma-separated. Not repeatable. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- `tag`: `tag=name`, `tag=!name`, `tag=` (no tags), `tag=!` (at least one tag). Repeatable; all must match. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- `team`: `team=name`, `team=` (no team), `team=!` (any team). Equality cannot repeat; inequality can. Since 25w05a (1.21.5) it can select non-living entities. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- `name`: quote names with spaces; `name=!` excludes; equality cannot repeat, inequality can. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- `type`: entity ID or `#entity_type_tag`; `minecraft:` optional; not allowed with `@a`, `@p`, `@r`; `type=X` once, `type=!X` repeatable only if no positive `type` is present. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- `predicate`: predicate resource location; `predicate=!` excludes; repeatable. Added 19w38a (1.15). — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- `x_rotation` (pitch −90..90) and `y_rotation` (yaw: 0 south, −90 east, 90 west, ±180 north): float ranges, not repeatable. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- `nbt`: SNBT compound; `nbt=!` excludes; repeatable; computationally expensive. Added 17w45b. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- `level`: player XP level, integer range. `gamemode`: `spectator|survival|creative|adventure`, `gamemode=!` excludes; equality once, inequality repeatable; numeric/shorthand IDs removed in 1.13. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- `advancements={id=true/false}` or `{id={criterion=true}}`; players only; not repeatable. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- `limit=N` caps results; `sort=nearest|furthest|random|arbitrary`. Both added in 1.13 (17w45a). — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- Range syntax: `10..` (≥10), `..10` (≤10), `8..16` (inclusive), `10` (exactly). Integer ranges for `scores`, `level`; float ranges for `distance`, `x_rotation`, `y_rotation`. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- 1.13 (17w45a) renamed the old shorthand arguments: `m`→`gamemode`, `l`/`lm`→`level`, `r`/`rm`→`distance`, `rx`/`rxm`→`x_rotation`, `ry`/`rym`→`y_rotation`, `c`→`limit`; arguments can be quoted; negative `limit` for furthest removed. — [Target selectors](https://minecraft.wiki/w/Target_selectors)
- 26.2 fixed MC-307125: selectors with duplicate `team` arguments were parsed differently depending on order. — [Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2)

### Inferences
- Teaching model: a selector is a *filter pipeline* — variable picks the candidate pool and default sort/limit, arguments narrow it, `sort` orders it, `limit` truncates. `@n` and `@p` are just `@e`/`@a` with `sort=nearest,limit=1` baked in.
- `@r` is player-only in Java (type not allowed); "random mob" must be `@e[type=zombie,sort=random,limit=1]`.
- Negation of `scores` is listed under Bedrock only; in Java, use an inverted range or a predicate instead.

### Gaps
- The wiki page did not state `@n`'s default sort/limit in its variable table, only via the 24w21a equivalence to `@e[sort=nearest,limit=1]`.

## Key question 2 — What does each /execute subcommand change, and how to teach "as vs at"?

### Takeaway
Every command runs inside an execution context of five fields — executor (`@s`), position, rotation, dimension, anchor — and each `/execute` subcommand overwrites one or more of them before `run`. `as` changes *who* (`@s`) without moving; `at` changes *where* (position + rotation + dimension) without changing `@s`; the idiom `as X at @s` does both. Selectors matching several entities fork the chain into independent branches.

### Cited Findings
- Context fields and what changes them: **Executor** — `as`, `on`, `summon`; **Position** — `at`, `positioned` (all forms), `align`, `in`, `summon`; **Rotation** — `at`, `rotated`, `facing`; **Dimension** — `at`, `in`; **Anchor** — `anchored` (and `positioned <pos>` resets it to feet). `at` sets position, rotation, and dimension but not the executor. — [Commands/execute](https://minecraft.wiki/w/Commands/execute)
- Modifiers: `as <targets>` sets executor (forks); `at <targets>` copies position/rotation/dimension (forks); `positioned <pos>` sets position and resets anchor to feet; `positioned as <targets>` copies position (forks); `positioned over <heightmap>` (`world_surface`, `motion_blocking`, `motion_blocking_no_leaves`, `ocean_floor`) moves to one block above the heightmap; `rotated <yaw pitch>` (tilde allowed); `rotated as <targets>` (forks); `facing <pos>` and `facing entity <targets> eyes|feet` (forks) set rotation measured from the anchor; `align <swizzle>` floors position on the given axes; `anchored eyes|feet` sets the anchor used by `^` and `facing`; `in <dimension>` sets dimension and rescales X/Z between Overworld and Nether; `on <relation>` sets the executor to a related entity — `attacker`, `controller`, `leasher`, `origin`, `owner`, `passengers`, `target`, `vehicle` — only `passengers` can fork; `summon <entity>` spawns an entity at the execution position and makes it the executor (whole command terminates for `minecraft:player` or `minecraft:fishing_bobber`). — [Commands/execute](https://minecraft.wiki/w/Commands/execute)
- `on attacker` = last entity to damage the executor within the previous 5 seconds; `on origin` = shooter of a projectile, thrower of an item, source of an area effect cloud, igniter of primed TNT, summoner of evoker fangs/vex. — [Java Edition 1.19.4](https://minecraft.wiki/w/Java_Edition_1.19.4)
- Conditions (`if`/`unless`): `biome <pos> <biome>`, `block <pos> <block|#tag>`, `blocks <start> <end> <dest> all|masked` (source ≤ 32768 blocks), `data block|entity|storage <…> <path>`, `dimension <dim>`, `entity <sel>`, `function <fn|#tag>` (runs it and tests the return value; cannot be last), `items block <pos>|entity <sel> <slots> <item_predicate>`, `loaded <pos>`, `predicate <id>`, `score <t> <obj> (<|<=|=|>=|>) <s> <obj>` or `score <t> <obj> matches <range>`, `stopwatch <id> <range>` (25w41a / 1.21.11). A failed test mid-chain terminates that branch; at the end of the chain it sets `success`/`result`. — [Commands/execute](https://minecraft.wiki/w/Commands/execute)
- `store result|success` targets: `block <pos> <path> <type> <scale>`, `bossbar <id> value|max`, `entity <sel> <path> <type> <scale>` (cannot modify player NBT), `score <targets> <objective>`, `storage <id> <path> <type> <scale>` (creates the storage). Types `byte|short|int|long|float|double`; values are rounded down to integers before scaling. Values are stored after the chain completes. — [Commands/execute](https://minecraft.wiki/w/Commands/execute)
- `run <command>` may appear once, only at the end; only `run` or a condition may end a chain. — [Commands/execute](https://minecraft.wiki/w/Commands/execute)
- Forking: `as`, `at`, `positioned as`, `rotated as`, `facing entity`, and `on passengers` fork when several entities match; Java processes subcommands breadth-first, one subcommand at a time, so a `run` cannot affect later subcommands in the same chain; each branch has its own `success`/`result`, and if several branches store to the same place the last one wins; total success count is the sum of branches. Depth-first ordering is obtained by moving the inner `execute` into a function. — [Commands/execute](https://minecraft.wiki/w/Commands/execute)
- Forking described for teaching: "some subcommands split execution into several branches, and each following subcommand runs once per branch" (example: `execute as @e[type=marker]` runs the function once per marker). — [datapack.wiki: execute](https://datapack.wiki/wiki/command/execute)
- Functions inherit the caller's context (executor, position, rotation, dimension, anchor); an `execute` inside a function only changes context for the commands after it in that `execute`. — [Function (Java Edition)](https://minecraft.wiki/w/Function_(Java_Edition))
- History: reworked 17w45a (1.13); `store` 17w45b; `if data` 18w43a (1.14); `if predicate` and `store storage` 19w38a (1.15); `if biome` 22w46a (1.19.3); `on`, `if dimension`, `if loaded` 23w03a (1.19.4), `on origin` 23w04a, `summon` 23w06a, `positioned over` 1.19.4-pre1; `if function` 23w31a (1.20.2, removed in pre1, reinstated 23w41a / 1.20.3); `if items` 24w10a (1.20.5); `if stopwatch` 25w41a (1.21.11); 26.2-pre1: `on owner` counts vexes as owned by their evoker; 26.3-snap1 (beyond scope): `if items` takes a slot source and a `slots` condition is added. — [Commands/execute](https://minecraft.wiki/w/Commands/execute)
- Legacy page name for the 1.12 form: `Commands/executeasother` is the wiki's redirect for the pre-1.13 syntax, which no longer exists. — [search result](https://minecraft.wiki/w/Commands/executeasother)

### Inferences
- The standard teaching model (consistent with the wiki's field table): the context is a "clipboard" of five values; `as` edits the *who* slot, `at` edits the *where/which-way/which-world* slots, and nothing is applied until `run`. The classic bug is `execute as @e[type=zombie] run setblock ~ ~ ~ stone` placing every block at the player: `as` moved `@s` but not the position, so `at @s` is needed.
- Breadth-first forking means a `store` at the end of a forked chain is overwritten by the last branch — a common surprise when counting; counting needs `execute store result score … if entity @e[...]` (which doesn't fork) instead.

### Gaps
- The r/MinecraftCommands wiki itself could not be fetched; the "as changes WHO, at changes WHERE" phrasing is from general guides surfaced by search, not from an official page.

## Key question 3 — How do scoreboards, criteria, operations, display slots, and /trigger work?

### Takeaway
Scoreboards are the command system's integer variables: objectives have a criterion (either `dummy`/`trigger` for command-only use, read-only player stats like `health`, or any statistic in `minecraft.<type>:minecraft.<name>` form), scores are 32-bit signed ints held per score holder (entities or `#fake` names), arithmetic is done with `scoreboard players operation`, and `trigger` lets a non-op set their own score once per enablement.

### Cited Findings
- Single criteria: `dummy` (commands only — variables/arithmetic), `trigger` (players set their own via `/trigger` once enabled), `deathCount`, `playerKillCount`, `totalKillCount` (all writable); `health` (half-hearts), `xp`, `level`, `food`, `air` (0–300), `armor` (0–20) are read-only. — [Scoreboard](https://minecraft.wiki/w/Scoreboard)
- Compound criteria use periods as delimiters, e.g. `minecraft.killed_by:minecraft.zombie`; `teamkill.<color>` and `killedByTeam.<color>` have 16 colour variants; any statistic can be used by its identifier, and compound-criteria objectives are writable. — [Scoreboard](https://minecraft.wiki/w/Scoreboard)
- Statistic identifiers are `namespace.type:namespace.name`, e.g. `minecraft.mined:minecraft.stone`; types are `custom`, `mined`, `broken`, `crafted`, `used`, `picked_up`, `dropped`, `killed`, `killed_by`; custom names include `jump`, `sneak_time`, `walk_one_cm`, `play_time`, `deaths`, `damage_dealt`, `damage_taken`, `time_since_rest`, `time_since_death`, `mob_kills`, `player_kills`. — [Statistics](https://minecraft.wiki/w/Statistics)
- `minecraft.custom:minecraft.jump` is used as the criterion in the working `jump-game` pack on this machine (CLAUDE.md), confirming the format in 26.2. — local: `/home/dave/minecraft/CLAUDE.md`
- Scores are 32-bit signed integers, −2,147,483,648 to 2,147,483,647. — [Scoreboard](https://minecraft.wiki/w/Scoreboard)
- `scoreboard players operation <target> <obj> <op> <source> <obj>` operators: `+=`, `-=`, `*=`, `/=` (floor division), `%=` (floorMod since 18w31a), `=` assign, `<` take minimum, `>` take maximum, `><` swap. — [Scoreboard](https://minecraft.wiki/w/Scoreboard)
- Display slots: `list` (tab list, number or hearts via `rendertype`), `sidebar` (up to 15 entries), `sidebar.team.<color>` (16 colours), `below_name` (hidden beyond ~10 blocks and while sneaking; not visible in singleplayer). `belowName` was renamed `below_name` in 23w31a (1.20.2), with old numeric slot IDs converted. — [Scoreboard](https://minecraft.wiki/w/Scoreboard); [Java Edition 1.20.2](https://minecraft.wiki/w/Java_Edition_1.20.2)
- Number formats (23w46a / 1.20.3): `scoreboard objectives modify <obj> displayautoupdate true|false` and `numberformat blank|fixed <text component>|styled <style>`; per-player `display` and `type`. — [Scoreboard](https://minecraft.wiki/w/Scoreboard); [Java Edition 1.20.3](https://minecraft.wiki/w/Java_Edition_1.20.3)
- `/trigger`: trigger objectives are disabled for players by default; enable with `scoreboard players enable <player> <obj>` (14w06a); `/trigger` works for non-operators even with cheats off; the objective disables itself for that player after one use. — [Scoreboard](https://minecraft.wiki/w/Scoreboard)
- Fake players: score holders whose names start with `#` do not appear in the sidebar (14w07a). 16-character name limits were removed in 21w37a (1.18). — [Scoreboard](https://minecraft.wiki/w/Scoreboard)
- The `operation` argument type accepts exactly `=`, `+=`, `-=`, `*=`, `/=`, `%=`, `><`, `<`, `>`; `score_holder` accepts a selector, name, UUID, or `*` (all tracked holders). — [Argument types](https://minecraft.wiki/w/Argument_types)
- 26.2 (snap5): a player's score no longer appears in the tab overlay if the player lacks the objective. — [Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2)
- `deathCount` keeps its camelCase name in 26.2 (used by `one-block_2`'s `ob_deaths` objective). — local: `/home/dave/minecraft/CLAUDE.md`

### Inferences
- For teaching arithmetic: there are no literals in `operation`, so constants live on fake players (`#c20`, `#c2` as in `one-block_2`'s HUD maths) set once in `load`.
- `trigger` is the canonical "menu/button for non-ops" mechanism; the pattern is: `scoreboard players enable @a menu` each tick (or on join), detect `scores={menu=1..}` in tick, act, reset to 0.

### Gaps
- The Scoreboard page did not list the full set of statistic categories as criteria; that came from the Statistics page, which does not itself discuss scoreboards. The wiki spells the walking stat both `walk_one_cm` and `walked_one_cm`; verify in-game (the 26.2 jar can be grepped).

## Key question 4 — Item NBT vs item components (1.20.5+), custom_data, can_break/can_place_on, and the 26.x flattening claim

### Takeaway
1.20.5 replaced the free-form item `tag` NBT with typed, validated data components written as `item[component=value,!removed]`; arbitrary data now lives only in `custom_data`. The `can_break`/`can_place_on` `predicates:[...]` wrapper and the `enchantments={levels:{...}}` wrapper were removed in **1.21.5** (not 26.x), and `show_in_tooltip` flags were replaced by the `tooltip_display` component at the same time.

### Cited Findings
- 1.20.5 (data pack format 41): item NBT in the `tag` field was replaced by structured components; `/give @s stick{foo:'bar'}` becomes `/give @s stick[custom_data={foo:'bar'}]`; components go in `[...]` after the item name with `=` and commas, e.g. `wooden_pickaxe[damage=23]`, `netherite_hoe[damage=5,repair_cost=2]`; invalid values fail to parse (`damage=-34` is rejected); affected commands `/give`, `/item`, `/loot`, `/clear`. — [Java Edition 1.20.5](https://minecraft.wiki/w/Java_Edition_1.20.5)
- Component removal uses a `!` prefix (`!minecraft:damage`); unspecified components keep the item type's defaults; brackets may be omitted when no components are given. — [Java Edition 1.20.5](https://minecraft.wiki/w/Java_Edition_1.20.5); [Data component format](https://minecraft.wiki/w/Data_component_format)
- Item stack storage format: `id`+`Count` → `id`+`count` (default 1, omitted when default); `tag` removed, leftovers go to `minecraft:custom_data`; new `components` field; empty stacks omitted rather than stored as air. — [Java Edition 1.20.5](https://minecraft.wiki/w/Java_Edition_1.20.5)
- 1.20.5 item predicates (used by `/clear`, `execute if items`, `/item`): `<type>[tests]` where type is an item ID, `#tag`, or `*`; `component=value` exact match, `component` existence, `predicate~value` sub-predicate; `count=`/`count~`; `!` negates; `|` alternatives; examples `*[damage~{durability:{min:3}}]`, `*[count~{max:2}]`, `*[!damage|damage=0]`. Old partial NBT matching `stick{a:2}` becomes `stick[custom_data~{a:2}]`. — [Java Edition 1.20.5](https://minecraft.wiki/w/Java_Edition_1.20.5)

## Key question 5 — JSON/SNBT text components in 1.21.5+ and /tellraw, /title

### Takeaway
Since 1.21.5 text components are NBT, written as SNBT in commands (unquoted keys, single or double quotes) rather than JSON strings; `clickEvent`/`hoverEvent` became `click_event`/`hover_event`, each action's payload key was renamed (`run_command` → `command`, `open_url` → `url`, `show_text` → `value`, `show_item`/`show_entity` inlined), and `run_command` no longer needs a leading `/`.

### Cited Findings
- Component forms: a plain string (shorthand for `{text:...}`), a list (first element is the parent; the rest become its `extra`), or a compound. Optional `type` (`text|translatable|score|selector|keybind|nbt`, added 23w40a / 1.20.3) speeds parsing; otherwise the type is inferred by checking `text`, `translate`, `score`, `selector`, `keybind`, `nbt` in that order. — [Text component format](https://minecraft.wiki/w/Text_component_format)
- Content tags: `text`; `translate` (+`fallback`, `with`); `score` (`name` selector/name/`*`, `objective`); `selector` (+`separator`); `keybind`; `nbt` (+ one of `block`/`entity`/`storage`, `nbt` path, `interpret`, `plain`, `separator`); `object` (sprites; 1.21.9 / 25w32a). — [Text component format](https://minecraft.wiki/w/Text_component_format)
- Formatting: `extra`, `color` (`#RRGGBB` or named), `font`, `bold`, `italic`, `underlined`, `strikethrough`, `obfuscated`, `shadow_color` (24w44a / 1.21.4; ARGB int or 4 floats), `insertion`. — [Text component format](https://minecraft.wiki/w/Text_component_format)
- `click_event` actions and fields: `open_url` → `url`; `open_file` → `path` (client-only); `run_command` → `command`; `suggest_command` → `command`; `change_page` → `page` (positive int); `copy_to_clipboard` → `value`; `show_dialog` → `dialog` (1.21.6); `custom` → `id`, `payload` (1.21.6). — [Text component format](https://minecraft.wiki/w/Text_component_format)
- `hover_event` actions: `show_text` → `value`; `show_item` → `id`, `count`, `components`; `show_entity` → `id` (entity type), `uuid`, `name`. — [Text component format](https://minecraft.wiki/w/Text_component_format)
- 1.21.5 (25w02a) rename list: `clickEvent`→`click_event`, `hoverEvent`→`hover_event`; `open_url` `value`→`url` (must be valid http/https); `run_command`/`suggest_command` `value`→`command`, and the leading `/` is no longer required; `change_page` `value`→`page`; `show_text` `contents`→`value` (final name settled in 25w03a); `show_item` and `show_entity` contents inlined, `show_entity` `type`→`id` and `id`→`uuid`; components are no longer stored as JSON inside strings but inlined (`custom_name={text:'Renamed item'}`), including in `tellraw`. Booleans in translation arguments must use the string form because NBT can't distinguish booleans from ints. — [Java Edition 1.21.5](https://minecraft.wiki/w/Java_Edition_1.21.5); [Text component format](https://minecraft.wiki/w/Text_component_format)
- The wiki says the `run_command` command "does not need to be prefixed" with `/`; it does not state whether a slash is stripped or rejected. — [Text component format](https://minecraft.wiki/w/Text_component_format)
- `/title <targets> (title|subtitle|actionbar) <component>`; `times <fadeIn> <stay> <fadeOut>` with `d`/`s`/`t` units (time argument since 22w03a / 1.19.4); the component switched from JSON to SNBT in 25w02a (1.21.5). — [Commands/title](https://minecraft.wiki/w/Commands/title)
- 1.20.3 (23w40a) tightened text components: numbers/booleans are no longer auto-converted to strings in `text`; some formerly ignored errors became hard errors; `show_entity` `uuid` accepts an int array. — [Text component format](https://minecraft.wiki/w/Text_component_format)
- 1.19.4: `translate` components accept an optional `fallback`; out-of-bound arguments are no longer silently ignored. — [Java Edition 1.19.4](https://minecraft.wiki/w/Java_Edition_1.19.4)
- 1.21.5: `/bossbar`, `/scoreboard`, and `/team` resolve text component arguments in the context of `@s`. — [Java Edition 1.21.5](https://minecraft.wiki/w/Java_Edition_1.21.5)
- 1.21.6: players must confirm before running `run_command` actions from books or chat if the command can't be parsed or needs permission above 0. — [Java Edition 1.21.6](https://minecraft.wiki/w/Java_Edition_1.21.6)
- Working 26.2 example on this machine (JSON-style quoting is still valid SNBT): `tellraw @s [{"text":"  [Play again]","color":"green","bold":true,"click_event":{"action":"run_command","command":"function oneblock:___play"}}]` in `one-block_2/.../internal/game_over.mcfunction`; the project notes record that `click_event`/`run_command` without a leading slash were verified in the client jar. — local: `/home/dave/minecraft/one-block_2`, `/home/dave/minecraft/CLAUDE.md`
- The 26.2 client jar contains both `click_event`/`hover_event` and the legacy `clickEvent`/`hoverEvent` strings (the latter presumably in data-fixer upgrade code). — local jar `strings` check

### Inferences
- Because JSON is (almost) a subset of SNBT, 2023-era `tellraw` JSON still parses in 26.2 *except* for the renamed keys: `clickEvent`/`hoverEvent`/`value`/`contents` are the breaking points. Teach students to write SNBT-style (`{text:"hi",color:gold}`) to signal the new model.

### Gaps
- Whether a leading `/` in `run_command` is tolerated or an error in 26.2 was not confirmed from the wiki; the local pack omits it and works.

## Key question 6 — NBT/SNBT, /data, and storage

### Takeaway
SNBT is the typed text form of NBT (13 tag types, numeric suffixes, typed arrays, optional quoting); `/data get|merge|modify|remove` operates on `block`, `entity`, or `storage` targets, and command storage (`storage <namespace:id>`, since 1.15) is the general-purpose key-value store that feeds macros and text `nbt` components.

### Cited Findings
- NBT tag types (IDs 0–12): End, Byte, Short, Int, Long, Float, Double, Byte Array, String, List, Compound, Int Array, Long Array. — [NBT format](https://minecraft.wiki/w/NBT_format)
- Suffixes (case-insensitive): `b` byte, `s` short, `i`/none int, `l` long, `f` float, `d` or bare decimal double; `u`/`s` signedness prefixes before the type suffix (`240ub` = `-16sb`, 1.21.5). Arrays `[B;…]`, `[I;…]`, `[L;…]` differ from plain lists `[1,2,3]`. — [NBT format](https://minecraft.wiki/w/NBT_format)
- Strings: quotes optional for `[A-Za-z0-9_.+-]` text not starting with a digit/`-`/`.`/`+`; single or double quotes (single quotes since 1.14); escapes `\n`, `\s`, `\\`, `\'`, `\"`, `\xhh`, `\uhhhh`, `\Uhhhhhhhh`, `\N{name}`. `true`/`false` are bytes `1b`/`0b` — NBT has no boolean type. — [NBT format](https://minecraft.wiki/w/NBT_format)
- 1.21.5 SNBT additions: heterogeneous lists (stored by wrapping non-compound entries in `{'':value}`; empty keys no longer valid in paths), `bool()` and `uuid()` functions, `.1`/`1.`/`1.2e3`/`0x`/`0b`/underscore number literals, trailing commas. — [NBT format](https://minecraft.wiki/w/NBT_format); [Java Edition 1.21.5](https://minecraft.wiki/w/Java_Edition_1.21.5)
- SNBT vs JSON: JSON has six types, NBT has several numeric types and no null/boolean; SNBT keys can be unquoted; NBT arrays are homogeneous. — [NBT format](https://minecraft.wiki/w/NBT_format)
- `/data` (permission 2): `get block|entity|storage <target> [<path>] [<scale>]` (numbers × scale then floored; lists/strings/compounds return length); `merge <target> <compound>`; `modify <target> <path> (append|insert <i>|merge|prepend|set) (from <source> [<path>]|string <source> [<path>] [<start>] [<end>]|value <snbt>)`; `remove <target> <path>`. Editing player data fails. Storage targets added 19w38a (1.15); `string` source added 1.19.4. — [Commands/data](https://minecraft.wiki/w/Commands/data); [Java Edition 1.19.4](https://minecraft.wiki/w/Java_Edition_1.19.4)
- `execute store … storage <id> <path> <type> <scale>` creates the storage if needed. — [Commands/execute](https://minecraft.wiki/w/Commands/execute)
- 1.21.5: `/data` can create and modify heterogeneous lists; `/setblock`/`/fill` keep existing block-entity data unless `{}` is given; `strict` placement option on `/fill`, `/clone`, `/setblock`, `/place template`. — [Java Edition 1.21.5](https://minecraft.wiki/w/Java_Edition_1.21.5)
- Working 26.2 storage idioms on this machine: `function oneblock:internal/do_save with storage oneblock:main`, list membership test `saves[{name:"..."}]`, and `nbt` text components reading `storage oneblock:main players`. — local: `/home/dave/minecraft/CLAUDE.md`, `one-block_2`

### Inferences
- Teaching order: SNBT literals → `/data get` to inspect entities → `storage` as "variables that aren't integers" → macros `with storage` as the payoff.

### Gaps
- The Commands/data page does not itself document type suffixes or arrays (they are on NBT format); no conflicts found.

**Functions, macros, /return**
- `.mcfunction`: one command per line, no leading `/`; `#` comments only; a trailing `\` continues a line (23w31a / 1.20.2). — [Function (Java Edition)](https://minecraft.wiki/w/Function_(Java_Edition))
- Macros (23w31a / 1.20.2): a line whose first non-space character is `$` is a macro line; each `$(key)` is replaced from the compound passed in; key characters are letters, digits, underscores. Call forms: `function <id> {k:v,...}` or `function <id> with (block <pos>|entity <sel>|storage <id>) [<path>]` — the source must be a compound. Substitution is textual: strings insert without quotes, numbers without suffix (≤15 fraction digits), booleans as `1`/`0`, lists/compounds as canonical SNBT. Non-macro lines are parsed once at load; macro lines are re-parsed per call (results cached per argument set). A missing key or an unparseable substituted line aborts the whole function — none of it runs; extra keys are ignored; passing a compound to a non-macro function is silently ignored. — [Function (Java Edition)](https://minecraft.wiki/w/Function_(Java_Edition)); [Java Edition 1.20.2](https://minecraft.wiki/w/Java_Edition_1.20.2)
- `/return <value>` ends the function with success and a 32-bit int result; `/return fail` ends it with failure and result 0; `/return run <command>` runs the command, ends the function, and propagates the command's success/result (only the first branch of a forking `execute` counts). History: `return` and `return run` added 23w31a (1.20.2), `run` temporarily removed in 1.20.2-pre1 and reinstated 23w41a (1.20.3); 23w44a (1.20.3) added `fail`, made `return run` always return (failing if the command yields no result), propagate success, support `execute store`, and stop multi-function tag calls after the first `/return`. A function with no `/return` returns nothing; since 1.20.3 functions no longer produce a result from their last command. — [Commands/return](https://minecraft.wiki/w/Commands/return); [Function (Java Edition)](https://minecraft.wiki/w/Function_(Java_Edition))
- Placement rule: in `return run execute … run cmd`, `/return` always runs (failure/0 if `execute` terminates); in `execute … run return run cmd`, `/return` doesn't run if `execute` terminates. — [Commands/return](https://minecraft.wiki/w/Commands/return)
- `execute if function <fn|#tag>` succeeds when the function returns a nonzero value; it cannot be the last subcommand and can change the world while testing. — [Commands/execute](https://minecraft.wiki/w/Commands/execute); [Java Edition 1.20.3](https://minecraft.wiki/w/Java_Edition_1.20.3)
- Command limit gamerule is `max_command_sequence_length` (default 65,536), applying to all commands in a tick including nested functions. — [Function (Java Edition)](https://minecraft.wiki/w/Function_(Java_Edition))
- Local macro idioms: `$tellraw @s [{"text":"  game-$(n)",...,"click_event":{"action":"run_command","command":"function oneblock:___restore_as {n:$(n)}"}}]`; `function oneblock:internal/list_named_line with storage oneblock:main work[0]`; a never-executed `place template oneblock:save-$(name)` line used purely to force `$(name)` through the resource-location parser so a bad name fails the whole function. — local: `/home/dave/minecraft/one-block_2`, `/home/dave/minecraft/CLAUDE.md`

## Key question 8 — Translation table: exact syntax changes from 1.19.3 (format 10) to 26.2 (format 107.1)

### Takeaway
A learner following 2023 (1.19.3) material must translate in six areas: item NBT → components (1.20.5, further flattened 1.21.5), JSON text keys (1.21.5), data pack folder names (1.21), `pack.mcmeta` fields (1.21.9), game rule names (1.21.11), and a handful of renamed arguments; everything else from 1.19.3 (selectors, `/execute` grammar, scoreboard operations, `~`/`^`) still parses unchanged.

### Inferences
- The biggest conceptual shift for a 2023 learner is not any single rename but the move from "stringly-typed NBT everywhere" (item `tag`, JSON-in-a-string text) to typed, validated structures (components, SNBT text components) that fail loudly at parse time — which is also why old commands now error instead of silently misbehaving.
- Folder renames and `pack.mcmeta` changes mean a 1.19.3 datapack zip will not load at all in 26.2 even if every command inside it were valid; fix those first, then let the "Failed to load function" log entries guide command fixes.

### Gaps
- The `/transfer` command, `/item modify` details, and the full 1.20.5 old-NBT-key→component rename table were not captured verbatim from the wiki; the 1.21 page's Technical section could not be read (page is 468k characters) and was substituted by the 24w21a snapshot page and the Data pack page.
- Whether `max_format` written as a bare `107` matches 107.1 was not spelled out beyond the 25w31a rule that a single integer in `max_format` means "any minor version within that major"; the local pack with `"max_format": 107` loads in 26.2 (107.1), consistent with that rule.
