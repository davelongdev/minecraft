Researched 2026-10-13. Scope: zero → running modded dev client for the current release, project structure, daily workflow, packaging into the Prism Launcher flatpak. Local machine facts (verified by shell on 2026-10-13): Arch with `jdk-openjdk 27.u35-1` installed and set as default (`archlinux-java status` → `java-27-openjdk (default)`), no `gradle` package, no IntelliJ (pacman or flatpak), Prism Launcher flatpak `org.prismlauncher.PrismLauncher` 11.1.1 with instances `26.2`, `26.3`, `26.3_mini_games`, `Command Forge - 26.3`, `Commands Training Grounds`, `SkyFactory 4`.

## Key question 0: What is the current Minecraft release and what Java does it need?

### Takeaway
The current release is Java Edition **26.3 "Wilderness Bound"** (2026-09-15); it requires **Java SE 25**, and 26.4 is in snapshot (snapshots 1–4 as of 2026-10-13, release planned Q4 2026). Everything from 26.1 on ships unobfuscated with Mojang's own names.

### Cited Findings

## Key question 1: JDK — which version, Gradle JVM requirements, does JDK 27 break Gradle/Loom, how to install/select on Arch

### Takeaway
You need **JDK 25** for both the mod toolchain and to run Gradle: Loom 1.18 is compiled for Java 25, NeoForge/MDG require a Java 25 toolchain, and — the practical trap on this machine — the templates' Gradle wrappers (Fabric: Gradle 9.7.1; NeoForge MDK: Gradle 9.2.1) are **too old to run on JDK 27** (Gradle needs 9.8.0 to run on Java 27). Install `jdk25-openjdk` from `extra`, and either make it the default with `archlinux-java set java-25-openjdk`, point `JAVA_HOME` at it, or set the Gradle JVM in IntelliJ; keep JDK 27 if you like, just don't run Gradle on it.

### Cited Findings
- Gradle's compatibility table: Gradle 9.1.0 is the first version that runs on Java 25 and supports it as a toolchain; Java 26 needs Gradle 9.4.0; Java 27 needs Gradle 9.8.0; current Gradle is 9.8.1 — [Gradle compatibility matrix](https://docs.gradle.org/current/userguide/compatibility.html)
- Fabric example mod (master, i.e. the 26.3 template) wrapper: `distributionUrl=https\://services.gradle.org/distributions/gradle-9.7.1-bin.zip` — [fabric-example-mod gradle-wrapper.properties](https://raw.githubusercontent.com/FabricMC/fabric-example-mod/master/gradle/wrapper/gradle-wrapper.properties)
- NeoForge MDK-26.3-ModDevGradle wrapper: `distributionUrl=https\://services.gradle.org/distributions/gradle-9.2.1-bin.zip` — [MDK-26.3-ModDevGradle gradle-wrapper.properties](https://raw.githubusercontent.com/neoforgemdks/MDK-26.3-ModDevGradle/main/gradle/wrapper/gradle-wrapper.properties)
- Loom 1.18's own build script compiles Loom for Java 25 (`options.release = 25`, `sourceCompatibility`/`targetCompatibility = VERSION_25`, Kotlin `jvmTarget = "25"`) — [fabric-loom dev/1.18 build.gradle](https://raw.githubusercontent.com/FabricMC/fabric-loom/dev/1.18/build.gradle)
- Loom 1.18 release notes: the `fabric-loom-native` library was replaced with "Java 25's Foreign Function and Memory API" — [Loom 1.18 release](https://github.com/FabricMC/fabric-loom/releases/tag/1.18)
- Loom release history: 1.11 "Requires Java 21 (mods can still target Java 8)"; 1.12 last version supporting Gradle 8.x; 1.14 minimum Gradle 9.2; 1.16 minimum Gradle 9.4; 1.17 "uses Gradle 9.5" with 9.6 deprecation warnings fixed — [fabric-loom releases](https://github.com/FabricMC/fabric-loom/releases)
- Fabric example mod `build.gradle` sets `options.release = 25` and `sourceCompatibility`/`targetCompatibility = JavaVersion.VERSION_25` — [fabric-example-mod build.gradle](https://raw.githubusercontent.com/FabricMC/fabric-example-mod/master/build.gradle)
- NeoForge getting started: "Java 25 JDK with a 64-bit JVM"; NeoForge "recommends and officially supports the Microsoft builds of OpenJDK 25", other JDKs should work; check with `java -version` — [NeoForge docs: Getting Started](https://docs.neoforged.net/docs/gettingstarted/)
- NeoForge 26.1 snapshots post: set `languageVersion = JavaLanguageVersion.of(25)` in the toolchain; Gradle 9.1.0 or newer; ModDevGradle 2.0.134 or later — [NeoForge for 26.1 Snapshots](https://neoforged.net/news/26.1snapshots/)
- MDK-26.3-ModDevGradle `build.gradle`: Java toolchain `JavaLanguageVersion.of(25)`, plugin `net.neoforged.moddev` version `2.0.148` — [MDK-26.3-ModDevGradle build.gradle](https://raw.githubusercontent.com/neoforgemdks/MDK-26.3-ModDevGradle/main/build.gradle)
- Gradle toolchains: the toolchain (compile/test/javadoc JDK) is separate from the JVM running Gradle; `JAVA_HOME` sets the default JDK for Gradle but does not override toolchain config; Gradle auto-detects installed JDKs from OS locations, `JAVA_HOME`, SDKMAN!/asdf/Jabba, and IntelliJ installs; auto-provisioning (download) only works with a toolchain repository such as the `org.gradle.toolchains.foojay-resolver-convention` plugin (example version `1.0.0`) in `settings.gradle(.kts)`; downloads go to the Gradle User Home — [Gradle toolchains](https://docs.gradle.org/current/userguide/toolchains.html)
- ModDevGradle README recommends the `org.gradle.toolchains.foojay-resolver-convention` plugin (example `0.8.0`) "so Gradle can download Java versions automatically" — [ModDevGradle README](https://github.com/neoforged/ModDevGradle)
- IntelliJ: File | Project Structure | Platform Settings | SDKs → Add → pick a detected JDK, "Add JDK from disk", or "Download JDK" (choose vendor and version, optional install path) — [IntelliJ IDEA help: SDKs](https://www.jetbrains.com/help/idea/sdk.html)
- Arch packages (extra): `jdk-openjdk 27.u35-1`, `jdk25-openjdk 25.0.4.1.u1-1`, `jdk21-openjdk 21.0.12.1.u1-1`, `jdk17-openjdk 17.0.20.1.u1-1`, plus matching `jre*`/`jre*-headless` — [Arch package search "openjdk"](https://archlinux.org/packages/?q=openjdk)
- Local: `pacman -Si jdk25-openjdk` → version 25.0.4.1.u1-1, provides `java-environment=25`, `java-runtime=25`, conflicts only with `jre25-openjdk`/`jre25-openjdk-headless` (so it coexists with `jdk-openjdk` 27); `archlinux-java` subcommands: `status`, `get`, `set <JAVA_ENV>`, `unset`, `fix`; JVMs live in `/usr/lib/jvm/<name>` (`/usr/lib/jvm/java-27-openjdk/bin/java` present) — local shell 2026-10-13
- The Fabric docs' IDE setup page for 26.2 still links an "install-jdk-21" anchor and names no JDK version outright, i.e. the setup prose lags the Java 25 requirement — [Fabric docs: Setting up IntelliJ IDEA](https://docs.fabricmc.net/develop/getting-started/intellij-idea/setting-up)
- Older Fabric wiki setup page lists Java minimums only up to "Since 1.20.5, Java 21 or newer" and does not mention Java 25 — [Fabric wiki tutorial:setup](https://wiki.fabricmc.net/_export/raw/tutorial:setup)

### Inferences
- With JDK 27 as the system default, `./gradlew runClient` in either template will fail at startup (Gradle 9.7.1 / 9.2.1 cannot run on Java 27 per the compatibility table). Fixes, pick one: `sudo pacman -S jdk25-openjdk && sudo archlinux-java set java-25-openjdk`; or keep 27 default and run `JAVA_HOME=/usr/lib/jvm/java-25-openjdk ./gradlew ...`; or set IntelliJ's Gradle JVM (Settings → Build Tools → Gradle → Gradle JVM) to the JDK 25. Bumping the wrapper to Gradle 9.8.x would let Gradle itself run on 27, but Loom 1.18 and MDG still want a Java 25 toolchain, and neither project documents JDK 27 — not worth it.
- Expected JVM home after install: `/usr/lib/jvm/java-25-openjdk` (Arch naming pattern, by analogy with the present `java-27-openjdk`; not verified by installing).
- The foojay resolver would auto-download a JDK 25 into `~/.gradle/jdks` if none is found, but with `jdk25-openjdk` installed system-wide Gradle's auto-detection should find it; the Fabric template does not ship the foojay plugin (its `build.gradle` uses `options.release`, not a toolchain block), the MDK's `settings.gradle` was not fetched (gap).

### Gaps
- SDKMAN was not researched beyond Gradle's note that it detects SDKMAN-installed JDKs.
- Whether the MDK-26.3 `settings.gradle` includes the foojay resolver plugin was not fetched.
- No source tested Loom 1.18 or MDG 2.0.148 running on a JDK 27 Gradle daemon; the incompatibility stated above comes from the wrapper versions vs Gradle's table, not from a reproduced failure.

## Key question 2: Fabric — template generator, what it generates, Loom/API/Loader versions, mappings, split source sets, running, dev login, output

### Takeaway
Generate at fabricmc.net/develop/template (or clone fabric-example-mod); for 26.3 the template pins Minecraft 26.3, Fabric Loader 0.19.5, Loom `1.18-SNAPSHOT`, Fabric API `0.162.0+26.3`, Java 25, Gradle 9.7.1, split `main`/`client` source sets, two mixin configs — and **no mappings line at all**, because 26.x is unobfuscated and Fabric dropped Yarn. Run with `./gradlew runClient`; Loom 1.18 adds a `microsoftLogin` task so the dev client can be signed in.

### Cited Findings
- Template generator: fill mod name, package name (lowercase, dot-separated, e.g. `com.example.example-mod`), target Minecraft version; Advanced Options offer Kotlin, Kotlin buildscripts, data generators; Generate downloads a zip; alternative is cloning `fabric-example-mod` and deleting `.git`; avoid cloud-synced dirs, non-ASCII and spaces in the path; after generating, edit `gradle.properties` (`maven_group`, `archive_base_name`) and `fabric.mod.json` (`id`, `name`, `description`) — [Fabric docs: Creating a Project](https://docs.fabricmc.net/develop/getting-started/creating-a-project)
- The generator page says it creates "a customised template mod project" like `fabric-example-mod`, licensed CC0 — [fabricmc.net/develop/template](https://fabricmc.net/develop/template/)
- fabric-example-mod `gradle.properties` (master): `org.gradle.jvmargs=-Xmx1G`, `org.gradle.parallel=true`, `org.gradle.configuration-cache=true`, `minecraft_version=26.3`, `loader_version=0.19.5`, `loom_version=1.18-SNAPSHOT`, `fabric_api_version=0.162.0+26.3`, `version=1.0.0`, `group=com.example` — [fabric-example-mod gradle.properties](https://raw.githubusercontent.com/FabricMC/fabric-example-mod/master/gradle.properties)
- fabric-example-mod `build.gradle`: plugins `id 'net.fabricmc.fabric-loom' version "${loom_version}"` and `maven-publish`; `loom { splitEnvironmentSourceSets() ... mods { "modid" { sourceSet main; sourceSet client } } }`; dependencies `com.mojang:minecraft:${minecraft_version}`, `net.fabricmc:fabric-loader:${loader_version}`, `net.fabricmc.fabric-api:fabric-api:${fabric_api_version}`; Java 25; `withSourcesJar()`; expands `${version}` into `fabric.mod.json`; **no `mappings` line** — [fabric-example-mod build.gradle](https://raw.githubusercontent.com/FabricMC/fabric-example-mod/master/build.gradle)
- fabric-example-mod `fabric.mod.json`: `schemaVersion 1`, entrypoints `main` → `com.example.ExampleMod`, `client` → `com.example.client.ExampleModClient`; `mixins: ["modid.mixins.json", {config: "modid.client.mixins.json", environment: "client"}]`; depends `fabricloader >=0.19.5`, `minecraft ~26.3`, `java >=25`, `fabric-api *` — [fabric-example-mod fabric.mod.json](https://raw.githubusercontent.com/FabricMC/fabric-example-mod/master/src/main/resources/fabric.mod.json)

- Fabric for Minecraft 26.3 (blog, Sep 15 2026): latest stable Fabric Loader 0.19.5; Loom 1.17 and Gradle 9.6.0 "at time of writing"; long list of breaking changes (registries removed in favour of `DataComponents.COMPOSTABLE`/`COOKING_FUEL`/`BREWING_FUEL`, brewing recipes data-driven, worldgen `Feature`/`FeatureConfiguration` merged, GLFW replaced by SDL so use `InputConstants`, etc.) — [Fabric for Minecraft 26.3](https://fabricmc.net/2026/09/15/263.html)
- Fabric meta loader list for 26.3: 0.19.5 (stable: true), 0.19.4, 0.19.3 (unstable); intermediary version shown as `0.0.0` — [meta.fabricmc.net loader/26.3](https://meta.fabricmc.net/v2/versions/loader/26.3)
- Fabric API GitHub releases: `0.162.0+26.3` (Oct 6, marked Latest) is the newest 26.3 build; `0.162.3+26.4` (Oct 13, 26.4-snapshot-4), `0.162.2+26.4`, `0.162.1+26.4`, `0.162.0+26.4`, `0.161.2+26.4` are pre-releases for 26.4 snapshots — [FabricMC/fabric releases](https://github.com/FabricMC/fabric/releases)
- Loom 1.18 (Sep 20): Gradle task-based run configurations by default (works around an IntelliJ configuration-cache issue, updates existing run configs; disable with `preferGradleTask = false`); experimental `microsoftLogin` task — "later client runs started through Gradle are then authenticated"; task for validating injected interfaces — [Loom 1.18 release](https://github.com/FabricMC/fabric-loom/releases/tag/1.18)
- Loom 1.17 (Jun 7): new property-based `RunConfiguration` API, old API deprecated; `preferGradleTask = true` option introduced — [Loom 1.17 release](https://github.com/FabricMC/fabric-loom/releases/tag/1.17)
- Loom 1.14 (Dec 4): "Initial support for non-obfuscated Minecraft, with new plugin IDs"; 1.15 (Jan 22): remapping directly from official mappings without intermediary, FernFlower removed — [fabric-loom releases](https://github.com/FabricMC/fabric-loom/releases)
- Mappings policy: Fabric "decided to not keep maintaining third-party mappings" from the first unobfuscated release; to update a mod to 26.1+ you must first switch from Yarn to Mojang mappings; migration via Loom's `migrateMappings` task (no Kotlin support) or the Ravel IntelliJ plugin; neither is fully automatic, check Mixins by hand — [Fabric docs: Migrating Mappings](https://docs.fabricmc.net/develop/porting/mappings/index)
- "Removing Obfuscation from Fabric" (Oct 31 2025): Mojang removes obfuscation from the first snapshot after 1.21.11; Fabric API migrates to official names; Yarn "cannot be justified" in its current form (older versions still accept contributions); Intermediary "will no longer exist", the game uses Mojang's names at runtime; new mods should use official Mojang mappings; a Loom 2.0 slimmer build without remapping is in design — [Removing Obfuscation from Fabric](https://fabricmc.net/2025/10/31/obfuscation.html)
- Launching: IntelliJ run profiles (client and server, run or debug) appear top-right; CLI `./gradlew runClient` / `./gradlew runServer` ("these make debugging your code difficult"); keep project path and OS username ASCII — [Fabric docs: Launching the Game (IntelliJ)](https://docs.fabricmc.net/develop/getting-started/intellij-idea/launching-the-game)
- Generating sources: Gradle panel Tasks > fabric > `genSources` or `./gradlew genSources`; then open a Minecraft class, click "Choose Sources..." in the banner and pick the `-sources` jar; Parchment/Yarn Javadocs appear if the mappings include them — [Fabric docs: Generating Sources](https://docs.fabricmc.net/develop/getting-started/intellij-idea/generating-sources)
- Older wiki: in IntelliJ, if run configurations are missing, reimport Gradle or run `ideaSyncTask`; do not run the `idea` task; `genSources` "can take a while" — [Fabric wiki tutorial:setup](https://wiki.fabricmc.net/_export/raw/tutorial:setup)
- NeoForge docs state the build output convention `build/libs/<archivesBaseName>-<version>.jar`; the Fabric template's `build.gradle` sets `archive_base_name` from `gradle.properties` — [NeoForge docs: Getting Started](https://docs.neoforged.net/docs/gettingstarted/); [fabric-example-mod build.gradle](https://raw.githubusercontent.com/FabricMC/fabric-example-mod/master/build.gradle)
- DevAuth (third-party dev login mod): disabled by default, enable with `-Ddevauth.enabled=true`; config in `$XDG_CONFIG_HOME/devauth` or `~/.config/devauth/config.toml`; tokens in `microsoft_accounts.json` (unencrypted); Maven repo `https://pkgs.dev.azure.com/djtheredstoner/DevAuth/_packaging/public/maven/v1`, dependency `modRuntimeOnly("me.djtheredstoner:DevAuth-fabric:<version>")` (NeoForge: `runtimeOnly`, module `neoforge`); first login opens a browser OAuth link; README lists Fabric support 1.14–1.21.11 — [DevAuth README](https://github.com/DJtheRedstoner/DevAuth); latest release 1.2.2 (Dec 20, "Minecraft 1.21.11 and later", JDK HTTP client fallback) — [DevAuth releases](https://github.com/DJtheRedstoner/DevAuth/releases)

### Inferences
- The blog (Loom 1.17 / Gradle 9.6.0, written Sep 15) and the example-mod master (Loom `1.18-SNAPSHOT` / Gradle 9.7.1, Loom 1.18 released Sep 20) disagree only because the template moved on after the post; either combination targets 26.3. A fresh generator download should match example-mod master; check `gradle.properties` after download.
- Since there is no `mappings` dependency in the 26.3 template, the "Yarn vs Mojang" choice no longer exists for 26.x: names are Mojang's, straight from the unobfuscated jar. Anything in older tutorials about `loom.officialMojangMappings()` or Yarn version strings is 1.21.x-era.
- The run directory is not documented on the fetched Fabric pages; Loom's long-standing default is `run/` in the project root (unverified here — confirm by looking for `run/` after the first `runClient`).
- For logging in during dev on 26.3, Loom 1.18's built-in `./gradlew microsoftLogin` is the first thing to try; DevAuth 1.2.2 is documented only up to 1.21.11 and its 26.x compatibility is unknown. Testing without a login works (offline dev player), which is what most tutorials assume.
- `./gradlew build` runs the game tests too (see Q6), so a plain compile check is faster with `./gradlew jar` or `assemble` (inference from "server game tests run automatically with the build task").

### Gaps
- The generator's exact checkbox list on 2026-10-13 (whether it still offers a split-source-set toggle or a mappings toggle) could not be read — the page is a JavaScript app; the docs say the options are Kotlin, Kotlin buildscripts, data generators.
- The `microsoftLogin` task's mechanics (device-code vs browser, where tokens are stored) are not documented in the release note.
- Loom's `preferGradleTask` / run-directory settings page was not fetched.

## Key question 3: NeoForge — MDK / ModDevGradle template, tasks, `neoforge.mods.toml`, Parchment, access transformers, setup effort vs Fabric

### Takeaway
Download a template from the NeoForge Mod Generator (or the `neoforgemdks/MDK-26.3-ModDevGradle` repo): it pins `net.neoforged.moddev` 2.0.148, NeoForge `26.3.0.69-beta` (maven already has `26.3.0.76` without the beta suffix), Java toolchain 25, Gradle 9.2.1, runs `client`/`server`/`gameTestServer`/`data`, and a `neoforge.mods.toml` template expanded from `gradle.properties`. Parchment is no longer needed on 26.x; access transformers are auto-detected from `META-INF/accesstransformer.cfg`. Setup effort is about the same as Fabric, but the first Gradle import is slower (NeoForge docs say up to an hour) and you get one source set, not split client/common.

### Cited Findings
- NeoForge getting started: choose ModDevGradle or NeoGradle in the Mod Generator; enter mod name, optional mod ID, package, Minecraft version; extract the ZIP and import the Gradle project; "the first import can take up to an hour because Gradle downloads and decompiles dependencies"; structure: `gradle.properties` (mod info), `build.gradle`/`settings.gradle`, `src/main/java`, output `build/libs/<archivesBaseName>-<version>.jar`, run dirs `runs/client` and `runs/server`; tasks `gradlew build`, `gradlew runClient`, `gradlew runServer` (or the generated IDE run configs); reload Gradle after editing Gradle files; for a dev server accept `eula.txt` and set `online-mode=false` in `server.properties` so the dev player can join; the docs dropdown lists 26.1 as current — [NeoForge docs: Getting Started](https://docs.neoforged.net/docs/gettingstarted/)
- `neoforgemdks` org hosts 43 generated template repos including `MDK-26.3-ModDevGradle`, `MDK-26.3-NeoGradle`, `MDK-26.2-*`, `MDK-26.1.2-*`; both plugins "fully endorsed"; MDG aims for simpler build scripts, NeoGradle supports multiple NeoForge/Minecraft versions in one project; the org accepts no PRs/issues — [github.com/neoforgemdks](https://github.com/neoforgemdks)
- MDK-26.3-ModDevGradle `gradle.properties`: `org.gradle.jvmargs=-Xmx1G`, daemon/parallel/caching/configuration-cache enabled; `minecraft_version=26.3`, `minecraft_version_range=[26.3]`, `neo_version=26.3.0.69-beta`; `mod_id=examplemod`, `mod_name=Example Mod`, `mod_license=All Rights Reserved`, `mod_version=1.0.0`, `mod_group_id=com.example.examplemod`; no parchment property — [MDK-26.3-ModDevGradle gradle.properties](https://raw.githubusercontent.com/neoforgemdks/MDK-26.3-ModDevGradle/main/gradle.properties)
- MDK-26.3-ModDevGradle `build.gradle`: plugins `java-library`, `maven-publish`, `net.neoforged.moddev` `2.0.148`, `idea`; toolchain Java 25; `neoForge { version = project.neo_version; runs { client (game test namespace = mod_id); server (`--nogui`); gameTestServer (runs all registered gametests and exits); data (client datagen to `src/generated/resources/`, reads `src/main/resources/`); configureEach sets `forge.logging.markers=REGISTRIES` and log level DEBUG }; mods { "${mod_id}" { sourceSet sourceSets.main } } }`; accessTransformers line commented out (auto-detected from `src/main/resources/META-INF/`); no `parchment`, no `jvmArguments` — [MDK-26.3-ModDevGradle build.gradle](https://raw.githubusercontent.com/neoforgemdks/MDK-26.3-ModDevGradle/main/build.gradle)

## Key question 4: Mixins — what they are, when a beginner needs them, Mixin + MixinExtras in the templates

### Takeaway
Mixins rewrite vanilla bytecode at class-load time; a beginner adding content (items, blocks, events) rarely needs one, and should prefer the loader API first. Both templates wire them in already (Fabric: `modid.mixins.json` + `modid.client.mixins.json` listed in `fabric.mod.json`; NeoForge: a commented `[[mixins]]` entry), and MixinExtras has been bundled in Fabric Loader since 0.15 (0.5.0 since Loader 0.17.0, updated again in 0.19.5).

### Cited Findings
- Mixin "is a tool for modifying existing game code"; works on compiled bytecode at runtime before the target class loads; `@Mixin` marks a class and names its target and priority; `@Inject` adds instructions to a target method without removing existing bytecode; all Mixin classes must be registered in the mod's Mixin config file; MixinExtras is bundled with Fabric from Loader 0.15, and Loader 0.17.0 includes MixinExtras 0.5.0 (Expressions); the wiki calls MixinExtras "essential for precise and compatible manipulation of many Mixins" — [Fabric wiki: Mixin introduction](https://wiki.fabricmc.net/tutorial:mixin_introduction)
- Fabric Loader 0.19.5 (Aug 28) release note: "Update Mixin Extras (modmuss50)" (version not stated) — [fabric-loader 0.19.5](https://github.com/FabricMC/fabric-loader/releases/tag/0.19.5); Loader 0.19.3 updated Mixin to 0.17.3 — [fabric-loader 0.19.3](https://github.com/FabricMC/fabric-loader/releases/tag/0.19.3)
- MixinExtras docs say Fabric Loader 0.15.0+ includes MixinExtras by default and list 0.5.4 as the version to depend on explicitly if a specific release is needed — [MixinExtras documentation (via search summary)](https://docsearch.algolia.com/mcp/docs/repo/llamalad7/mixinextras)
- Fabric template registers two mixin configs: `modid.mixins.json` (common) and `modid.client.mixins.json` with `environment: client` — [fabric-example-mod fabric.mod.json](https://raw.githubusercontent.com/FabricMC/fabric-example-mod/master/src/main/resources/fabric.mod.json)
- NeoForge `[[mixins]]` entries carry `config`, optional `requiredMods`, and `behaviorVersion` matching a Fabric Mixin version such as `0.17.1` — [NeoForge docs: Mod Files](https://docs.neoforged.net/docs/gettingstarted/modfiles)
- Loom 1.12 disabled the legacy Mixin annotation processor by default; Loom 1.15 added a `defaultMixinRemapType` option — [fabric-loom releases](https://github.com/FabricMC/fabric-loom/releases)
- Mixin hot-swapping needs `-javaagent:"<path to the mixin jar>"` in the run configuration's VM arguments (find the Mixin jar under External Libraries) — [Fabric docs: Launching the Game (IntelliJ)](https://docs.fabricmc.net/develop/getting-started/intellij-idea/launching-the-game)
- The Minecraft Development IntelliJ plugin lists Mixins among its first-class platforms, with in-depth support for Access Transformers, Access Wideners and NBT — [mcdev.io](https://mcdev.io/)

### Inferences
- Because 26.x has no obfuscation and no intermediary, mixin "refmaps" and remapping concerns from 1.21-era tutorials no longer apply; mixin targets are written with Mojang's names directly (follows from the mappings findings in Q2).
- "When a beginner needs them": only when the loader API has no hook for what you want to change in vanilla behaviour; the Fabric template leaves the example mixin configs in place so adding a first `@Inject` is a matter of writing the class and listing it in the JSON.

### Gaps
- The exact MixinExtras version bundled in Loader 0.19.5 is not stated anywhere fetched.
- Fabric's docs page `/develop/mixins` returned 404; the Mixin material above comes from the legacy wiki.

## Key question 5: Workflow — hot swap, dev server, Gradle memory, build times, `./gradlew build`, installing into the Prism flatpak instance

### Takeaway

### Cited Findings
- Hot swapping: in debug mode classes can be hot-swapped without restart, but by default you cannot add/remove methods or fields or change parameters; "Using the JetBrains Runtime removes most of these limits, including adding or removing classes and methods"; add `-XX:+AllowEnhancedClassRedefinition` to the run configuration's VM arguments — [Fabric docs: Launching the Game (IntelliJ)](https://docs.fabricmc.net/develop/getting-started/intellij-idea/launching-the-game)

3. In Prism: instance `26.3` → Edit → Version → Install tab → Fabric Loader 0.19.5 (and drop `fabric-api-0.162.0+26.3.jar` into `minecraft/mods`), or NeoForge 26.3.0.76 — [Prism wiki: Version](https://prismlauncher.org/wiki/help-pages/instance-version/); [Fabric 26.3 post](https://fabricmc.net/2026/09/15/263.html); [NeoForge maven](https://maven.neoforged.net/api/maven/versions/releases/net/neoforged/neoforge).

### B. Fabric project
1. fabricmc.net/develop/template → name, package, Minecraft 26.3 → Generate → unzip to an ASCII path without spaces — [Fabric docs: Creating a Project](https://docs.fabricmc.net/develop/getting-started/creating-a-project).

Run: the "Minecraft Client" run configuration (Gradle-task-based in Loom 1.18) or `./gradlew runClient`; server: `./gradlew runServer` — [Launching](https://docs.fabricmc.net/develop/getting-started/intellij-idea/launching-the-game); [Loom 1.18](https://github.com/FabricMC/fabric-loom/releases/tag/1.18).
