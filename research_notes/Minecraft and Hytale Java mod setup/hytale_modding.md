## Game status (release, platforms, price, cadence, Linux, server, ownership)

### Takeaway
Hytale is a paid Early Access game (US$19.99 base, hytale.com store only, no Steam) released 2026-01-13 for Windows, macOS, and Linux x64 (native, Flatpak launcher, "experimental"); the server is a Java application (HytaleServer.jar, Java 25) that every player runs locally for singleplayer and that anyone can run as a dedicated server; the studio is independent again after Riot cancelled the game in June 2025 and founder Simon Collins-Laflamme bought it back in November 2025. Updates land as numbered releases every two to six weeks with weekly pre-release builds; the current release is 0.7.0 (Update 7 = "Chapter I: Out of the Breach", 2026-10-12).

## Modding model (plugins vs packs, scripting, tools, source, API distribution)

### Takeaway
Modding is server-side: Java plugins (JARs with a `manifest.json`) plus data-driven asset packs (JSON assets, Blockbench models, textures, sounds) and worlds/prefabs; there is no client-side mod loader, no text scripting language (Lua/JS rejected by design), and the planned "visual scripting" is only partly here (Trigger Volumes since Update 5, node editors in progress). The server is unobfuscated Java, the source is readable under a gated Shared Source licence (private read-only GitHub repos, since June 2026), there is an official Javadoc at docs.hytale.com/api/ and an official Maven repository (`maven.hytale.com/release`, artifact `com.hypixel.hytale:Server`), but no official Gradle plugin.

### Inferences
- "Early plugins" appear to be a bootstrap/early-load class of plugin loaded before normal plugins (hence the separate folder and warning flag); no source found explains the technical distinction, so treat as unknown.
- Because the game client is C# and closed, "client-side mods" in the Minecraft sense do not exist; everything a modder ships runs on the server, with the client receiving assets at join. The 2019 design and the 2025 strategy post both say this.
- With an official Javadoc, Maven artifacts, and readable source, the situation is closer to Paper/Bukkit (API jar from a repo) than to Fabric/NeoForge (mappings + mod loader), but without a stable-API promise.

## Developer setup (JDK, templates, running a local server, hot reload, debugging, distribution)

### Takeaway
A working Linux recipe exists today: JDK 25 + the HytaleModding `plugin-template` (Gradle Kotlin DSL, Gradle wrapper) or `realBritakee/hytale-template-plugin` (Groovy DSL, shadowJar), with the server API pulled from `maven.hytale.com` (or `compileOnly(files("HytaleServer.jar"))`), `./gradlew runServer` to download/launch a local server with the plugin in `mods/`, `-Ddebug=true -Dhotswap=true` for JDWP + hot swap with the JetBrains Runtime, then "add a private server at localhost" in the game. Distribution is CurseForge (official partner, in-game Mod Browser since Update 6, no paid mods); Modrinth has explicitly declined Hytale; Thunderstore and BuiltByBit/UnifiedHytale are secondary.

### Inferences
- Concrete Linux/Arch recipe assembled from the above (community-sourced; official docs give the API but not the workflow):
  1. Install a JDK 25 (`pacman -S jdk25-openjdk` if present in the repos, otherwise Adoptium tarball) and select it with `archlinux-java set java-25-openjdk`; keep JDK 27 for other work.
  2. Install the game via the Flatpak launcher (needed to play-test and to sign in: the server asks for a device-code login on first run).
  3. `git clone https://github.com/HytaleModding/plugin-template.git MyFirstMod`, edit `gradle.properties`, `./gradlew setupHytaleDev`, `./gradlew build`.
  4. `./gradlew runServer` (add `-Ddebug=true -Dhotswap=true` for JDWP + hot swap; JetBrains Runtime recommended), then in the game add a private server at `localhost` (UDP 5520).
  5. For a manual server: `java -jar HytaleServer.jar --assets ./Assets.zip` with the plugin JAR in `mods/` (early plugins in `earlyplugins/` + `--accept-early-plugins`).
  6. For any editor other than IntelliJ (Neovim with jdtls, Emacs with lsp-java), nothing Hytale-specific is required: the project is plain Gradle with the API resolved from `maven.hytale.com`, so jdtls should import it; the hot-swap convenience and the template's "JetBrains Runtime" recommendation are IntelliJ-centric but not mandatory.
- The two templates differ on build DSL (Kotlin vs Groovy) and on how the server is fetched (azuredoom Gradle plugin vs a `jarUrl` you supply); the official Maven repo removes the need for a local `HytaleServer.jar` as a compile dependency but you still need a server jar to run.

## Java skills needed vs Minecraft modding; editor support

### Takeaway
Hytale plugins are plain Java 25 against a published, unobfuscated API with Javadoc and Maven artifacts, so the mechanics are easier than Fabric/NeoForge (no mappings, no mixins, no Gradle loom plugin) and most like Bukkit/Paper; the harder part is that the API is large (ECS, event bus, codecs, chunk stores) and changes between updates. For editors, IntelliJ CE is the documented path; nothing found is IntelliJ-only in principle since projects are standard Gradle, but no Hytale-specific Neovim/Emacs/jdtls guide and no verified IntelliJ marketplace plugin were found.

### Cited Findings
- Entry points per the official Javadoc are the plugin package, the ECS (`com.hypixel.hytale.component`, "An implementation of an EntityComponentSystem"), and events — [docs.hytale.com/api/](https://docs.hytale.com/api/)
- Community docs: "plugin system, ECS, event bus, command system, codec layer"; advice to register everything in setup and use codecs for serialisation — [gitea docs README](https://gitea.minidev.space/hytale/hytale-server/raw/branch/main/docs/README.md)
- Hosting guide compares the plugin ecosystem to Bukkit/Spigot — [xgamingserver](https://xgamingserver.com/blog/hytale-server-modding-guide-everything-you-need-to-know/)
- Update 7 API changes show the shape of the work: `TickProcedure.onTick` now takes `CommandBuffer<ChunkStore>` and a section `Ref<ChunkStore>`, `TargetUtil` takes `ChunkStore` instead of `World`, vectors are JOML (`org.joml.Vector3d`), nullable annotations on UI `Element` — [Modder-Facing Patch Notes Update 7](https://hytale.com/news/2026/10/modder-facing-patch-notes-update-7); JOML migration reported by a plugin author — [CurseForge GlymeraFloatingIslands changelog](https://www.curseforge.com/hytale/mods/glymerafloatingislands/files/8160253)
- Community setup guide recommends IntelliJ CE and links a gist on using the correct `Nonnull` annotation — [hytalemodding.dev setting-up-env](https://hytalemodding.dev/en/docs/guides/plugin/setting-up-env); "If you use IntelliJ IDEA, almost everything is built-in" — [CurseForge how-to-create](https://blog.curseforge.com/how-to-create-hytale-mods/)
- Template recommends JetBrains Runtime for hot reload / enhanced class redefinition — [HytaleModding/plugin-template](https://github.com/HytaleModding/plugin-template)
- One tutorial uses VS Code instead of IntelliJ — [YouTube (Turkish)](https://www.youtube.com/watch?v=vPnsgNdhfRI)
- "Hyve" is listed by an aggregator as an IntelliJ platform plugin + knowledge library + MCP server for Hytale modding; github.com/Hyve-IDE/Hyve returned 404 on 2026-10-13 — [tomevault listing](https://tomevault.io/tome/Hyve-IDE/Hyve)

### Inferences
- Transferable from Fabric: Java, Gradle, event-listener thinking, JSON data packs, Blockbench. Not transferable: mixins, Yarn/Mojang mappings, client rendering/mod loaders, and the Fabric API conventions. A student who has written a Paper plugin will feel at home faster than one who has written Fabric mixins.
- Neovim + jdtls or Emacs should work on the template because it is an ordinary Gradle project resolving `com.hypixel.hytale:Server` from a Maven repo; hot swap without the JetBrains Runtime would fall back to standard JDWP method-body replacement.

## Risk assessment (API stability, breakage cadence, teaching kids 2026–27)

### Takeaway
The API is officially unstable: Update 6 (2026-08-27) bumped the protocol so every plugin needed a rebuild, and Update 7 (2026-10-12) deleted entire chunk/block accessor interfaces and renamed dozens of members, with the studio publishing "Modder-Facing Patch Notes" rather than deprecation cycles. Teaching Hytale plugin writing in 2026–27 is feasible for small, short-lived projects pinned to one server version (the Maven repo keeps the last five releases), but a term-long curriculum would need rewriting every stable update; data-driven asset packs and the no-code Trigger Volume/Node tools are the lower-risk entry point for younger students.

### Cited Findings
- OFFICIAL Update 7 removals: `ChunkAccessor`, `IWorldChunks`, `IWorldChunksAsync`, `IChunkAccessorSync`, `OverridableChunkAccessor`, `LocalCachedChunkAccessor` deleted; `WorldChunk.setBlock`/`breakBlock`/`setBlockInteractionState` overloads removed; `World.validate` removed; `ClientFeature` constants removed ("Plugins referencing them will not compile"); `ShowEventTitle` wire layout changed ("Hand-built packets break"); protocol version bumped; event listeners now keep running when one throws; asset renames (`Spectre_Void` → `Void_Spectre`, density node renames) make old assets fail to load — [Modder-Facing Patch Notes Update 7](https://hytale.com/news/2026/10/modder-facing-patch-notes-update-7)
- OFFICIAL Update 6: "The network protocol moved from hytale/2 to hytale/3 … Servers and plugins need a rebuild before they will connect" — [Update 6 notes](https://hytale.com/news/2026/8/update-6-patch-notes); plugin author: jars built for 0.5.x will not run on 0.6.0, `canGeneratePermission` no longer called, old builds can lock commands to operators or crash the world thread — [CurseForge changelog](https://www.curseforge.com/hytale/mods/glymerachunkloader/files/8754030)
- Earlier 0.5.x migration items: `AssetModule.registerPack` gained a `PackSource` parameter, `HudManager` moved to keyed entries, `Player`/`PlayerRef` split, JOML vectors, `SpawnParticleSystem` constructor changes — [CurseForge GlymeraFloatingIslands changelog](https://www.curseforge.com/hytale/mods/glymerafloatingislands/files/8160253); [BuiltByBit GlymeraBluestone](https://builtbybit.com/resources/glymerabluestone.94336/updates)
- OFFICIAL November 2025 warning: tools rough and inconsistent, crashes may cause data loss, back up frequently — [hytale.com modding strategy](https://hytale.com/news/2025/11/hytale-modding-strategy-and-status)
- Early plugins "technically unsupported and may cause the server to crash" — [ggservers](https://ggservers.com/knowledgebase/article/accept-early-plugins-hytale-server/)
- Cadence: stable every two to six weeks plus weekly pre-releases — [Wikipedia](https://en.wikipedia.org/wiki/Hytale); the Maven repo keeps only the last five release jars — [hytalemodding.dev setting-up-env](https://hytalemodding.dev/en/docs/guides/plugin/setting-up-env)
- Age/accounts: under-13 accounts need parent or guardian consent via an emailed request; Hytale does not store the entered birth date — [support.hytale.com account article](https://support.hytale.com/hc/en-us/articles/44134044725787-How-to-Create-a-Hytale-Account); ToS: a parent must accept for minors, "Age of Consent" by jurisdiction (13 US) — [hytale.com/terms-of-service](https://hytale.com/terms-of-service); Privacy Policy cites COPPA — [hytale.com/privacy](https://hytale.com/privacy)
- Account/licence requirements for the developer workflow: the server needs a signed-in account on first run (device-code flow) — [gameserverkings](https://www.gameserverkings.com/knowledge-base/hytale/hytale-dedicated-server/); source access needs a game licence + GitHub link — [shared-source-license](https://hytale.com/shared-source-license)
- Studio funding commitment: founder-funded, 10-year commitment, Early Access for "at least a few years" — [Hitmarker](https://hitmarker.net/news/cancelled-sandbox-title-hytale-reacquired-by-hypixel-founder-from-riot-games-1578723)

### Inferences
- Each student (or the class) needs a paid Hytale account ($19.99) to run even a local test server because the server authenticates; for under-13s that is a parent-consent account. Budget and consent paperwork are part of the risk.
- For a kids' class: a one-session "custom command / chat event" plugin pinned to a known server version is realistic now; a multi-week project should pin the Maven version and the server jar together and avoid the chunk/block APIs that Update 7 just rewrote.
- Compared with Minecraft (Paper API stable across years, huge tutorial base), Hytale's advantage is the official Javadoc, readable source and no mappings; its disadvantage is breakage every stable release and tutorials that go stale within months. Waiting until the "1.0" or an announced API freeze would remove most of the risk, but no such freeze has been announced.

- No direct evidence of how many CurseForge plugins broke on 0.7.0 (one day old at research time).
- No classroom or education-sector use of Hytale modding found.
