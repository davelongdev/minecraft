# Day-to-day Fabric mod development workflow and classroom logistics (as of 2026-10-13)

Scope: the practical layer between "environment works" and "shipping a mod" for Fabric on Minecraft 26.3, plus how a small nonprofit makerspace would run modding with kids on shared Arch Linux laptops using the Prism Launcher Flatpak. Sibling notes in `../Minecraft modding approaches/` already cover loader choice, version history, and kid-modding products; this file does not repeat them except where a fact is needed in context.

Version anchor verified 2026-10-13 against live APIs and the live template: Minecraft 26.3 "Wilderness Bound" (released 2026-09-15), Fabric Loader 0.19.5 (the only stable loader), Fabric API 0.162.0+26.3 (2026-10-06), Loom 1.18, Java 25 minimum; 26.4 snapshots 1–4 are already out. (Sources cited under the relevant questions below.)

## Key question 1: The canonical beginner progression (hello-world log → item → block → keybinding → command → entity)

### Takeaway
The official Fabric docs (docs.fabricmc.net, currently built for 26.2 and labelled per page) cover every step of the progression in a stable order, and the example-mod template already ships the "hello world" log line; the item and block steps are JSON-heavy but short, the keybinding and command steps are a few lines of Java each, and the entity step is a large jump (10 Java classes plus a texture) that is better treated as a capstone than a lesson.

### Cited Findings
- The docs index for "Developer Guides" is built for Minecraft 26.2 with a version selector offering 26.2, 26.1.2, 1.21.11, 1.21.1 and 1.20.4; the guide pages for the progression are: Creating Your First Item `/develop/items/first-item`, Creating Your First Block `/develop/blocks/first-block`, Key Mappings `/develop/key-mappings`, Creating Commands `/develop/commands/basics` (+ `arguments`, `suggestions`), Creating Your First Entity `/develop/entities/first-entity`, Events `/develop/events/`, Debugging Mods `/develop/debugging`, Data Generation Setup `/develop/data-generation/setup` — [Fabric Developer Guides index](https://docs.fabricmc.net/develop/)
- No docs build labelled 26.3 exists yet (the newest selector entry is 26.2), but the 26.3 Fabric blog post lists only API removals/renames (compostables/fuels moved to item components, block transformers, feature/placement renames, GLFW→SDL input constants), none of which touch the first-item/first-block/command/keybind flows — [Fabric for Minecraft 26.3](https://fabricmc.net/2026/09/15/263.html)
- **Hello world is already in the template:** `ExampleMod.java` in fabric-example-mod declares `public static final Logger LOGGER = LoggerFactory.getLogger(MOD_ID);` with the comment "It is considered best practice to use your mod id as the logger's name" and calls `LOGGER.info("Hello Fabric world!");` inside `onInitialize()`; it also provides a helper `public static Identifier id(String path) { return Identifier.fromNamespaceAndPath(MOD_ID, path); }` — [fabric-example-mod ExampleMod.java](https://raw.githubusercontent.com/FabricMC/fabric-example-mod/master/src/main/java/com/example/ExampleMod.java)
- **Custom item (page labelled 26.2):** ten steps — `ModItemIds` helper building a `ResourceKey<Item>` from `Registries.ITEM` + mod id; `ModItems` register helper taking key, factory (`Item::new`) and `Item.Properties`; an empty static `initialize()` called from the mod initializer so the class loads; `CreativeModeTabEvents.modifyOutputEvent(...)` to add it to a creative tab; `assets/<modid>/lang/en_us.json` with `item.example-mod.suspicious_substance`; a 16×16 PNG at `assets/<modid>/textures/item/<name>.png`; a model at `assets/<modid>/models/item/<name>.json` (parent `minecraft:item/generated`, `layer0` texture); a client item definition at `assets/<modid>/items/<name>.json` (`minecraft:model` type); optional recipe in `data/<modid>/recipe/` and a tooltip subclass overriding `appendHoverText` — [Creating Your First Item](https://docs.fabricmc.net/develop/items/first-item)
- **Custom block (26.2):** `ModBlockItemIds`/`ModBlockIds` ID classes, `ModBlocks.register()` overloads (one for blocks with items, one without — "Both are required, or the code won't compile"), `BlockBehaviour.Properties.of()` or `ofFullCopy()`, `CreativeModeTabEvents.modifyOutputEvent(CreativeModeTabs.BUILDING_BLOCKS)`, lang key `block.example-mod.condensed_dirt`, texture `assets/<modid>/textures/block/`, block model `models/block/<name>.json` (parent `minecraft:block/cube_all`), item definition `assets/<modid>/items/<name>.json` pointing at `example-mod:block/<name>`, blockstate `assets/<modid>/blockstates/<name>.json` ("The filename must match the block ID"), loot table `data/<modid>/loot_table/blocks/<name>.json` (`minecraft:block` table, `minecraft:item` entry, `minecraft:survives_explosion`), optional tool tags under `data/minecraft/tags/block/mineable/shovel.json` etc. plus `.requiresCorrectToolForDrops()`; the fetched page is internally inconsistent about `loot_table/` vs `loot_tables/` and `tags/block/mineable/` vs `tags/mineable/` — [Creating Your First Block](https://docs.fabricmc.net/develop/blocks/first-block)
- **Keybinding (26.2):** client-only (`src/client/java/...`); `KeyMapping.Category.register(ExampleMod.id("custom_category"))`, then Fabric API's `KeyMappingHelper.registerKeyMapping(new KeyMapping("key.example-mod.send_to_chat", InputConstants.Type.KEYSYM, InputConstants.KEY_J, CATEGORY))`; press detection in `ClientTickEvents.END_CLIENT_TICK` with `while (key.consumeClick()) {...}`; lang keys `key.category.<ns>.<path>` and the mapping key; `InputConstants.KEY_*` names assume a US layout; "Holding the key fires repeatedly, so add a guard" — [Key Mappings](https://docs.fabricmc.net/develop/key-mappings)
- **Command (26.2):** register inside `CommandRegistrationCallback.EVENT.register((dispatcher, registryAccess, environment) -> dispatcher.register(Commands.literal("test_command").executes(ctx -> { ctx.getSource().sendSuccess(() -> Component.literal("Called /test_command."), false); return 1; })))`; Brigadier is "a tree-based command library"; a `Command` returns an int where "Zero or negative values indicate failure, and positive values indicate success" (`Command#SINGLE_SUCCESS`); `environment.includeDedicated` gates dedicated-server-only commands; client commands use `ClientCommandRegistrationCallback` + `ClientCommands` and "The code should exist only in client-side code" — [Creating Commands](https://docs.fabricmc.net/develop/commands/basics)
- **Entity (26.2):** "Moderate to high" complexity — 7 main sections, ~15 code steps, 10 Java classes (`MiniGolemEntity` extends `PathfinderMob`, `ModEntityTypeIds`, `ModEntityTypes` with attribute registration via Fabric's default-attribute registry, goals such as tempt-by-wheat/random stroll, client `MiniGolemEntityModel` + `LayerDefinition`, `ModEntityModelLayers`, `MiniGolemEntityRenderState`, `MiniGolemEntityRenderer`, `MiniGolemAnimations`) plus a 64×32 texture at `assets/<modid>/textures/entity/mini_golem.png`; synced data, NBT persistence and an `AnimationState` dance; the spawn egg is a separate page (`/develop/items/spawn-egg`) — [Creating Your First Entity](https://docs.fabricmc.net/develop/entities/first-entity)
- **Events as the "hello world" of behaviour:** Fabric API events are `net.fabricmc.fabric.api.event.Event` instances registered with `EVENT.register(callback)`; `InteractionResult.FAIL` cancels, `SUCCESS` finishes, `PASS` falls through; the docs' example is `AttackBlockCallback`; "events often substitute for mixins" — [Events introduction](https://docs.fabricmc.net/develop/events/)
- A free, current beginner workshop (jvdesignstudio, UK, "Episode 1 of 6", ages 10+, "No Java Experience Needed", ~1.5 hours) does exactly the first-item step on Fabric 1.21/JDK 21 in ten steps: install JDK, install IntelliJ CE, download the example-mod ZIP, open + Gradle sync + `genSources`, edit `fabric.mod.json` and move the package, write `ModItems`, add texture/model/lang, run the client, find the item in creative or `/give @p crystalmod:crystal_gem`; the challenge is a second item — [Hello Minecraft! Build Your First Custom Item Mod](https://jvdesignstudio.co.uk/workshops/minecraft-first-item-mod.html)
- The same workshop's teacher notes: Gradle sync is "the #1 stuck point in the whole series" (wrong JDK, firewall blocking `gradle.org`/`services.gradle.org`, impatience); "First sync can take 10-20 min on slow connections"; the first sync "downloads about 500MB"; don't put the project in OneDrive/iCloud folders; the commonest run-time crash is "a typo in one of the JSON files"; common kid error is creating `ModItems.java` in the wrong package or forgetting to call the register method — [jvdesignstudio workshop](https://jvdesignstudio.co.uk/workshops/minecraft-first-item-mod.html)
- A seven-week free course "Basics of Java in Minecraft" (Unlicense/public domain) uses the Fabric toolchain to teach Java itself: weeks are Environment; Data Types and Control Structure; Objects, Classes, Inheritance; Control Structures in Depth; Arrays and Iteration; Polymorphism; Project Basics/Planning/Pseudo-Code, each with a lesson and a project and a `Master Lesson Plan.docx`; it does not state a Minecraft version or age range — [coder0987/Basics-of-Java-in-Minecraft](https://github.com/coder0987/Basics-of-Java-in-Minecraft)
- Older Fabric wiki tutorials (wiki.fabricmc.net) still exist but redirect to or lag the docs; the wiki items page now redirects to the docs' first-item page — [wiki.fabricmc.net tutorial:items](https://wiki.fabricmc.net/_export/raw/tutorial:items)

### Inferences
- A workable session plan for 60–90 minute slots, derived from the step counts above and the jvdesignstudio timing: (1) open the pre-built project, change the `LOGGER.info` text, run the client, find the line in `run/logs/latest.log` (10–20 min once Gradle is warm); (2) custom item (one full 90-minute session — three Java edits plus four JSON/PNG files; this is what the UK workshop fits in 1.5 h including installs); (3) custom block (another session — same shape plus blockstate and loot table; reuse the item session's muscle memory); (4) command (30–45 min — a single lambda, immediately testable in chat; good for kids who already know `/` commands from the datapack work); (5) keybinding (30–45 min, client-side only, teaches the main/client split); (6) entity (two to three sessions, or instructor-built with students editing goals/texture). These durations are inference, not measured.
- For kids coming from the makerspace's datapack workshops, the command step is the most natural entry after hello world, since Brigadier trees mirror what they already type; the block loot-table JSON is byte-for-byte the datapack format they know.
- Because no docs build is labelled 26.3 yet, lessons should be written from the 26.2 pages and smoke-tested once on 26.3 before class; the 26.3 blog lists no breaking change in these areas, so breakage is unlikely but unverified by the docs themselves.

### Gaps
- No source gives measured per-step times for beginners beyond the UK workshop's "~1.5 hours" for the item step; the other durations above are inference.
- The CSU Stanislaus CS-club "Preworkshop Onboarding" page surfaced in search but its host (`csclub.csustan.edu`) did not resolve, so it could not be read.
- No 26.x-era classroom write-up was found; all educator material is 1.18–1.21 era.

## Key question 2: Project conventions (mod id, packages, assets/data layout, datagen vs hand JSON, bundling a datapack, fabric.mod.json, entrypoints, split sources)

### Takeaway
The rules are concise and documented in the loader reference: mod id = letter-first, ASCII letters/digits/underscore/hyphen, 2–64 chars; the jar's `assets/<modid>` and `data/<modid>` folders are literally resource-pack and data-pack layout, so the makerspace's datapack files drop in unchanged; the 26.3 template defaults to split `main`/`client` source sets, Java 25, and a `fabric.mod.json` with `main` and `client` entrypoints; data generation is optional and adds a `fabric-datagen` entrypoint plus `./gradlew runDatagen` writing to `src/main/generated`.

### Cited Findings
- **Mod id rule (quoted):** "Must start with a letter. May only contain ASCII letters, digits, underscores, or hyphens. 2 to 64 characters." `schemaVersion` "Must be the first entry, and the value must always be `1`." `version` should be SemVer 2.0.0 with any number of components, else it is treated as a plain string with no range support — [fabric.mod.json reference](https://docs.fabricmc.net/develop/loader/fabric-mod-json)
- **Entrypoints:** `main` → `ModInitializer`; `client` → `ClientModInitializer` (runs after `main`, client only); `server` → `DedicatedServerModInitializer`; custom keys allowed, the example being `fabric-datagen` from Fabric API; entries may be a class or `Class::method`; `preLaunch` is not documented on this page — [fabric.mod.json reference](https://docs.fabricmc.net/develop/loader/fabric-mod-json)
- **Environment:** `*` (default), `client` ("will not be loaded on dedicated servers"), `server` (not loaded on clients "including singleplayer and LAN") — [fabric.mod.json reference](https://docs.fabricmc.net/develop/loader/fabric-mod-json)
- **Dependencies:** `depends` (missing → crash), `recommends` (warning), `suggests` (metadata), `breaks` (present → crash), `conflicts` (warning); range operators `*`, exact, `>`, `>=`, `<=`, space-separated bounds, `~26.1-rc.2` (same major.minor), `^26.2` (same major), `26.1.x`; "Build metadata, that is whatever follows the `+` in a version, is ignored for version comparison"; `.x` is buggy with >3 components in Loader 0.19.3 — [fabric.mod.json reference](https://docs.fabricmc.net/develop/loader/fabric-mod-json)
- **Other fields:** `license` "recommended to use SPDX License Identifiers"; `icon` square PNG (power of two recommended); `jars` for nested jars ("when you use `include` on dependencies, Loom populates this automatically"); `mixins` entries may carry their own `environment`; `accessWidener` names an access widener or class tweaker; `custom` holds arbitrary namespaced data — [fabric.mod.json reference](https://docs.fabricmc.net/develop/loader/fabric-mod-json)
- **The live 26.3 template's `fabric.mod.json`** (fetched 2026-10-13): `"id": "modid"`, `"version": "${version}"`, `"license": "CC0-1.0"`, `"icon": "assets/modid/icon.png"`, `"environment": "*"`, entrypoints `main: ["com.example.ExampleMod"]` and `client: ["com.example.client.ExampleModClient"]`, mixins `"modid.mixins.json"` plus `{ "config": "modid.client.mixins.json", "environment": "client" }`, depends `fabricloader >=0.19.5`, `minecraft ~26.3`, `java >=25`, `fabric-api *` — [fabric-example-mod fabric.mod.json](https://raw.githubusercontent.com/FabricMC/fabric-example-mod/master/src/main/resources/fabric.mod.json)
- **Template `gradle.properties` (2026-10-13):** `org.gradle.jvmargs=-Xmx1G`, `org.gradle.parallel=true`, `org.gradle.configuration-cache=true`, `minecraft_version=26.3`, `loader_version=0.19.5`, `loom_version=1.18-SNAPSHOT`, `version=1.0.0`, `group=com.example`, `fabric_api_version=0.162.0+26.3`, with the comment "check these on https://fabricmc.net/develop" — [fabric-example-mod gradle.properties](https://raw.githubusercontent.com/FabricMC/fabric-example-mod/master/gradle.properties)
- **Template `build.gradle`:** calls `splitEnvironmentSourceSets()` and declares a `mods { modid { sourceSet sourceSets.main; sourceSet sourceSets.client } }` block; compiles with `options.release = 25`, `sourceCompatibility = JavaVersion.VERSION_25`, `targetCompatibility = JavaVersion.VERSION_25`; a comment warns "If you remove this line, sources will not be generated" about the sources-jar line — [fabric-example-mod build.gradle](https://raw.githubusercontent.com/FabricMC/fabric-example-mod/master/build.gradle)
- **Folder layout:** `src/main/resources` holds "textures, models, and sounds" plus `fabric.mod.json` and mixin configs, and "Assets mirror resource pack structure, for example `assets/example-mod/textures/block/block.png`"; `src/client/resources` = client-only resources; `src/main/java` = code for both sides; `src/client/java` = client-only code "such as rendering code or block color providers" — [Project Structure](https://docs.fabricmc.net/develop/getting-started/project-structure)
- `splitEnvironmentSourceSets()` splits "the Minecraft jar and incoming dependencies across the main (common) and client-only source sets", giving "compile-time safety for accessing client-only code"; Loom ≥ 1.17 run-config syntax is property based: `jvmArguments.add("-Dexample=true")`, `programArguments.add("--example")`, `runDirectory = file("run")`, `displayName = "Minecraft Client"`, `runtimeEnvironment = "client"`, `generateRunConfig = true`, with `client()`/`server()` defaults; `log4jConfigs.from(file("log4j.xml"))` — [Loom extension options](https://docs.fabricmc.net/develop/loom/options)
- **Package naming:** the template generator wants a package name that is "lowercase, separated by dots, and unique", typically a reversed domain such as `com.example.example-mod`; required generator fields are mod name, package name, Minecraft version; Advanced Options are Kotlin, Kotlin buildscripts, data generators; "Avoid cloud storage directories, non-ASCII characters, and spaces" in the project path; the manual route is to clone `fabric-example-mod`, delete `.git`, then edit `maven_group`/`archive_base_name` in `gradle.properties` and `id`/`name`/`description` in `fabric.mod.json` — [Creating a Project](https://docs.fabricmc.net/develop/getting-started/creating-a-project); generator at [fabricmc.net/develop/template](https://fabricmc.net/develop/template/) (CC0 output)
- **Data generation:** enable with `fabricApi { configureDataGeneration() { client = true } }` in `build.gradle`; entrypoint class implements `DataGeneratorEntrypoint` and is listed under `"fabric-datagen"` in `fabric.mod.json` ("you must add the comma"; close and reopen IntelliJ so it creates the run configuration); create a pack with `fabricDataGenerator.createPack()`; run via the IDE config or `./gradlew runDatagen`; "the generated files will be created in `src/main/generated`"; follow-up providers exist for advancements, loot tables, recipes, tags, translations, block models, item models (block-state provider not mentioned on the setup page) — [Data Generation Setup](https://docs.fabricmc.net/develop/data-generation/setup)
- **Bundling a data/resource pack inside a mod (Fabric API javadoc, 0.160.4+26.3):** built-in packs live under `resources/resourcepacks/`; "a built-in data pack with the ID `example:test` should be placed under `resources/resourcepacks/test/data/`"; register with `ResourceManagerHelper.registerBuiltinResourcePack(Identifier, ModContainer, ResourcePackActivationType)`; "Players can switch these packs on or off unless the pack is forced on"; bundled packs are currently sorted by mod id — [Fabric API `net.fabricmc.fabric.api.resource` package summary](https://maven.fabricmc.net/docs/fabric-api-0.160.4+26.3/net/fabricmc/fabric/api/resource/package-summary.html)
- Minecraft 26.3 is data pack format 121.0 and resource pack format 97.1 — [Minecraft Wiki: Java Edition 26.3](https://minecraft.wiki/w/Java_Edition_26.3); the makerspace's Command Forge pack already targets pack format 121 for 26.3 — local project notes, `/home/dave/minecraft/CLAUDE.md`
- In 26.3 more content moved to data: brewing recipes are JSON, several worldgen registries (`worldgen/material_rule`, `worldgen/material_condition`, `block_transformer`, `worldgen/block_state_provider`, context float/int providers) are now data-driven — [Fabric for Minecraft 26.3](https://fabricmc.net/2026/09/15/263.html)
- The "Project Structure" page does not cover mod-id character rules, `preLaunch`, the `data/` folder, or `gradle.properties`/`libs.versions` — [Project Structure](https://docs.fabricmc.net/develop/getting-started/project-structure)

### Inferences
- The simplest way to "bundle a datapack in a mod" is to put the pack's `data/<namespace>/...` tree straight into `src/main/resources/data/`: a mod jar's root `data/` and `assets/` folders are loaded as the mod's own always-on pack (that is how the first-block guide ships its loot table and tags). The `resourcepacks/<name>/` + `registerBuiltinResourcePack` route is for *optional* packs the player can toggle. The first claim is inferred from the first-block guide's file placement; the docs never state it as a rule in so many words.
- For a classroom, hand-written JSON is the better teaching default (it reuses the datapack skills and keeps the mental model "a mod is Java + a datapack + a resource pack"); datagen pays off only once a student has more than a handful of items/blocks, and it adds an IDE restart and a second run configuration to explain.
- Pick mod ids without hyphens when kids will type translation keys and `/give` ids by hand (the docs' `example-mod` is legal but `item.example-mod.x` keys and `example-mod:x` ids invite typos); this is a preference, not a rule.

### Gaps
- `preLaunch` entrypoint semantics are not on the current loader reference page; not pursued further (beginners never need it).
- The template-generator form itself could not be read (the page is JavaScript-rendered), so whether it offers a Mojang-mappings/Yarn toggle or split-sources toggle in October 2026 is unverified; the downloaded 26.3 example mod uses Mojang names and split sources by default.

## Key question 3: Debugging (logs, LOGGER, breakpoints, common crash types, crash reports, memory flags)

### Takeaway
In a Loom project everything lands under `<project>/run/` (`run/logs/latest.log`, `run/crash-reports/`); the docs' debugging page covers IDE breakpoints (start with Debug, not Run), hot-swap via Build Project, and a `log4j-dev.xml` trick to enable your mod's `debug` level; Fabric's own docs do not catalogue crash causes, so "mixin apply failed", missing registry entries and client/server mismatches have to be taught from the crash-report structure and community threads.

### Cited Findings
- All Loom run configurations use run directory `${projectDir}/run` and pass `-Dfabric.development=true`; default main classes are `net.fabricmc.loader.launch.knot.KnotClient`/`KnotServer`; if an `.idea` folder exists Loom installs run configurations in `.idea/runConfigurations` — [Loom introduction](https://docs.fabricmc.net/develop/loom/)
- Logs: "Consoles are exported to the instance's `logs` directory, and the newest file is usually `latest.log`. In the dev environment, look in `run > logs`"; crash reports in the dev environment are in `run > crash-reports` — [Debugging Mods](https://docs.fabricmc.net/develop/debugging)
- LOGGER: created with `LoggerFactory.getLogger(MOD_ID)`; use `debug`, `info`, `warn`, `error`; "use `debug` for development-only data"; to see debug output create `log4j-dev.xml` in the project root with your mod's logger at `level="debug"` and add `loom.log4jConfigs.from "log4j-dev.xml"` to `build.gradle` — [Debugging Mods](https://docs.fabricmc.net/develop/debugging); the template imports `org.slf4j.Logger`/`org.slf4j.LoggerFactory` — [ExampleMod.java](https://raw.githubusercontent.com/FabricMC/fabric-example-mod/master/src/main/java/com/example/ExampleMod.java)
- Breakpoints: "To use breakpoints, you must execute the instance using the `Debug` option instead of the `Run` option"; Step Over F8, Step Into F7, Resume F9, conditional breakpoints via right-click; hot swap = `Build > Build Project` on a running Debug instance, "limited changes" only, mixins need extra run configuration; assets reload with F3+T, data with `/reload` — [Debugging Mods](https://docs.fabricmc.net/develop/debugging)
- Missing assets/textures only log a warning (they do not crash) — [Debugging Mods](https://docs.fabricmc.net/develop/debugging)
- Reading a crash report (player-side guide): the `---- Minecraft Crash Report ----` summary is "the most important section" with the main error, time and stack trace; the stack trace "can usually contain references to the mod that caused the crash" but the first mod listed may not be at fault ("compatibility issues between the mods"); "Last Reload" errors "are usually caused by resource packs"; System Details lists OS/Java/memory and Fabric adds a "Fabric Mods:" list; method mixins show up as `mod-id$handlerName` in stack traces; share via GitHub Gist, mclo.gs or Pastebin and ask in Fabric Discord `#player-support` — [Fabric crash-report guide](https://docs.fabricmc.net/players/troubleshooting/crash-reports)
- "Mixin apply failed" patterns from real reports: target method/field missing after a version change (Aternos thread; Controlify issue 374 — `@Shadow` method not found), wrong descriptor/argument index (RCT API issue 75), two mods patching the same method (Meteor Client redirect conflict), and a dependency/version mismatch (VulkanMod issue 738 with Bookshelf) — [Aternos thread](https://board.aternos.org/thread/79260-why-isnt-my-mods-server-starting-crashing/); [Controlify #374](https://github.com/isXander/Controlify/issues/374); [RCT #75](https://gitlab.com/srcmc/rct/mod/-/issues/75); [VulkanMod #738](https://github.com/xCollateral/VulkanMod/issues/738)
- JVM args for the dev client go in `loom { runs { client { jvmArguments.add("...") } } }` (Loom ≥ 1.17 syntax) — [Loom extension options](https://docs.fabricmc.net/develop/loom/options); the Gradle daemon itself gets `org.gradle.jvmargs=-Xmx1G` from the template — [gradle.properties](https://raw.githubusercontent.com/FabricMC/fabric-example-mod/master/gradle.properties)
- Prism's Java settings page says "about 4GB is enough for most uses except large modpacks" and that more RAM "doesn't necessarily mean better performance" — [Prism Launcher Java Settings](https://prismlauncher.org/wiki/help-pages/java-settings/)
- The 26.3 template's `fabric.mod.json` requires `"java": ">=25"` and the docs' setup page says "To develop mods for Minecraft 26.1, you will need JDK 25" — [fabric.mod.json](https://raw.githubusercontent.com/FabricMC/fabric-example-mod/master/src/main/resources/fabric.mod.json); [Setting Up Your IDE](https://docs.fabricmc.net/develop/getting-started/setting-up)
- Minecraft 26.3 requires "Java SE 25" minimum — [Minecraft Wiki: Java Edition 26.3](https://minecraft.wiki/w/Java_Edition_26.3)

### Inferences
- For a terminal/nvim workflow (no IntelliJ) the practical debug loop is `./gradlew runClient` in one terminal and `tail -f run/logs/latest.log` in another; breakpoints need a JDWP agent (`jvmArguments.add("-agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=5005")` in the `client` run block) and an attach from nvim-dap/jdtls. The JDWP flag is standard JVM behaviour, but neither Fabric nor Loom documents this attach route, so it is unverified for Loom 1.18 specifically.
- Teach the three crash families with one example each: (a) "missing registry entry"/typo = the game boots, the item is missing or pink-black, `latest.log` has a warning naming the path (from the docs' "missing assets only warn" note); (b) client/server mismatch = calling `Minecraft`/renderer code from `src/main` fails to compile under split sources, which is the whole point of `splitEnvironmentSourceSets()`; (c) mixin apply failure = a startup crash whose stack trace names `mod-id$handler`, almost always a version mismatch for beginners who never write mixins.
- JDK 27 on the host is fine for running Gradle (Gradle 9.6 is the 26.3 recommendation), but the project compiles with `--release 25`, so the kid never sees a Java-version mismatch unless Gradle's own JVM is older than 25.

### Gaps
- No Fabric page states a recommended `-Xmx` for the dev client; the only memory guidance found is Prism's 4 GB remark for players.
- No official Fabric/Loom documentation for attaching an external debugger (JDWP) was found; the docs assume IntelliJ's Debug button.

## Key question 4: Multi-loader and multi-version (Architectury, Stonecutter, Sinytra Connector) — should a beginner care?

### Takeaway
All three tools are alive in October 2026 — Architectury API 22.0.5 ships for both Fabric and NeoForge on 26.3, Stonecutter (now on Codeberg) does comment-based multi-version preprocessing, and Sinytra Connector runs Fabric mods on NeoForge but only for 26.1.2 (primary) and 1.21.1 (LTS) with no 26.2/26.3 build — but none of them belongs in a beginner classroom; pin one loader (Fabric), one Minecraft version (26.3), and one semester.

### Cited Findings

## Key question 5: Distribution (Modrinth, CurseForge, Minotaur, licensing) and the classroom alternative (shared jar + Prism instance vs a tiny local server)

### Takeaway
Publishing is cheap and documented (Modrinth: SPDX license id, 1–3 categories, a first version with loaders + game versions, 24–48 h review; Minotaur 2.x automates uploads with a `MODRINTH_TOKEN`), but for a makerspace the realistic path is sharing the built jar inside a Prism instance; a mod's `environment` field and the Fabric server launcher decide whether every laptop needs the jar (any mod that is not purely client-side must be on both the server and every client).

### Cited Findings
- Build: `./gradlew build` from the project root; jars land in `build/libs`; "Use the JAR file with the shortest name outside development"; share via CurseForge or Modrinth; terminal builds "can fail if your default Java version doesn't match the project's" — [Building a Mod](https://docs.fabricmc.net/develop/getting-started/building-a-mod)
- Modrinth project requirements (creator guide): name 3–64 chars; slug 3–64 lowercase/numbers/hyphens, unique; summary 3–255; Markdown description ≤ 65,536; 1–3 primary categories; license as an SPDX identifier in `license_id`, default `ARR` (All Rights Reserved), optional `license_url`; icon ≤ 256 KiB; a submitted project needs at least one version with version number, title, files, loaders, game versions and a channel (release/beta/alpha); "Most projects are approved within 24-48 hours"; a file whose hash exists in another project is rejected; `is_draft` saves without review — [Modrinth creators: creating projects (mirror)](https://mintlify.wiki/modrinth/code/creators/creating-projects); the version endpoint accepts `.mrpack`, `.jar`, `.zip`, `.litemod` — [Modrinth API: create version](https://docs.modrinth.com/api/operations/createversion)
- Modrinth's license tag list has 706 SPDX entries (queried 2026-10-13) — [Modrinth API `/v2/tag/license`](https://api.modrinth.com/v2/tag/license)
- Minotaur (`com.modrinth.minotaur`, README recommends version `2.+`; latest tag v2.10.0, 2026-09-17): `modrinth { token = System.getenv("MODRINTH_TOKEN"); projectId; versionNumber; versionType; uploadFile = remapJar (with Loom); gameVersions; loaders; dependencies { required.project "fabric-api" } }`; needs a token with `CREATE_VERSION` (and `PROJECT_WRITE` for `modrinthSyncBody`); duplicate version numbers fail; game versions/loaders auto-detected under Loom; body sync is irreversible, `debugMode` dry-runs — [modrinth/minotaur README](https://github.com/modrinth/minotaur); [GitHub releases API](https://api.github.com/repos/modrinth/minotaur/releases/latest)
- CurseForge: Darkhax's CurseForgeGradle (`net.darkhax.curseforgegradle`, seen at 1.1.25) registers a `TaskPublishCurseForge` task that uploads the `remapJar` output with changelog, release type, game version, loader and dependencies; alternatives exist (`io.github.themrmilchmann.curseforge-publish`, which warns against hard-coding tokens in committed build scripts) — [CurseForgeGradle source](https://github.com/Darkhax/CurseForgeGradle); [gradle-curseforge-publish README](https://github.com/TheMrMilchmann/gradle-curseforge-publish/blob/master/README.md)
- Licensing norms: the Fabric template ships `"license": "CC0-1.0"` — [fabric.mod.json](https://raw.githubusercontent.com/FabricMC/fabric-example-mod/master/src/main/resources/fabric.mod.json); the loader reference recommends SPDX ids — [fabric.mod.json reference](https://docs.fabricmc.net/develop/loader/fabric-mod-json); Modrinth defaults to ARR unless set — [Modrinth creators guide](https://mintlify.wiki/modrinth/code/creators/creating-projects)
- Minecraft EULA on mods: "Any Mods you create for Minecraft: Java Edition from scratch belong to you ... as long as you don't sell them for money / try to make money from them and so long as you don't distribute Modded Versions of the game"; "Mods are okay to distribute; hacked versions or Modded Versions of the game client or server software are not okay to distribute"; a "Mod" must not "contain a substantial part of our copyrightable code or content" — [Minecraft EULA](https://www.minecraft.net/en-us/eula)
- Fabric server: the fabricmc.net server page offers a "Minecraft Server Launcher" download (JavaScript-rendered) and says "Most mods will also require you to install Fabric API into the mods folder" — [fabricmc.net/use/server](https://fabricmc.net/use/server/)
- LAN: Pause → "Open to LAN" (or `/publish`), a port is announced in chat ("Local game hosted on port 2121"), a specific port can be chosen since 22w45a; players on the same network see it under Multiplayer; "Using one Minecraft account on two computers won't let both join the same world"; disabling `online-mode` in `server.properties` lets players join a dedicated server "with other names without a Minecraft account" — [Minecraft Wiki: Setting up a LAN world](https://minecraft.wiki/w/Tutorial:Setting_up_a_LAN_world)
- A mod with `environment: client` "will not be loaded on dedicated servers"; `server` mods are not loaded "on clients, including singleplayer and LAN" — [fabric.mod.json reference](https://docs.fabricmc.net/develop/loader/fabric-mod-json)
- Prism can export an instance as CurseForge zip, Modrinth `.mrpack`, MultiMC/Prism zip or Technic; release 7.1 fixed `.mrpack` export bundling all mods instead of metadata — [Prism developer docs: instance management (mirror)](https://www.mintlify.com/PrismLauncher/PrismLauncher/development/architecture/instance-management); [Prism 7.1 release notes](https://prismlauncher.org/news/release-7.1/); Prism's "Copy instance" dialog can copy saves, options, resource packs, mods etc., with symlink/hardlink and copy-on-write options — [Prism Launcher: Instance Copy](https://prismlauncher.org/wiki/help-pages/instance-copy/)

### Inferences
- Classroom distribution ladder: (1) copy `build/libs/<mod>.jar` into each laptop's instance `mods/` (plus Fabric API) — works for everything, needs a licensed account per laptop; (2) one "class instance" exported from Prism as a MultiMC zip and imported on every laptop, so kids get the same Fabric version + Fabric API + the day's mods; (3) a Fabric dedicated server in a plain folder on the instructor's laptop with `online-mode=false` — players still need the same non-client-only mods installed locally, so it does not reduce per-laptop setup, but it does remove the "host leaves and the world dies" problem of LAN worlds and lets kids with offline names join (EULA/licensing caveats in Q6).
- A blocks/items/commands/entities mod is *not* client-only (registries must match on both sides), so every kid's client needs the jar; only HUD/keybind-style mods can be `environment: client` and live on one laptop.
- Modrinth publishing is a good "graduation" activity for a teen (SPDX license choice, slug, version number, changelog) but requires an adult-managed account and a token; do not store tokens in the repo.

### Gaps
- Prism's official wiki page for *exporting* an instance was not found (only the developer-doc mirror and release notes); menu names in 11.1.1 are unverified.
- Whether `/publish` LAN worlds accept offline-named demo/offline clients was not documented.
- No source quantifying Modrinth review wait beyond the "24-48 hours" line.

## Key question 6: Classroom logistics on Linux (Prism Flatpak paths, Java, accounts, Gradle offline caching, build times, 60–90 min feasibility)

### Takeaway
On this machine the Prism Flatpak keeps everything under `~/.var/app/org.prismlauncher.PrismLauncher/data/PrismLauncher/` (instances at `instances/<name>/minecraft/mods/`), auto-downloads Mojang's Java 25 (`java/java-runtime-epsilon`, 111 MB) and pins it per instance; Prism refuses offline accounts until a Microsoft account that owns Minecraft has been added, and an account that does not own the game is offered Demo mode only; Gradle's cache can be pre-seeded and reused offline (`--offline`, `GRADLE_USER_HOME`, or a read-only `GRADLE_RO_DEP_CACHE`), which is the key to a 60–90 minute session on shared laptops.

### Cited Findings
- **Prism data path (official):** Flatpak `~/.var/app/org.prismlauncher.PrismLauncher/data/PrismLauncher`; native `~/.local/share/PrismLauncher`; `instances` "Stores user instances" — [Prism Launcher: Data Location](https://prismlauncher.org/wiki/getting-started/data-location)
- **Verified locally (2026-10-13, Prism Flatpak 11.1.1 from Flathub):** data dir holds `accounts.json assets cache instances java libraries logs meta prismlauncher.cfg ...`; instances present: `26.2`, `26.3`, `26.3_mini_games`, `Command Forge - 26.3`, `Commands Training Grounds`, `SkyFactory 4`; an instance is `instance.cfg`, `mmc-pack.json`, `minecraft/` and inside `minecraft/`: `mods/ saves/ resourcepacks/ logs/ options.txt servers.dat coremods/ downloads/ ...` (so the mods folder is `.../instances/<name>/minecraft/mods/`); `mmc-pack.json` components for the 26.3 instance: `net.minecraft 26.3`, `org.lwjgl3 3.4.3` (no Fabric loader component yet); `instance.cfg` has `OverrideJavaLocation=true` and `JavaPath=.../PrismLauncher/java/java-runtime-epsilon/bin/java`; global `prismlauncher.cfg` records `JavaVendor=Microsoft`, `JavaVersion=25.0.1`; auto-downloaded runtimes: `java-runtime-epsilon` 111 MB (Java 25, used by 26.3), `java-runtime-gamma` 96 MB, `jre-legacy` 226 MB; one account of type `MSA` — local inspection via `flatpak info`, `ls`, `grep` (no URL)
- **Flatpak sandbox permissions (local `flatpak info --show-permissions`):** `filesystems=xdg-download:ro; ~/.ftba:ro; ...` — the host home is *not* mounted, so a mod jar built in `~/minecraft/...` must be copied into the Flatpak data dir (or Prism granted extra filesystem access with `flatpak override`), and `~/Downloads` is readable but read-only — local inspection (no URL)
- Prism Java settings: "Auto-download Mojang Java" is "Recommended", "will automatically download needed the Java runtimes you need", requires autodetect on, and "will change the java path in instance settings"; "Skip Java compatibility checks" exists; "about 4GB is enough for most uses except large modpacks" — [Prism Launcher: Java Settings](https://prismlauncher.org/wiki/help-pages/java-settings/)
- **Offline accounts (Prism source, `develop` branch):** adding an offline account shows "You must add a Microsoft account that owns Minecraft before you can add an offline account." — [AccountListPage.cpp](https://raw.githubusercontent.com/PrismLauncher/PrismLauncher/develop/launcher/ui/pages/global/AccountListPage.cpp)
- **Demo mode (Prism source):** if there is no account or the account does not own the game, the launcher asks "This account does not own Minecraft.\nYou need to purchase the game first to play the full version." … "Do you want to play the demo?" with a "Play Demo" button, then "Choose your demo mode player name"; an online account that cannot reach auth servers launches in offline mode ("The Minecraft authentication servers are currently unavailable, launching in offline mode") — [LaunchController.cpp](https://raw.githubusercontent.com/PrismLauncher/PrismLauncher/develop/launcher/LaunchController.cpp)
- Java demo limits (third-party summaries, not Mojang text): five in-game days ≈ 100 minutes, then the world locks; servers blocked, LAN allowed with only one demo account at a time — [Sportskeeda: how to play Minecraft demo](https://www.sportskeeda.com/minecraft/how-play-minecraft-demo-2023); [minecraft.net/demo](https://minecraft.net/demo)
- EULA: "a Microsoft account is required to purchase our games"; for minors "your parent or legal guardian is responsible for the creation of your Microsoft account"; no explicit "one account per person" clause was found in the fetched text, and "Using one Minecraft account on two computers won't let both join the same world" is from the wiki — [Minecraft EULA](https://www.minecraft.net/en-us/eula); [Minecraft Wiki: LAN world](https://minecraft.wiki/w/Tutorial:Setting_up_a_LAN_world)
- Third-party summaries say standard Java Edition is one account per person and that only Minecraft Education is licensed for shared classroom use; these are affiliate-style blogs, not Mojang — [gameslearningsociety summary](https://www.gameslearningsociety.org/wiki/can-you-share-a-minecraft-game/)
- **Gradle offline/caching (official):** `--offline` makes Gradle use cached modules "regardless of whether they are due for a recheck" and "makes no network requests for dependency resolution. If a required module is missing from the cache, the build fails"; cache lives at `$GRADLE_USER_HOME/caches` (default `~/.gradle/caches/modules-2`); to copy a cache "Copy `$GRADLE_USER_HOME/caches/modules-<version>` to the same relative structure on the destination", "Don't copy `*.lock` or `gc.properties` files", use compatible Gradle versions; `GRADLE_RO_DEP_CACHE` points at a read-only directory containing `modules-2`, read without locking so "several builds can use it at once", "incubating", and must not be a live Gradle installation's cache — [Gradle: Dependency caching](https://docs.gradle.org/current/userguide/dependency_caching.html)

- First Gradle sync "downloads about 500MB" and "can take 10-20 min on slow connections" (educator, 1.21 era); school firewalls must allow `gradle.org` and `services.gradle.org` — [jvdesignstudio workshop](https://jvdesignstudio.co.uk/workshops/minecraft-first-item-mod.html)
- Loom 1.18 (2026-09-20) "uses Gradle task-based run configurations by default" and replaced `fabric-loom-native` with Java 25's FFM API; 26.3 recommends Loom 1.17 and Gradle 9.6.0 — [fabric-loom releases](https://github.com/FabricMC/fabric-loom/releases); [Fabric for Minecraft 26.3](https://fabricmc.net/2026/09/15/263.html)
- Host JDK on this machine: `openjdk version "27" 2026-09-15` at `/usr/lib/jvm/java-27-openjdk`; no `~/.gradle` cache exists yet (nothing has been built here) — local inspection (no URL)
- Prism copy-instance supports symlinks/hardlinks and copy-on-write clones (BTRFS/XFS/ZFS…), "not available on FAT filesystems" — [Prism Launcher: Instance Copy](https://prismlauncher.org/wiki/help-pages/instance-copy/)
- A Tokyo coding-club Minecraft workshop capped classes at 10 students and ended with show-and-tell to families — [Tokyo Coding Club](https://tokyocodingclub.com/events/2025-05-18)

### Inferences
- **Accounts are the hard constraint.** Prism's rule means every shared laptop needs at least one Microsoft account that owns Java Edition before offline names can be used, and the EULA puts account creation for minors on parents; the defensible setup is one purchased account per laptop (owned by the makerspace, created by an adult), used to launch, with the kid choosing an offline display name — or, strictly, each kid's family account. Demo mode (≈100 minutes then locked) is unusable for a multi-week course but could cover a single taster session. The "offline name after a real login" approach is what Prism's own code permits; whether it satisfies Mojang's terms for a nonprofit classroom is a legal question these sources do not settle.
- **Dev-side runClient does not need Prism or an account at all**: Loom's run configuration launches the dev client from Gradle with Fabric's development flags; in the fetched sources nothing mentions logging in (Loom 1.18 added an *experimental* `microsoftLogin` task, which implies the default dev client is an unauthenticated/offline-named session). This means the modding sessions themselves can run entirely from the project folder, and Prism is only needed when kids want the built jar in "real" Minecraft with their friends. Unverified against a live Loom 1.18 run on this machine.
- **Offline workshop recipe:** on one laptop run the template once online (`./gradlew build runDatagen genSources` or at least `build` and a first `runClient` to fetch assets), then rsync `~/.gradle/caches` (minus `*.lock`, `gc.properties`) and `~/.gradle/wrapper` to each laptop with the same Gradle version, and run with `./gradlew --offline runClient`; alternatively put one copy on a USB/NFS share and set `GRADLE_RO_DEP_CACHE` (incubating). Loom also keeps Minecraft jars/assets in its own cache under `~/.gradle/caches/fabric-loom`, which the copy picks up. Expect ~500 MB+ per laptop based on the workshop's figure (26.3 assets are likely larger; unmeasured).
- **60–90 minutes is realistic only with a pre-built template repo and warm caches.** The UK workshop fits installs + first item in 90 minutes on fresh machines with good internet, so with JDK and caches pre-seeded, a "clone, edit, `./gradlew runClient`" loop leaves most of the session for the actual mod. Gradle configuration-cache is already on in the template, which helps repeat runs.
- Keep each kid's project in a per-kid folder (or a git branch each) on the shared laptop; Gradle's daemon and `run/` directory are per project, so two kids on one laptop at once would fight over the run dir.
- Avoid the Flatpak Java for Gradle; use the host `/usr/lib/jvm/java-27-openjdk` (or a JDK 25 if a tool complains), since the Flatpak runtime is sandboxed and its Java path is not visible to a host shell.

### Gaps
- No measured first-build or `runClient` start-up time on a modest Linux laptop for 26.3; the only figures are a 1.21-era "10–20 min on slow connections" and "about 500MB".
- Whether Loom 1.18's default `runClient` starts with no account (offline player name) was not confirmed by documentation; only the existence of an optional `microsoftLogin` task implies it.
- No official Prism wiki pages for "Installing Java" or "export instance" could be fetched (404s); the Java auto-download behaviour is confirmed from the Java Settings page and from the local install.
- No Mojang document found that addresses a nonprofit lending one licensed account to successive children on a shared laptop.

### Inferences
- Tracking sources, in order of signal: the Fabric blog post per drop (lists the breaking API changes), `fabricmc.net/develop` (version table), the docs version selector (when a 26.x build appears, the guides have been ported), and NeoForge's news feed if a NeoForge track is ever added. Minecraft Wiki's "Game drop" page is the calendar.
