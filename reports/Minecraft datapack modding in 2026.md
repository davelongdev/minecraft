# Data packs reach deeper, break harder in 26.3

*Research date 2026-10-12. Current release: Java Edition 26.3 "Wilderness Bound" (2026-09-15), data pack format 121.0, resource pack format 97.1. Sources are the Minecraft Wiki, Mojang changelogs, project repos and package registries, and the local 26.3 client jar; where only a secondary write-up was reachable (Nodecraft, Kore docs, GamingOnLinux), it's flagged.*

"Modding" Java Edition without Java in October 2026 means a data pack of roughly 55 JSON/NBT/mcfunction registries running on the logical server, paired (optionally) with a resource pack the client has to install itself. The surface is wide and widening: every 26.x drop has moved another hard-coded system into data (villager trades in 26.1; tool block-conversion, fuels, compost, and sign text as item components in 26.3) and added map-maker commands (`/time` on world clocks in 26.1, `/compute` and `/posteffect` in 26.3). The ceiling hasn't moved, though. A data pack still can't add a block, entity, or item *class*, draw a GUI, play a sound that isn't in vanilla or a client-installed pack, or see any player input beyond the seven movement keys, a handful of statistics, and clicks that land on an entity or block. The standard workarounds are display and interaction entities for fake blocks, `item_model`/`custom_model_data` for fake items, and dialogs, books, signs, and containers for UI. **26.3 is the biggest format break since 1.20.5**: predicates renamed `condition` to `type` and dropped `reference`/`block_state_property`/`value_check`, loot tables renamed `conditions`/`functions`/`function` to `condition`/`modifier`/`type`, `number_provider` split into context providers, `worldgen/configured_feature` became `worldgen/feature`, and sign click events now need `allow_op_features`. Two toolchains are alive (Python: Beet/Bolt/Mecha; TypeScript: Spyglass for editing, Sandstone for generation), Misode's generators lag one drop, and Trident and the old mc-build are dead. Distribution hasn't changed in principle since 1.13: a zip in `saves/<world>/datapacks/`, `/reload`, and for Realms a whole-world upload. Mojang's direction is data-driven-by-changelog rather than by roadmap, and nothing it has said in 2025–2026 (deobfuscation, a vague "creator platform") points to Java add-ons; for anything a data pack can't see, a 30-line client-only Fabric mod that sends `/trigger` remains the pragmatic hybrid.

## 26.3 lifts tool actions, fuels, and trades into data, then renames half the loot format

A 26.3 data pack is `data/<namespace>/` plus `pack.mcmeta`, and the wiki's current listing of what can live under it runs to functions and function tags, `.nbt` structures, advancements, `loot_table`, `item_modifier`, `predicate`, `recipe`, `slot_source`, the new `context_float_provider`/`context_int_provider`, `enchantment` and `enchantment_provider`, `dimension` and `dimension_type`, the whole `worldgen/` tree (biomes, carvers, features, density functions, noise, processor lists, structures, structure sets, template pools, world presets), mob variants (cat, chicken, cow, frog, pig, wolf, wolf sounds, zombie nautilus), cosmetics (`banner_pattern`, `painting_variant`, `trim_material`, `trim_pattern`, `decorated_pot_pattern`, `instrument`, `jukebox_song`), `chat_type`, `damage_type`, `dialog`, `villager_trade` and `trade_set`, `trial_spawner`, `world_clock`, `timeline`, `block_transformer`, `sulfur_cube_archetype`, GameTest `test_environment`/`test_instance`, and `tags/<registry>` for all of it ([Minecraft Wiki: Data pack](https://minecraft.wiki/w/Data_pack)). The distinction that matters day to day is which half reloads: `/reload` picks up tags, loot tables, recipes, advancements, item modifiers, predicates, functions, and structure templates, while dynamic-registry content (dimensions, worldgen, enchantments, dialogs, trades, clocks) needs a world reopen or server restart ([Minecraft Wiki: Data pack](https://minecraft.wiki/w/Data_pack)). For Command Forge that line is why `___rr` can hot-swap quest functions but any future custom dialog or dimension would mean leaving the world.

Functions themselves are stable: the wiki lists no function-format changes between 1.21 and 26.3, so macros, `$(key)` substitution rules (strings unquoted, numbers unsuffixed, booleans as 1/0, lists and compounds as SNBT), the 65,536-command `max_command_sequence_length` default, and `#minecraft:load` running before `#minecraft:tick` all still hold ([Minecraft Wiki: Function](https://minecraft.wiki/w/Function_(Java_Edition))). Everything around them moved. In 26.2 snapshot 3, entity predicates switched to a component-map-like format with namespaced keys (`type` → `minecraft:entity_type`), type-specific checks moved under `minecraft:type_specific/<x>`, a new `minecraft:entity_tags` sub-predicate arrived, and unknown keys are now rejected instead of ignored ([Minecraft Wiki: Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2); [Minecraft Wiki: Predicate](https://minecraft.wiki/w/Predicate)). Then 26.3 removed the `reference` and `block_state_property` condition types (the latter replaced by `match_block`) and split `value_check` into `int_value_check` and `float_value_check` ([Minecraft Wiki: Predicate](https://minecraft.wiki/w/Predicate)). On the loot side, Nodecraft's summary of the official notes has `minecraft:number_provider` replaced by `context_int_provider`/`context_float_provider`, `minecraft:reference` removed from loot functions and predicates (fields take IDs or inline objects directly), pool entries renaming `conditions` → `condition` and `functions` → `modifier`, loot functions renaming `function` → `type`, recipes now requiring `cookingtime` with smoker and blast furnace deriving from the furnace value, brewing becoming a `minecraft:brewing` recipe type, and the blunt warning that "Nearly all complicated datapacks will not work with this new format" ([Nodecraft, 2026-09-15](https://nodecraft.com/blog/game-news-tips/minecraft-java-26-3-wilderness-bound-is-out-what-it-means-for-your-server), secondary; the wiki's 26.3 page independently confirms the `context_*_provider` registries and the removal of the `#brewing_fuel` tag, [Minecraft Wiki: Java Edition 26.3](https://minecraft.wiki/w/Java_Edition_26.3)). Fabric's own 26.3 post corroborates the `worldgen/feature` rename and describes tilling, flattening, and stripping as "a vanilla data type" now ([Fabric for Minecraft 26.3](https://fabricmc.net/2026/09/15/263.html)).

The two 26.3 commands aimed squarely at map makers are `/compute` and `/posteffect`. `/compute <target> <provider> [<scale>|integer]` evaluates a number provider against a `default`, `block <pos>`, or `entity <selector>` context, with optional scaling (multiply and floor) and an `integer` mode that truncates between steps, so results can differ from float mode; division by zero fails the command. It arrived in 26.3 Snapshot 10 at format 118.0 ([Minecraft Wiki: Java Edition 26.3](https://minecraft.wiki/w/Java_Edition_26.3); [Mojang: 26.3 Snapshot 10](https://feedback.minecraft.net/hc/en-us/articles/48394701938573-Minecraft-Java-Edition-26-3-Snapshot-10)). For scoreboard-heavy packs like one-block_2's speedrun HUD, that's the first vanilla way to do a float calculation without a `c20`/`c2` constants dance. `/posteffect add|remove|clear|list` names a client-side post-processing shader (vanilla ships `blur`, `creeper`, `entity_outline`, `invert`, `spider`); the wiki is explicit that post effects live in resource packs, so the server "cannot confirm that one will apply" ([Minecraft Wiki: Commands/posteffect](https://minecraft.wiki/w/Commands/posteffect)). Both are 26.3-only; a pack that uses either can't declare a `min_format` below 121.

Item components kept growing through the year. 26.1 added `additional_trade_cost` and a `dye` component whose "presence … does not enable functionality", and let `blocks_attacks.bypassed_by` and `damage_resistant` accept IDs or lists rather than only tags; 26.2 added `sulfur_cube_content` and the attributes `air_drag_modifier`, `below_name_distance`, `bounciness`, `friction_modifier`, and `name_tag_distance`; 26.3 added `attack_animation`/`interact_animation`, `block_transformer` (a block-state provider plus sound, particle, loot, `consume_on_use`, and `item_damage_per_use`, which axes, hoes, and shovels "use by default"), `brewing_fuel`, `cooking_fuel`, `compostable`, `mob_visibility`, `sign_text_front`/`sign_text_back`, `villager_food`, and `waxed` ([Minecraft Wiki: Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1); [Minecraft Wiki: Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2); [Minecraft Wiki: Java Edition 26.3](https://minecraft.wiki/w/Java_Edition_26.3)). `block_transformer` is the one to notice: it means a "magic shovel that turns dirt into gold" is now a `/give` with a component, no entity tricks required, which is exactly the kind of toy a kids' program can hand out in one command.

Two smaller 26.x changes bite existing packs quietly. 26.1 pre-release 1 changed the `minecraft:nbt`, `minecraft:selector`, and `minecraft:object` text-component formats and gave `object` a `fallback` ([Minecraft Wiki: Pack format](https://minecraft.wiki/w/Pack_format)), which matters for one-block_2's `nbt`-component leaderboard names. And in 26.3 signs ignore `click_event`s unless the sign carries `allow_op_features` (existing signs are grandfathered) ([Nodecraft, 2026-09-15](https://nodecraft.com/blog/game-news-tips/minecraft-java-26-3-wilderness-bound-is-out-what-it-means-for-your-server)), the same gotcha this repo already hit in Command Forge. The practical reading: this repo's four game packs can carry `min_format: 107, max_format: 121` only because they use no predicate or loot JSON with renamed fields; the moment one gains a predicate, it either splits into two zips or uses the 1.20.2 overlay mechanism (`overlays` with per-format directories) to ship both shapes in one file ([Minecraft Wiki: Data pack](https://minecraft.wiki/w/Data_pack)).

## The server sees seven keys, a jump counter, and clicks that land on something

The hard limit behind every "can a data pack do X" question is that a data pack sees only what the logical server sees. The complete list of player input that is visible, as of 26.3, is short. Since 1.21.2 (24w36a) the `input` entity sub-predicate exposes seven booleans, `forward`, `backward`, `left`, `right`, `jump`, `sneak`, and `sprint`, matched against "the corresponding keybind the player is pressing" ([Minecraft Wiki: 24w36a](https://minecraft.wiki/w/Java_Edition_24w36a); [Minecraft Wiki: Predicate](https://minecraft.wiki/w/Predicate)). Custom statistics usable as scoreboard criteria add `minecraft:jump`, `sneak_time`, `crouch_one_cm`, `sprint_one_cm`, `swim_one_cm`, `aviate_one_cm`, `drop`, `open_chest`, `interact_with_<station>`, `play_time`, and `time_since_rest`, plus the `minecraft.used`/`mined`/`crafted`/`broken`/`picked_up`/`dropped`/`killed`/`killed_by` families keyed by resource location; there is no `use_item` stat, item use is `minecraft.used:<item>` ([Minecraft Wiki: Statistics](https://minecraft.wiki/w/Statistics)). Entity `flags` in predicates include `is_on_ground` and `is_flying` (1.21), with "new values" added in 1.21.11 that the wiki doesn't enumerate; this repo's `predicate/sneaking.json` confirms `minecraft:flags.is_sneaking` works in 26.3 ([project CLAUDE.md](/home/dave/minecraft/CLAUDE.md)). Mouse clicks become visible only when they hit something: an entity (the interaction entity's `attack`/`interaction` compounds, or the `player_hurt_entity`/`player_interacted_with_entity` advancement triggers, or `execute on attacker|target`) or a block (`item_used_on_block`, `placed_block`, `using_item`) ([Minecraft Wiki: Interaction](https://minecraft.wiki/w/Interaction)).

Everything else is invisible, and the community has stopped pretending otherwise. A 2025 feedback post asks for a `/detectinput`-style command because command blocks "can't read movement directly", and the working answers for drop (Q), swap-hands (F), and hotbar changes are plugins or client mods such as ControlCommands, a Fabric client mod that turns those keys into `/jump`, `/drop-item`, `/swap-hands`, and `/select-slot-N` ([feedback.minecraft.net](https://feedback.minecraft.net/hc/en-us/community/posts/35962989701517-Add-player-input-detection-to-commands); [Modrinth: ControlCommands](https://modrinth.com/mod/controlcommands)). The table below is the practical inventory for a tutorial author:

| Player action | Detectable? | Vanilla mechanism |
|---|---|---|
| W/A/S/D, space, shift, ctrl held | Yes | `input` sub-predicate (1.21.2) |
| Jump happened | Yes | `minecraft.custom:minecraft.jump` scoreboard criterion |
| Sneaking | Yes | `minecraft:flags.is_sneaking` or `sneak_time` |
| Drop item (Q) | Indirectly | `minecraft.custom:minecraft.drop` or `minecraft.dropped:<item>` |
| Right-click with item in hand | Only for items with a "use" | `minecraft.used:<item>` (carrot/warped fungus on a stick are the classics) |
| Hotbar slot change | Yes, by polling | `SelectedItemSlot` NBT compared tick to tick |
| Offhand swap (F) | By inference | Diff `Inventory`/`equipment` NBT between ticks |
| Left/right-click on air | No | Needs an interaction entity to be hit |
| Click on an entity/block | Yes | Interaction entity data, advancement triggers |
| Chat open, Esc, Tab, typing, GUI navigation | No | Nothing reaches the server |

That last row is why Command Forge quests 1–2 pass on trust and the rest are checked in-world (the outcome of the command the kid ran, not the keys they pressed), and it's the same verification model slicedlime's Command Training Grounds uses: re-run the learner's command in a hidden sandbox and inspect the result, never text-match ([local report: Teaching Minecraft Java commands](/home/dave/minecraft/reports/Teaching%20Minecraft%20Java%20commands.md)).

Faking blocks, GUIs, and entities is where the display-entity toolkit from 1.19.4 does all the work. Display entities are summon-only, carry a `transformation` (rotation, scale, translation), interpolate via `start_interpolation`/`interpolation_duration`, and since 1.20.2 `teleport_duration`; `block_display` shows any block state except fluids, `item_display` shows an item including resource-pack `item_model` models and has a slot `/item` and `/loot` can target, and `text_display` has alignment, a default `line_width` of 200, background colour, shadow, see-through, and opacity. Their limits define the trade: no hitbox, collision, or damage; they don't block placement or push entities; they're invisible for one tick after load; and they count toward the entity total ([Minecraft Wiki: Display](https://minecraft.wiki/w/Display)). A fake block is therefore a `block_display` for the look, an `interaction` entity for the clicks, and often a real barrier block for the collision. The interaction entity is invisible and invincible with configurable `width`/`height` (default 1), optionally plays a punch sound or arm swing with `response: true`, and stores the last `attack` and `interaction` compounds (player UUID plus timestamp); detection reaches about 22.6 blocks but is asymmetric, roughly 3.3 blocks on the negative X/Z side of the centre versus 19.3 on the positive side ([Minecraft Wiki: Interaction](https://minecraft.wiki/w/Interaction)), so a large "poor man's button" should sit with its centre toward the negative corner of the area players will click from. For invisible data anchors, the `marker` entity doesn't move, take damage, or collide, is not sent to the client, and is not counted in the entity total ([Minecraft Wiki: Display](https://minecraft.wiki/w/Display)); Command Forge's bedrock "marker blocks" could become markers if the per-island state ever outgrows a block check. Smithed formalises this whole pattern with a Custom Block library (v0.2.0), a Tag Specification for custom block/entity/item tags, and CMD ID Prefixing for `custom_model_data` ([Smithed Docs: Conventions](https://docs.smithed.dev/conventions/)).

Fake GUIs have exactly one modal option, dialogs (1.21.6), and they come with strings attached. Types are `notice`, `confirmation`, `multi_action`, `server_links`, and `dialog_list`; bodies hold `plain_message` and `item`; inputs are `text`, `boolean`, `single_option`, and `number_range`; actions include `run_command`, `suggest_command`, `show_dialog`, `copy_to_clipboard`, and `dynamic/run_command`, which fills a macro template from the inputs ([Minecraft Wiki: Dialog](https://minecraft.wiki/w/Dialog)). But `run_command` runs as the player (so privileged commands need an op), controls are disabled while a dialog is open, NBT/score/selector text components are not resolved inside dialogs (MC-297871), `custom` events do nothing on vanilla servers ([Minecraft Wiki: Dialog](https://minecraft.wiki/w/Dialog)), and every dialog header carries a warning button that "is always there" and offers to leave the world ([Kore docs: Dialogs](https://kore.ayfri.com/docs/dialogs), secondary; [feedback.minecraft.net](https://feedback.minecraft.net/hc/en-us/community/posts/36772820246029/comments/37097836540813)). The `/dialog` command hasn't changed since 1.21.7 ([Minecraft Wiki: Commands/dialog](https://minecraft.wiki/w/Commands/dialog)). Dave's 2026-10-11 ruling to keep Command Forge chat-only with physical buttons looks right on the evidence: for eight-year-olds, a yellow "custom screen" triangle that offers to quit the world is a trap, and "controls disabled while open" fights a tutorial whose whole point is pressing keys. The non-modal alternatives (clickable chat with `click_event`, written books, signs with `allow_op_features`, and real containers with `container_loot`/`lock`) remain the better fit, and the `lock` component is already doing GUI duty as one-block_2's key-gated chest.

## Resource packs supply the client half, but nothing guarantees they arrive

Everything a player sees or hears that isn't vanilla comes from `assets/<namespace>/` in a resource pack: `atlases`, `blockstates`, `equipment`, `font`, `items`, `lang`, `models`, `particles`, `post_effect`, `shaders` (`core`, `include`, `post`), `sounds`, `texts`, `textures`, and `waypoint_style`, plus root `sounds.json`; `pack.mcmeta` can declare languages, `overlays`, and `filter` ([Minecraft Wiki: Resource pack](https://minecraft.wiki/w/Resource_pack)). The piece that makes data-pack custom items work is the 1.21.4 item model definition system at `assets/<ns>/items/`: definitions of type `model`, `composite`, `condition`, `select`, `range_dispatch`, `empty`, `bundle/selected_item`, or `special`, switching on boolean properties (`broken`, `damaged`, `has_component`, `keybind_down`, `selected`, `using_item`, `custom_model_data` flags), select properties (`block_state`, `component`, `display_context`, `local_time`, `main_hand`, `custom_model_data` strings), and range properties (`count`, `damage`, `time`, `cooldown`, `custom_model_data` floats), with tint sources including `custom_model_data` colours. Its history is dense: `component` properties in 1.21.5, `player_head` and `oversized_in_gui` in 1.21.6, `copper_golem_statue` and `on_shelf` in 1.21.9, `swap_animation_scale` in 1.21.11, a `transformation` field and `bell`/`book`/`end_cube` special types in 26.1, and in 26.2 the removal of the `bed`, `standing_sign`, and `hanging_sign` special types because beds and signs became ordinary block models (Mojang's Slicer tool is referenced for migrating their textures) ([Minecraft Wiki: Items model definition](https://minecraft.wiki/w/Items_model_definition); [Minecraft Wiki: Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2)). On the data-pack side this is driven by the `item_model` component (nonexistent model renders the missing-texture cube) and `custom_model_data` with its `floats`, `flags`, `strings`, and `colors` lists ([Minecraft Wiki: Data component format](https://minecraft.wiki/w/Data_component_format)). The two-keys items in one-block_2 could get distinct models this way with a dozen lines of JSON, if the kids' machines had the pack.

The 26.x churn on the resource side is mostly in shaders and models. 26.1 rewrote the lightmap algorithm and changed the `LightmapInfo` uniforms (`BlockLightTint` and `NightVisionColor` added, `AmbientLightFactor` removed), let any block model use cutout or translucent textures based on pixel transparency, and allowed texture entries to be objects with `sprite` and `force_translucent`; 26.2 consolidated text shaders into `core/text` and `core/text_background` with `IS_GUI`/`IS_SEE_THROUGH`/`IS_GRAYSCALE` defines ([Minecraft Wiki: Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1); [Minecraft Wiki: Java Edition 26.2](https://minecraft.wiki/w/Java_Edition_26.2)). Core shaders are still overridable by packs in 26.x (community packs list 26.1/26.2 compatibility while replacing `particle.fsh`/`particle.vsh`), though Sodium needs a separate compatibility mod for them ([Modrinth: VNP](https://modrinth.com/resourcepack/vnp), secondary). The rendering platform underneath is moving: 26.2 added an experimental Vulkan backend with OpenGL "planned for removal once Vulkan is stable", and 26.3 swapped GLFW for SDL ([Fabric for Minecraft 26.2](https://fabricmc.net/2026/06/15/262.html); [Fabric for Minecraft 26.3](https://fabricmc.net/2026/09/15/263.html)); no Mojang statement on the long-term status of GLSL core shaders was found, so treat shader-dependent packs as the most fragile asset type.

Distribution is where resource packs are weaker than data packs. A pack reaches a client in three ways: the player drops it in their own `resourcepacks` folder (higher in the list overrides lower), a dedicated server sets `resource-pack` in `server.properties` to an HTTP(S) zip URL (players may decline unless `require-resource-pack=true`, which disconnects refusers), or the world embeds one, which "is not sent to LAN players"; Realms have "no way to force a pack" ([Minecraft Wiki: Resource pack](https://minecraft.wiki/w/Resource_pack)). 26.1's level-format change moved world resource packs into a `resourcepacks/` subfolder of the save, alongside `dimensions/<ns>/<dim>/`, `players/`, and namespaced `data/` ([Minecraft Wiki: Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1)). That almost certainly explains this repo's note that a world `resources.zip` "did not get applied in 26.3": the wiki's `resources.zip` text predates the move, and the file now belongs in `saves/<world>/resourcepacks/`. This is untested here and worth a five-minute check before the next class. The 26.3 `/posteffect` command makes the asymmetry concrete: a function can ask for the `creeper` effect, but only clients with a pack containing `assets/<ns>/post_effect/<name>.json` will show a custom one ([Minecraft Wiki: Commands/posteffect](https://minecraft.wiki/w/Commands/posteffect)). For a classroom of Prism-flatpak singleplayer instances, the honest position is that a resource pack is a per-machine install step, so anything a quest *depends on* should stay vanilla-rendered, and resource packs should be reserved for optional polish. The scale of the ecosystem shows where effort goes: Modrinth hosts 36,572 resource pack projects against 15,209 data packs and 77,111 mods ([Modrinth API](https://api.modrinth.com/v2/search?facets=%5B%5B%22project_type%3Aresourcepack%22%5D%5D&limit=1)).

## Two toolchains are alive; judge them by npm and PyPI, not GitHub Releases

The tooling question has a clean answer in October 2026, provided you look at the right signals. Spyglass's GitHub "latest release" is still v3.2.0 from 2020, which would suggest a dead project; the npm package `@spyglassmc/core` 0.4.56 was published 2026-09-15 and the VS Code extension `SPGoding.datapack-language-server` ("Datapack Helper Plus") hit v4.13.0 the same day with about 359,000 cumulative installs, because Spyglass *is* DHP v4 and the old `vscode-datapack` repo (archived 2024-05-31) points to it ([GitHub API: SpyglassMC/Spyglass](https://api.github.com/repos/SpyglassMC/Spyglass); [npm: @spyglassmc/core](https://registry.npmjs.org/@spyglassmc/core); [VS Code Marketplace](https://marketplace.visualstudio.com/items?itemName=SPGoding.datapack-language-server)). The `MinecraftCommands/syntax-mcfunction` grammar repo recommends it as the language server for validation and autocomplete ([GitHub: syntax-mcfunction](https://github.com/MinecraftCommands/syntax-mcfunction)). Bolt, Mecha, and Lectern were all archived on 2025-12-08 with "Development moved to the beet monorepo", which also looks like a death notice until you see PyPI `bolt` 0.51.0 (2026-09-10), `mecha` 0.106.0 (2026-09-19), and `beet` 0.119.1 (2026-10-02) ([GitHub: mcbeet/bolt](https://github.com/mcbeet/bolt); [PyPI: bolt](https://pypi.org/pypi/bolt/json); [PyPI: mecha](https://pypi.org/pypi/mecha/json); [PyPI: beet](https://pypi.org/pypi/beet/json)).

My recommendations for this repo follow from what actually hurts. The number-one debugging pain recorded in CLAUDE.md is that a function with a parse error silently fails to load and you find out from `latest.log`; that is precisely what a language server fixes at edit time, so Spyglass is the one tool worth adopting now. It's an LSP server distributed as a VS Code extension; whether the bare `@spyglassmc` language server runs cleanly under nvim's LSP client wasn't researched and should be tested before committing (a VS Code install just for mcfunction is a defensible fallback). Second, `tools/gen_lessons.py` is already a bespoke Beet: Python emitting mcfunctions and dialog JSON. If it grows another engine's worth of generated functions (the tile game is heading there), Beet's project model plus Bolt's Python-in-mcfunction will beat extending it, and it lives on PyPI so it fits the existing Python tooling. Mecha also offers compile-time command validation, which is a second line of defence against silent load failures. Third, keep copying predicate and loot shapes from the 26.3 jar as CLAUDE.md already prescribes; Misode's generators are excellent but showed 26.2 at fetch time, and 26.3 is the drop where the shapes changed. Fourth, skip Sandstone, JMC, mcb, and Kore for this project: each is a second language the kids would never see, and none is as widely used as the two stacks above. Finally, no 26.x "pack format upgrader" exists as far as the research could find, and whether Spyglass or Beet automates the 107→121 renames was not confirmed, so budget the migration as hand work.

## Zips in `datapacks/` remain the only universal channel

How a pack reaches players hasn't changed in shape since 1.13: drop the zip or folder into the world's `datapacks/` folder (via the world-creation screen's Data Packs button, or Edit → Open world folder for an existing world, or the dedicated server's `world/datapacks`), then `/reload` (cheats) or F3+T, and verify with `/datapack list enabled`; load order lives in `level.dat` and is changed with `/datapack`, last pack wins for duplicate files, and tags merge unless `"replace": true` ([Minecraft Wiki: Tutorial: Installing a data pack](https://minecraft.wiki/w/Tutorial:Installing_a_data_pack); [Minecraft Wiki: Data pack](https://minecraft.wiki/w/Data_pack)). Realms are the exception that constrains everything: a data pack reaches a Java Realm only by uploading the whole world (one feedback poster complains that updating "a 4MB pack on a realm" means downloading a 500 MB world), worlds with experimental settings "cannot be uploaded to Realms", and Realms accept no mods or plugins ([feedback.minecraft.net](https://feedback.minecraft.net/hc/en-us/community/posts/360023754951/comments/360013179971); [Minecraft Wiki: Data pack](https://minecraft.wiki/w/Data_pack); [Windows Central Realms FAQ](https://windowscentral.com/gaming/minecraft-realms-faq-how-to-setup-price-and-other-questions-answered)). Vanilla 26.2 added peer-to-peer "Online" hosting of singleplayer worlds with a Friends List, described as "a first version" ([Mojang: 26.2 Snapshot 7](https://feedback.minecraft.net/hc/en-us/articles/45790287863437-Minecraft-Java-Edition-26-2-Snapshot-7)), which is the first vanilla channel other than LAN where a host's data pack runs for remote friends with no server to administer; it's worth a test as a way for kids to play each other's games from home. The reason this repo's zip-plus-world-zip workflow is the right one is simply that resource packs and command blocks/functions/data packs are the only customization tier that works on every Java host: singleplayer, LAN, Online, Realms, and any server.

Public distribution has consolidated on Modrinth, and the leaders there reveal the practical pattern for reach. Modrinth lists 15,209 data pack projects, of which 2,306 declare 26.3 support four weeks after release versus 3,928 for 26.2, 4,076 for 26.1, and 5,670 for 1.21.11; the top packs by downloads (VeinMiner 93.7M, Terralith 24.1M, Dungeons and Taverns 21.8M, Towns and Towers 18.3M, Tectonic 17.1M) all carry `fabric`/`forge`/`neoforge`/`quilt`/`bukkit` loader tags alongside `datapack`, meaning one `data/` folder shipped twice, as a zip for vanilla worlds and as a jar for modded launchers ([Modrinth API: datapack search](https://api.modrinth.com/v2/search?facets=%5B%5B%22project_type%3Adatapack%22%5D%5D&limit=1); [Modrinth API: by downloads](https://api.modrinth.com/v2/search?facets=%5B%5B%22project_type%3Adatapack%22%5D%5D&index=downloads&limit=8)). The 15% 26.3 adoption versus 26% for 26.2 is the format break showing up in the numbers; expect that gap to close more slowly than usual. Planet Minecraft and Vanilla Tweaks both blocked automated fetches, so their counts and 26.3 status couldn't be verified (a search snippet suggested about 23,000 Planet Minecraft data packs; third-party mirrors of Vanilla-Tweaks-style packs showed 26.2 builds and no 26.3 ones).

The conventions that let packs coexist come from Smithed, Gamemode 4, and Bookshelf rather than Mojang. Lantern Load is "the convention nearly every serious datapack library follows to control load order and to advertise its version", publishing a pack's version as three fake players on a `load.status` objective, and Bookshelf, the Smithed libraries, GM4, and PlayerDB all depend on it ([Kore docs: Lantern Load](https://kore.ayfri.com/docs/guides/lantern-load), secondary). Smithed adds a Pack IDs convention (extra `pack.mcmeta` metadata), Namespacing for tags and scores, CMD ID Prefixing for `custom_model_data`, Vanilla Overrides for Weld-mergeable asset overrides, and a "Data Pack Menu Dialog" meant to be "the mod menu for data packs"; Weld merges packs under custom rules (Rule, Source, Priority, Condition) ([Smithed Docs](https://docs.smithed.dev/); [Smithed Docs: Conventions](https://docs.smithed.dev/conventions/)). A community request for "Official Docs / GitHub Samples for Minecraft Java Datapacks & Resource Packs" captures the state of documentation: scattered across community wikis and third-party tools, with nothing first-party ([feedback.minecraft.net](https://feedback.minecraft.net/hc/en-us/community/posts/39599717910541-Official-Docs-GitHub-Samples-for-Minecraft-Java-Datapacks-Resource-Packs)). For this repo, the conventions worth adopting are the cheap ones already half-followed: namespaced objective prefixes (`tut_`, `ob_`), one namespace per pack, and `internal/` for helpers. Lantern Load matters only if the packs start depending on Bookshelf or Smithed libraries or get published for others to combine; the `___` autocomplete-sorting prefix is a classroom convention with no public equivalent and should stay. One caution carried over from the Modrinth data: the one-block and one-block_2 packs share the `oneblock` namespace, which is exactly the collision Smithed's Pack IDs exist to prevent, and a rename to `oneblock2` would cost a `sed` and remove the "install only one at a time" footnote.

## Mojang lifts systems into data by changelog, not roadmap, and leaves input to mods

Mojang has never published a "data-driven" strategy document, but the 26.x changelogs make the direction unmistakable. 26.1 made villager trades data-driven (`villager_trade` with `wants`, `gives`, `max_uses`, `reputation_discount`, `xp`, `merchant_predicate`; `trade_set` with `trades`, `amount`, `allow_duplicates`) and introduced world clocks as a registry; 26.3 turned axe/hoe/shovel behaviour into the `block_transformer` component, fuels into `cooking_fuel`/`brewing_fuel` (deleting the `#brewing_fuel` tag), compost into `compostable`, and biome spawn settings into environment attributes ([Minecraft Wiki: Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1); [Minecraft Wiki: Java Edition 26.3](https://minecraft.wiki/w/Java_Edition_26.3); [Nodecraft](https://nodecraft.com/blog/game-news-tips/minecraft-java-26-3-wilderness-bound-is-out-what-it-means-for-your-server)). The same year brought the pack-format policy that makes this bearable: from 88.0 (1.21.9), formats carry a minor version and "non-breaking changes raise the minor version, not the major one", with packs declaring supported ranges via `min_format`/`max_format` ([Minecraft Wiki: Pack format](https://minecraft.wiki/w/Pack_format)). The cadence is the cost: 26.3 alone burned formats 108 through 121 across ten snapshots and three pre-releases, and four drops a year (26.1 March, 26.2 June, 26.3 September, 26.4 next) mean a pack author who follows snapshots is migrating every few weeks. Mojang is also pairing new power with guardrails, visibly in the permanent dialog warning button and in 26.3's decision to disable sign click events by default behind `allow_op_features`.

The one structural announcement for Java modding in the period helps mods, not data packs. On 2025-10-29 Mojang announced it would "remove obfuscation completely" because "Modding is at the heart of Java Edition – and obfuscation makes modding harder", with "No changes to EULA" and a LICENSE file now inside the jar; 26.1 (2026-03-24) is the first unobfuscated release ([Mojang: Removing obfuscation in Java Edition](https://www.minecraft.net/en-us/article/removing-obfuscation-in-java-edition); [Minecraft Wiki: Java Edition 26.1](https://minecraft.wiki/w/Java_Edition_26.1)). Minecraft LIVE September 2026 added only that Mojang "will begin an official creator platform", with no date, details, or mention of Java, plus a coming "sound effects pack" type of resource pack ([Minecraft Wiki: Minecraft Live September 2026](https://minecraft.wiki/w/Minecraft_Live_%E2%80%93_September_2026)). Add-ons remain a Bedrock concept: Microsoft's own docs call Bedrock behavior packs "equivalent to Java's data packs" while noting that "Java can create custom fonts and GLSL shaders, while Bedrock cannot. Bedrock can create custom particles and fogs, while Java cannot", and Bedrock's `@minecraft/server` scripting API (stable 2.10.0) now registers custom commands, block and item components, dimensions, and world clocks from JavaScript ([Microsoft: Differences between Bedrock and Java](https://learn.microsoft.com/en-us/minecraft/creator/documents/differencesbetweenbedrockandjava); [Microsoft: @minecraft/server](https://learn.microsoft.com/en-us/minecraft/creator/scriptapi/minecraft/server/minecraft-server?view=minecraft-bedrock-stable)). No source found promises or rules out a Java equivalent; that's absence of evidence, but after two years of Bedrock add-ons and three LIVE shows in 2026 with nothing on the subject, the realistic planning assumption is that Java data packs stay JSON-and-mcfunction with no scripting layer, and that the gap between what a pack can *express* (more every drop) and what it can *perceive* (the same seven keys) keeps widening.

That gap is where the hybrid pattern earns its place, and the research pinned down the minimal version. Key mappings "only exist on the client side" in Fabric, and the 26.3 client jar exposes `ClientPacketListener.sendCommand(String)` on `LocalPlayer.connection`, which is exactly what pressing Enter on `/trigger …` does ([Fabric Docs: Key Mappings](https://docs.fabricmc.net/develop/key-mappings); local `minecraft-26.3-client.jar`, inspected 2026-10-12). A client-only Fabric mod is therefore one class: register a `KeyMapping` for N with `KeyMappingHelper`, and in `ClientTickEvents.END_CLIENT_TICK` loop `while (key.consumeClick()) client.player.connection.sendCommand("trigger tut_key_n")`. The data pack side is pure vanilla: a `trigger` objective, `scoreboard players enable @a tut_key_n` each tick, and a tick function that reacts and resets. The server can't tell it from typing, so it works on vanilla servers, and the pack still loads without the mod (the key just does nothing). BindCommands already does the generic version of this (613K downloads, builds through 26.3, client-side key→command with an optional server half that only syncs bindings), so the zero-Java route is three jars (BindCommands, Mod Menu, Fabric API) and a config entry mapping N to `/trigger tut_key_n` ([Modrinth: BindCommands](https://modrinth.com/mod/bindcommands); [GitHub: devs-immortal/bind-cmd](https://github.com/devs-immortal/bind-cmd)). Bundling the data pack inside a mod jar is possible on both loaders (NeoForge auto-applies every mod's `data/` as a pack and generates `pack.mcmeta` at runtime) but changes the install story to `mods/` and loses the one-zip-for-two-versions property ([NeoForge Docs: Resources](https://docs.neoforged.net/docs/resources/)); for this project it's not worth it unless mods are adopted for other reasons. The teaching argument cuts the same way: Java 26.2 has 99 player-reachable commands, about 15 more than 1.19.3 (macros, `/return`, `/random`, `/dialog`), and Bedrock lacks `/data`, `execute store`, NBT on `/give`/`/summon`, and `/trigger`, so the variables → conditionals → functions → return values → data ladder Command Forge climbs is only available in Java, and only in chat and data packs ([local report: Teaching Minecraft Java commands](/home/dave/minecraft/reports/Teaching%20Minecraft%20Java%20commands.md)). Keep the tutorial a data pack; let a tiny client mod handle the keyboard if the jump-to-continue workaround ever wears thin.

## Conclusion

The useful mental model for 2026 is that a data pack is a *server-side content format with a function language attached*, not a scripting platform, and Mojang is expanding the content format at a pace that makes the function language's limits more visible, not less. Each drop converts another hard-coded system into components or registries, which means a growing share of what a kids' program wants ("a shovel that only digs dirt", "a tool that turns dirt to gold", "a villager who sells quest items") is a `/give` or a JSON file rather than a trick with entities. At the same time, the perceptual boundary is fixed by the protocol: seven keys, statistics, and clicks on things. Designing a tutorial so every check is an in-world outcome rather than a detected keypress isn't a workaround for a missing feature, it's the correct architecture for this platform, and slicedlime's map reached the same conclusion independently.

The 26.3 break also changes how to think about compatibility. The `min_format`/`max_format` range is a promise that your pack uses no renamed field across the whole range, and the only way to keep that promise cheaply is to keep game packs on the stable subset (functions, scoreboards, structures, components) and push anything with predicate or loot JSON onto a single target version or into overlays. Spyglass turns "the function silently didn't load" into a red squiggle; Beet is waiting when `gen_lessons.py` outgrows itself; and for the classroom the deliverable stays a zip in `datapacks/` and a re-zipped world, because that's the only path that works on every Java host, including the peer-to-peer Online hosting 26.2 introduced. The open items worth a quick check before the next class are whether `saves/<world>/resourcepacks/` is where a world pack now has to live in 26.3, and whether the bare Spyglass language server runs under nvim.
