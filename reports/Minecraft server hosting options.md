# Metered hosting beats always-on for class-time Minecraft

**Host the Newburgh Creates games on exaroton, as one Fabric 26.3 server per game, and expect to pay roughly $3–6 a month.** exaroton is the only option in the field that bills by the GB-hour (1 credit = €0.01 per GB per hour), lets any number of servers run at the same time from one shared credit pool, accepts your own Fabric jar and datapack zips through its web file manager, and has a North America region, so three 4 GB game servers used three hours a week cost about €1.60 a month in play time ([exaroton Pricing](https://support.exaroton.com/hc/en-us/articles/360019687657-Pricing)). The runner-up is Kinetic Hosting's 12 GB plan at **$12.99/month**, which can be split into up to four always-on servers at no extra cost and explicitly supports Fabric, datapacks, and a Java-version toggle, but whose reputation nobody in this research could vet ([Kinetic order page](https://www.kinetichosting.com/game-servers/minecraft/order)). Four of the thirteen candidates fail the hard requirement outright: Java Realms, Aternos, and the CurseForge Servers beta can't load a custom server-side mod jar, and the vanilla "Online" peer-to-peer feature was pulled from 26.2 before release and hasn't returned. Modrinth Hosting, GodLike, the big four managed brands, and a VPS all work technically, but they charge per server or per month whether or not a class is in session, which puts three concurrent games at $30–62/month, and GodLike's billing record and Modrinth's out-of-stock plans add risk. Architecturally, keep each game in its own server process rather than stacking dimensions in one server: datapacks, scoreboards, and command storage are per save, not per dimension, so the repo's two `oneblock` packs can't coexist in one world. A Velocity proxy is optional and best skipped on a managed host. The dialog `dynamic/custom` route to a server-side mixin is confirmed to bypass the "Confirm Command Execution" screen, and per-player entity hiding is a tracker mixin, not a Fabric API event; both only need a host that runs your jar, which is exactly the filter above.

## Four of thirteen options can't run the mod at all

The requirement that does the most work in this decision is the custom server-side Fabric mod, the "instructor plumbing" that `Minecraft modding approaches compared.md` recommends and whose toolchain (JDK 25, Fabric Loader 0.19.5) `Minecraft and Hytale Java mod setup.md` already covers. Any host that can't take an arbitrary jar in `mods/` is out, no matter how cheap.

Java Realms is the clearest case. It runs Mojang's vanilla server only, and the wiki states flatly that "Mods and plugins cannot be installed"; nothing in the 26.2 or 26.3 release notes changes that, and the 26.3 Realms work was limited to invite links, render-distance sliders, and new regions ([minecraft.wiki: Realms](https://minecraft.wiki/w/Realms); [26.3 release notes](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-3)). Even as a datapack-only host it fits badly: **$7.99/month buys the owner plus 10 players and three world slots of which exactly one is live**, so "several games at once" means several Realms, and a 20-kid class doesn't fit in one ([minecraft.wiki: Realms](https://minecraft.wiki/w/Realms)). Pack updates mean downloading the whole world, editing it, and re-uploading it with the Realm closed, a complaint that has sat on the feedback forum for years ([feedback.minecraft.net](https://feedback.minecraft.net/hc/en-us/community/posts/360023754951/comments/360013179971)), and the Realm always runs the newest release, so you can't pin 26.3 for a term. The vanilla "Online" option (host a singleplayer world for Friends-List friends over peer-to-peer) shipped only in 26.2 Snapshots 7–8; Mojang removed it in 26.2 Pre-Release 1 on 2026-05-26 because it "did not meet the quality bar", and it's absent from 26.2, 26.3, and the 26.4 snapshots ([minecraft.wiki: Online (P2P)](https://minecraft.wiki/w/Online); [26.2 Pre-Release 1](https://minecraft.wiki/w/Java_Edition_26.2_Pre-Release_1)). Even when it returns, it's one world on one host's laptop for friended accounts, not a classroom host.

Aternos is free and offers Fabric, but it refuses custom jars by design: "It's only possible on Aternos to install mods from our mods library. You can't upload mods you've downloaded from the web", and there's no FTP because custom code could defeat the auto-shutdown that keeps the service free ([Aternos: Install mods](https://support.aternos.org/hc/en-us/articles/360027235871-Install-mods-Minecraft-Java-Edition); [Aternos: Uploading files](https://support.aternos.org/hc/en-us/articles/360027235831-Uploading-files-and-FTP-access)). Datapacks would upload fine, but servers start through a capacity queue with a confirm click and sleep when empty, so class start times can't be guaranteed ([Aternos: Queue](https://support.aternos.org/hc/en-us/articles/360026950812-Queue)). Aternos itself points paying users to exaroton, which it also operates.

CurseForge Servers is new (rollout began 2026-09-08), is a Shockbyte server billed by Tebex at **$12/$24/$36 for 4/8/12 GB**, and at launch can only be created from a CurseForge modpack that already has a server pack; custom packs, plan changes, and longer billing terms are all "coming" ([CurseForge blog](https://blog.curseforge.com/the-easiest-way-to-play-modded-minecraft-with-your-friends-curseforge-servers-are-here/); [CurseForge support](https://support.curseforge.com/support/solutions/articles/9000278741-setting-up-a-curseforge-minecraft-server)). The server does land in a normal Shockbyte panel with SFTP, so a teacher could in principle repurpose it, but that's undocumented, and the buyer must be 16+ under Tebex terms ([Tebex Terms](https://checkout.tebex.io/terms)). If you want Shockbyte, buy Shockbyte.

## One server per game, and the proxy is optional

Both ways of running several games at once work on 26.3, but they're not equivalent. Architecture A (several Fabric servers, optionally behind a Velocity proxy) is fully supported: Velocity's compatibility page lists "Minecraft 1.7.2 through 26.3", the 26.3 pull request merged on 2026-09-14, Velocity 4.3.0 requires Java 25, and FabricProxy-Lite v2.12.0 declares 26.1 through 26.3 ([Velocity server compatibility](https://docs.papermc.io/velocity/server-compatibility/); [PaperMC/Velocity PRs](https://github.com/PaperMC/Velocity/pulls?q=26.3); [Velocity getting started](https://docs.papermc.io/velocity/getting-started/); [Modrinth: FabricProxy-Lite versions](https://api.modrinth.com/v2/project/fabricproxy-lite/version)). Architecture B (one Fabric server with several worlds or datapack dimensions) also works; Multiworld 1.14.2 for 26.3 was published 2026-10-09, though its own changelog says "Portals Currently broken" ([Modrinth: Multiworld](https://modrinth.com/mod/multiworld)).

The deciding fact is scoping. Datapacks are installed per world save, and "If a file exists in multiple data packs only the file in the last data pack is used" ([minecraft.wiki: Data pack](https://minecraft.wiki/w/Data_pack)); the 26.3 server exposes one `ServerScoreboard` and one `CommandStorage` per `MinecraftServer`, not per dimension (checked against the 26.3 jar with `javap`; the Yarn javadoc shows the same shape for 1.21.11 ([Yarn: MinecraftServer](https://maven.fabricmc.net/docs/yarn-1.21.11+build.4/net/minecraft/server/MinecraftServer.html))). In one server, every game's functions, tags, `load`/`tick` hooks, `trigger` objectives, and storage namespaces are global, one `/reload` or one broken predicate takes down every game at once, and `one-block` and `one-block_2`, which share the `oneblock` namespace, overwrite each other file by file. Adding a datapack dimension to a running server also needs a restart, because `/reload` doesn't apply dimension definitions ([minecraft.wiki: Commands/reload](https://minecraft.wiki/w/Commands/reload)). **Separate servers give each game its own save, pack set, scoreboard, storage, whitelist, and crash domain**, which matches how the packs in this repo are already written (each assumes it owns the world around the origin). The cost is N Java 25 processes at roughly 2–3 GB heap each; the vanilla wiki's guidance is 2 GB for 5–10 players and 4 GB for 10+, with single-core speed mattering most since "the server uses up to about three cores" ([minecraft.wiki: Server/Requirements](https://minecraft.wiki/w/Server/Requirements)).

A Velocity proxy adds one address and `/server <name>` hopping (granted to everyone by default ([Velocity built-in commands](https://docs.papermc.io/velocity/built-in-commands/))), but it also forces the backends to `online-mode=false` with modern forwarding and a shared secret, which the Velocity docs call insecure until the backends are unreachable except through the proxy ([Velocity forwarding](https://docs.papermc.io/velocity/player-information-forwarding/)). On a VPS, that's a firewall rule; on a managed host, every split or sub-server has a public port, so you're relying on FabricProxy-Lite's secret check or exaroton's preinstalled BungeeGuard ([exaroton: proxies](https://support.exaroton.com/hc/en-us/articles/4404724229137-Using-Minecraft-proxies-on-exaroton)). For a class of 10–20 kids who can keep three entries in their server list, direct-join addresses per game are simpler and keep `online-mode=true` everywhere, so the proxy is a later refinement, not a starting requirement. Skipping it also sidesteps the fact that CrossStitch, the mod Velocity recommends for custom command argument types, has no 26.x build ([Modrinth: CrossStitch versions](https://api.modrinth.com/v2/project/crossstitch/version)).

### The custom-click route works, and so does per-player hiding

The mod's two planned jobs both check out. A dialog `dynamic/custom` action "will build a `minecraft:custom` event using all input values" packed into an NBT compound, and the static `custom` action "has no effect on vanilla servers" ([minecraft.wiki: Dialog](https://minecraft.wiki/w/Dialog)). In the 26.3 jar, the client sends `ServerboundCustomClickActionPacket(Identifier id, Optional<Tag> payload)`, `ServerCommonPacketListenerImpl.handleCustomClickAction` runs it on the server thread, and `MinecraftServer.handleCustomClickAction` merely logs it. The "Confirm Command Execution" screen (`multiplayer.confirm_command.permissions_required` in the 26.3 language file) belongs to `run_command` actions that need elevated permissions, which is why the npc-game forms currently require op; a `dynamic/custom` button is not a command, so no permission check and no confirmation screen apply. Fabric API has no dialog or custom-click module (Paper does, but Paper isn't Fabric ([Purpur javadoc: DialogAction.CustomClickAction](https://purpurmc.org/javadoc/io/papermc/paper/registry/data/dialog/action/DialogAction.CustomClickAction.html))), so the mod needs a mixin at the listener level, where the player is available, that copies the payload into `CommandStorage` and runs the existing macro function with `Commands.performPrefixedCommand`. Treat the payload as untrusted; vanilla decodes it with an untrusted codec, and the datapack side changes only the action type and id. No published Fabric example of this hook was found, so the first build is pathfinding.

Per-player visibility is a tracker mixin. Fabric API's `EntityTrackingEvents.START_TRACKING` "is called after the entity's spawn packet is sent to the player", so it can't cancel a spawn ([Fabric API 0.163.0+26.3 javadoc](https://maven.fabricmc.net/docs/fabric-api-0.163.0+26.3/net/fabricmc/fabric/api/networking/v1/EntityTrackingEvents.html)); the right layer is `ChunkMap$TrackedEntity.updatePlayer(ServerPlayer)`, which is where Vanish (server-side, supports 26.3) and Ghosty (1.21.1 only) operate ([Modrinth: Vanish](https://modrinth.com/mod/vanish); [Modrinth: Ghosty](https://modrinth.com/mod/esp-ghosty)). The one rule that keeps vanilla clients joinable is to register nothing: Fabric's registry sync "kicks the client with a warning if any block, item, fluid, or block entity is missing", and a server-only data component has caused the same mismatch ([FabricMC registry-sync issue summary](https://lightrun.com/answers/fabricmc-fabric-fabric-registry-sync-cannot-be-skipped); [Modrinth changelog](https://modrinth.com/project/WC4UgDcZ/version/vAm2WOgJ)). Mixins, events, commands, storage, and packet filtering are all fine. Note that Command Forge's 1024-block island spacing already gives per-player isolation with no mod; the visibility mixin only matters if games must share one space.

exaroton's model is unusual enough to spell out. "Running a server on exaroton costs 1 credit per GB of RAM per hour", RAM ranges 2–16 GB, billing is prorated to a hundredth of a credit, and the only standing charge is a 10-credit (€0.10) monthly storage fee per server that's waived once that server burns 10 credits in the month ([exaroton Pricing](https://support.exaroton.com/hc/en-us/articles/360019687657-Pricing)). One 4 GB server for three hours a week is about 52 credits a month; three of them are about €1.56, and a 10-week term with three servers is roughly €3.60 before any teacher prep time. Credit pools let "all assigned servers automatically use those credits", share access grants a co-teacher per-server Start/Stop/Console/Files rights without sharing the login, servers can autostart when a player joins and autostop when empty, and backups go to a linked Google Drive at no charge and no cap ([Credit pools](https://support.exaroton.com/hc/en-us/articles/11567970055581-Credit-pools); [Share access](https://support.exaroton.com/hc/en-us/articles/360019857358-Share-access); [Autostop](https://support.exaroton.com/hc/en-us/articles/360019687297-Stop-your-server-automatically-when-it-s-empty); [Backups](https://support.exaroton.com/hc/en-us/articles/360019857278-Creating-and-restoring-backups)). Custom server software uploads cover Fabric (you pick the Minecraft version and point at `fabric-server-launch.jar`), and "custom mods and plugins" go through the browser uploader, though neither works in the free trial ([Custom server software](https://support.exaroton.com/hc/en-us/articles/360019687717-Uploading-custom-server-software-and-modpacks); [Uploading files](https://support.exaroton.com/hc/en-us/articles/360019687677-Uploading-files-and-FTP-access)). The region is a broad "North America" with no city choice ([Server region](https://support.exaroton.com/hc/en-us/articles/21659706549789-Server-region)), the 10 GB per-server cap exists because each server is moved between storage and a host machine on every start, which is also why startup takes a moment ([Maximum server size](https://support.exaroton.com/hc/en-us/articles/360019687317-Maximum-allowed-server-size)), and purchases run through Paddle or Tebex with a 14-day refund on unused credits ([exaroton ToS](https://aternos.gmbh/en/exaroton/terms)). For void worlds measured in tens of megabytes, none of those limits bite. The genuine unknowns are whether 26.3 is already in the panel's software list (custom upload is the fallback) and exaroton's uptime record, for which no public score turned up.

Kinetic is the cheapest always-on answer by a wide margin: its order page lists **4 GB $4.99, 8 GB $7.99, 12 GB $12.99**, with the 8 GB plan carrying 6 CPU threads, NVMe, 5 backup slots, 60 GB storage, "4 splits", and the line "Split Your Server: Allocate unused resources to additional servers at no extra cost", plus US locations in Texas, Washington DC, Florida, and San Francisco and a 7-day any-reason refund ([Kinetic order page](https://www.kinetichosting.com/game-servers/minecraft/order)). It names Fabric and datapacks explicitly and exposes a Java-version toggle, which matters because 26.x needs Java 25 and Multicraft-era panels at Apex and Shockbyte don't advertise one. What's missing is any independent reliability data and the split rules (minimum RAM per split, ports, whether each split can pick its own Java), so it earns runner-up on paper and has to prove itself inside the refund window.

The known brands cost three times as much for this use because they sell one server per subscription. Apex renews at $14.99 for 4 GB and $27.99 for 8 GB, Shockbyte Premium lists $15.99 and $31.99 with a standing 30 % recurring promo, BisectHosting runs about $3/GB ($11.99 for 4 GB), and Nodecraft Lite is $11.92–13.98 for 4 GB with Pro at $19.98 ([Apex pricing](https://apexminecrafthosting.com/pricing/); [Shockbyte](https://shockbyte.com/games/minecraft-server-hosting); [iTechGuides Bisect vs Nodecraft](https://www.itechguides.com/best/minecraft-server-hosting/compare/bisecthosting-vs-nodecraft/)). Their "instances" store up to two or three server setups but run one at a time ([Shockbyte KB: instances](https://shockbyte.com/help/knowledgebase/articles/how-to-create-and-switch-instances-on-your-server-panel); [Nodecraft KB: instances](https://nodecraft.com/support/knowledgebase/nodepanel/what-are-instances-and-how-to-use-them)), which solves a class that rotates games week to week, not groups playing side by side. Two things are still worth a look: BisectHosting's Craft Together Project offers schools, libraries, and "other small learning communities" free servers, eligibility unpublished ([Bisect blog](https://www.bisecthosting.com/it-it/blog/bisecthosting-presents-the-craft-together-project)), and Shockbyte's 2026 Trustpilot pattern is "slow ticket responses", with one October report of a 14-day wait, which is the wrong failure mode for a 4 pm class ([Trustpilot: Shockbyte](https://www.trustpilot.com/review/shockbyte.com)).

Modrinth Hosting is the most Fabric-native panel and documents datapack uploads step by step, but on 2026-10-18 all three preset plans ($10/$15/$20 a month billed quarterly for 4/6/8 GB) were out of stock with only a custom plan "starting at $5/month" orderable, there's no proxy platform, backups are manual and require a stopped server, and each server is a full extra subscription ([modrinth.com/hosting](https://modrinth.com/hosting); [Datapacks on Modrinth Hosting](https://support.modrinth.com/en/articles/14030919-datapacks-on-modrinth-hosting); [Managing Backups](https://support.modrinth.com/en/articles/14030930-managing-backups)). Its 2.8/5 Trustpilot score mixes app and hosting reviews, but the 2026 hosting complaints are specifically about multi-hour outages and support gaps ([Trustpilot](https://ca.trustpilot.com/review/www.modrinth.com)). GodLike has the right feature, a Server Splitter that carves one plan into sub-servers, but Trustpilot has suspended its score for a guidelines breach and removed fake reviews, 20 % of its 457 reviews are one-star, the dominant complaint is being charged after cancelling, and its Fabric guide stops at Java 17 ([Trustpilot: GodLike](https://www.trustpilot.com/review/godlike.host); [GodLike Fabric KB](https://godlike.host/knowledgebase/setting-up-fabric-en-db/)). It's the one option here to actively avoid.

A VPS is the only route with no feature ceiling, and the price band is tight: at list on 2026-10-18 an 8 GB shared-CPU box is $48 at DigitalOcean and Linode, $40–48 at Vultr, and $44 at Lightsail, with OVHcloud US VPS-2 the outlier at $8.50 on what looks like a 12-month upfront term ([DigitalOcean pricing](https://www.digitalocean.com/pricing/droplets); [Akamai pricing](https://www.akamai.com/cloud/pricing/cpu); [VPSBenchmarks: Vultr](https://www.vpsbenchmarks.com/hosters/vultr); [Lightsail pricing](https://aws.amazon.com/lightsail/pricing/); [OVHcloud US VPS](https://us.ovhcloud.com/vps/)). Daily backups add 30 % at DigitalOcean. Two former bargains have gone: Hetzner raised prices twice in 2026 with US sites hit hardest, and its current US USD prices couldn't be confirmed from a primary source ([wz-it.com](https://wz-it.com/en/blog/hetzner-price-increase-june-2026-cpx-ccx-alternatives/)), while Oracle's Always Free tier was cut to 2 OCPU and 12 GB in June 2026 with idle reclamation when a week's utilisation stays under 20 %, which is precisely the profile of a server used three hours a week ([Oracle docs](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm); [InfoQ](https://infoq.com/news/2026/07/oracle-cloud-free-tier-limits/)). Every provider bills a powered-off VM, so "turn it off between classes" saves nothing short of snapshot-and-destroy ([Hetzner billing FAQ](https://docs.hetzner.com/cloud/billing/faq/); [DigitalOcean community](https://www.digitalocean.com/community/questions/billing-of-droplets-when-they-are-off)). The tooling is mature if you go this way: the `itzg/minecraft-server` image (2026.10.0, `latest` = Java 25) takes `TYPE=FABRIC` and `VERSION=26.3`, and Pelican rc.1 or Crafty 4.11.0 add a web console ([itzg docs](https://docker-minecraft-server.readthedocs.io/en/latest/types-and-platforms/server-types/fabric/); [Pelican releases](https://github.com/pelican-dev/panel/releases); [Crafty releases](https://gitlab.com/crafty-controller/crafty-4/-/releases)). Budget an afternoon to build it and an hour or two a month to keep it patched; that's an estimate, not a sourced figure, and it's the real price of this route for one adult who also has to teach.

## Child accounts and the whitelist are the same work everywhere

None of the hosting choices changes the account problem, which is the item most likely to eat the first class. In the US, Microsoft treats anyone under 16 as a child account, child accounts start with multiplayer blocked, and while blocked the player "cannot join any multiplayer game in Minecraft, including shared local worlds, Realms, or servers" ([help.minecraft.net: Parental Controls](https://help.minecraft.net/en-us/article/parental-controls); [minecraft.net: How to Stay Safe Online](https://www.minecraft.net/en-us/article/minecraft-multiplayer-server-safety)). The family organiser has to set "You can join multiplayer games" (and, for Realms, clubs) to Allow at account.xbox.com, and the child has to sign out and back into the launcher afterwards; a Microsoft Q&A thread on the greyed-out Java Multiplayer button runs past 30 pages of parents stuck on exactly this ([learn.microsoft.com Q&A](https://learn.microsoft.com/en-us/answers/questions/4220013/minecraft-java-edition-multiplayer-option-disabled?page=5)). Send families the instructions a week early, and have a program-owned adult account or two as spares. Each child still needs a paid Java license on their own Microsoft account.

On the server side, 26.3 made `white-list` default to `true`, so every new server needs `/whitelist add` for each kid, and `enforce-whitelist=true` is worth adding so a removed name is kicked rather than left online ([minecraft.wiki: Java Edition 26.3](https://minecraft.wiki/w/Java_Edition_26.3); [Server.properties](https://minecraft.wiki/w/Server.properties)). Keep `online-mode=true` on anything a kid connects to directly, keep op to adults, and keep the logs (chat lives in `logs/latest.log`) as part of the backup. The hosting accounts themselves are an adult-only affair by terms: Modrinth requires 13+, Shockbyte 13+ with parental permission under 18, GodLike 18+ or parental permission, and Tebex checkouts (CurseForge, some exaroton purchases) 16+ ([Modrinth ToS](https://modrinth.com/legal/terms); [Shockbyte ToS](https://shockbyte.com/terms-of-service); [GodLike Terms](https://godlike.host/terms); [Tebex Terms](https://checkout.tebex.io/terms)). The teacher holds the account and uses per-server sharing (exaroton share access, Modrinth's Owner/Editor/Limited roles since June 2026 ([Modrinth: Manage servers together](https://modrinth.com/news/article/server-access/))) for helpers; kids never log into a hosting panel.

## Recommendation: exaroton first, Kinetic second

**Recommended: exaroton, one Fabric 26.3 server per game, direct-join addresses, no proxy to start.** Realistic cost is **$3–6 a month** during a term (three 4 GB servers for three class hours a week is about €1.60 in play time; teacher prep on one server adds a euro or two), and about €0.30 a month to keep three dormant servers over the summer, or nothing if you back them up to Drive and delete them. Buy one credit bundle, create a credit pool, add the servers to it, give a co-teacher Start permission, and set autostop so a forgotten server costs cents. The workflow fits the repo's build step: upload the pack zip through the Files page into `world/datapacks/`, drop the mod jar into `mods/`, and `/reload`.

**Runner-up: Kinetic Hosting, 12 GB plan at $12.99/month, split into three or four always-on servers** (or the 8 GB plan at $7.99 if 2–2.5 GB per game proves enough for small void worlds). It wins if the exaroton start-up moment or its vague "North America" latency annoys the class, or if you want servers that are simply always there for kids to join from home. Its unknown reputation is the risk; the 7-day refund is the test window. If both fail their checks, the no-surprises fallback is a DigitalOcean 8 GB droplet in NYC at about **$62/month with daily backups**, running three itzg Fabric containers, with the option of adding Velocity later.

Before paying, verify these in order, most of them inside a free trial or refund window:

1. On exaroton, confirm 26.3 and Fabric Loader 0.19.5 appear in the software picker (or that the custom-upload path accepts a 26.3 `fabric-server-launch.jar`), then time a cold start of one of the void worlds; uploads aren't available in the free trial, so this needs a small credit purchase.
2. Upload the actual server-side mod jar and one real pack, join from an unmodified 26.3 client, and confirm no registry-sync kick and that a `dynamic/custom` dialog button reaches the mixin without the confirmation screen.
3. Run three servers at once from one credit pool with a co-teacher's account holding Start/Stop, and measure ping from Newburgh to the "North America" region during a weekday afternoon.
4. On Kinetic, ask support for the split rules (minimum RAM per split, separate port and Java version per split, whether splits share the 60 GB and the 5 backup slots) and whether 26.3 is in the version list, and search for any 2026 outage or billing complaints before the 7-day refund lapses.
5. For both, do a full backup-and-restore cycle of a world (Drive on exaroton, a backup slot on Kinetic) and check that the restored world still has the pack enabled.
6. Email BisectHosting about the Craft Together Project; a free server for a nonprofit kids' program would change the always-on math even if it only covers one game.
7. Whatever host you pick, run through the child-account multiplayer toggle with one real family a week before the first class.

## Conclusion

The field splits on a single axis the hosting comparisons rarely show: whether you pay for server-hours or server-months. For a program that plays a few hours a week, the always-on tier ($30–62 a month for three games) is mostly paying for empty servers, and the cheapest always-on option with the right feature (splits) is a host nobody has vetted. Metered billing makes the multi-game requirement nearly free, which in turn removes the pressure to cram several games into one server and inherit shared namespaces, shared scoreboards, and one shared failure. The right order is therefore the opposite of the usual "pick a big brand" advice: start with the metered host, prove the mod and the packs there, and only move to always-on if the class notices the difference.

The other shift is that the mod, not the datapacks, now sets the hosting floor. Once the custom-click handler exists, Realms and Aternos are off the table for good, and every remaining host is judged on "can I upload a jar and a zip and press reload." That's a much easier bar than it was a year ago, and it means the hosting decision can be revisited each term in an afternoon rather than being a one-time bet.
