# Command Forge (commands-tutorial)

A Minecraft Java **26.3** datapack that teaches commands entirely in-game: no videos.
Each idea is explained in chat, and the
pack checks what actually happened in the world (not what you typed). Progress is per
player, so a whole class can share one LAN world or Realm.

Namespace `tut`. Design doc: `PLAN.md`. Research behind it: `../reports/Teaching Minecraft Java commands.md`.

## What's built

- **Engine**: per-player 12×12 fenced islands (128 blocks apart), per-player section/exercise scores,
  quest text in chat (commands are clickable and drop into the chat box; long quests come in parts), a reference book, teacher commands.
- **Section 1: Command Basics** (9 quests, one idea each, some in parts): opening chat with t and saying hello, Esc to close it, clicking a link in chat, the slash + `/effect`,
  CLI (+ `/xp`), REPL (+ `/give` and reading the reply), Tab autocomplete + `/help` + `/gamemode`, `/give` with a count,
  the Up arrow, `/tp` to X Y Z.

## Install

Minecraft runs from the Prism Launcher flatpak, which can't see this folder, so copy from the host:

```
cd ~/minecraft/commands-tutorial
rm -f ../zips/commands-tutorial.zip
zip -r ../zips/commands-tutorial.zip pack.mcmeta data
SAVES="$HOME/.var/app/org.prismlauncher.PrismLauncher/data/PrismLauncher/instances/Command Forge/minecraft/saves"
cp ../zips/commands-tutorial.zip "$SAVES/<world>/datapacks/"
```

World: create a new world in the **26.3** instance, World Type **Superflat → preset "The Void"**,
**Allow Commands ON** (students need commands to work for them). Then `/reload` in-game after
every zip update.

## Running a class

1. Everyone joins (Open to LAN with cheats on, or a Realm). Each new player gets their own island.
   Nothing opens by itself. Pressing the **QUEST button on the post by the sign**
   prints the quest in chat (press t to read it; the blue commands drop into the chat box when clicked).
   Dialog-window version: swap the one line in `internal/show_part.mcfunction` (dialogs are still generated).
2. Kids work through the exercises on their own. The actionbar always shows the goal.
   Chat shows gentle red corrections when something's not quite right.
3. Stuck? Press QUEST again to reread the current part.
   Three buttons on the island: QUEST (press again for the next part), NEXT QUEST (checks the task first), PREVIOUS QUEST.
   A "Leaderboard" sidebar (every player, sorted by points, persists offline) scores each quest once per player: 1 point for a section 1 quest, 2 for a section 2 quest. Redoing a quest adds nothing.
   From chat: `/function tut:___quest`, `/function tut:___previous`.
4. Lost? `/function tut:___start` replays the current exercise and teleports home.

### Teacher commands

Run these *as the kid* from your own chat: `/execute as <Name> run function tut:___skip`

| Function | Does |
|---|---|
| `tut:___skip` | mark the current exercise done |
| `tut:___top` | announce the top 5 online players by points to everyone, medals for the top 3 |
| `tut:___goto_quest {q:"1.4"}` | jump to section 1, quest 4 (quests 10 and 11 need the quotes: `{q:"1.10"}`) |
| `tut:___goto {sec:1,ex:3}` | same, 0-based exercise index |
| `tut:___reset_player` | back to the start, plot rebuilt, inventory cleared (keeps their plot) |
| `tut:___reset_world` | reset every online player |
| `tut:___restart_section` | redo the current section |

Buttons everywhere go through `/trigger tut_btn`, which works even for non-op players.
The course commands themselves (`give`, `tp`, …) need the player to have cheats, so turn
Allow Commands on for the world or op the students.

## Troubleshooting

- A function with a syntax error silently fails to load. After `/reload`, check:
  `grep -A3 "Failed to load function" ~/.var/app/org.prismlauncher.PrismLauncher/data/PrismLauncher/instances/26.3/minecraft/logs/latest.log`
- A macro function with a bad argument fails at run time with a red "Failed to instantiate" chat line.
- Nothing happens on join: check `/scoreboard players get global tut_init` is 1 and that the world
  has the pack enabled (`/datapack list`).

## Layout

```
data/tut/function/___*            player/teacher commands
data/tut/function/internal/       engine: load, init, tick, join, dispatch, complete, plot, book
data/tut/function/s1/eN/          one folder per quest: start, tick, check, title, part1.. (+ build, sign)
data/tut/function/s1/eN/partN     chat text, generated by tools/gen_lessons.py (edit the Python)
```

Exercise contract: `start` runs once when the exercise begins, `tick` every tick (re-asserts props,
shows the goal, probes the world, prints corrections), `check` ends in `return 1` or `return fail`.
All three run positioned at the player's plot origin, so they use `~` coordinates.
